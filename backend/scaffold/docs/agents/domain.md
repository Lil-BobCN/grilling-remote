# 领域文档

本文件说明读代码前怎么找领域知识。

## 开始前先读什么

- 根目录有 `GLOSSARY.md` 时，先读它。写词条、写决策记录或改术语前，先读它开头的「写词条的规矩」。
- 根目录有 `GLOSSARY-MAP.md` 时，先通过它找到相关的 `GLOSSARY.md`。
- 有 `docs/adr/决策记录.md` 时，读它。

这些文件不存在时直接继续。不提示缺失，也不提前创建。等术语或重要决定真正明确后，再用 `domain-modeling` 按需创建。

## 文件布局

本仓是单一上下文，没有多包结构。一个功能一个目录，放在 `src/features/` 下。

## 词汇表

格式按 `domain-modeling` 技能的 `GLOSSARY-FORMAT.md`。增删词条时读那一份，不在本文件另写格式。

Issue 标题、测试名称、重构建议里出现领域概念时，用 `GLOSSARY.md` 已定义的名称，不要换成近义词。

## 决策记录

三条同时成立才写：

1. 难回退：以后改主意，代价明显。
2. 不写会让人意外：后来的人看代码会问「当时为什么这样做」。
3. 真取舍：有真实备选，并为具体理由选了其中一个。

缺一条不写。容易换掉的库和常规做法不写。写法按 `domain-modeling` 的决策记录格式。

## 明确指出冲突

建议和记录里的决定冲突时，直接指出冲突和重新讨论的理由，不要悄悄覆盖已有决定。
