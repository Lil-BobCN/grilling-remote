# 信任阶梯

一句话：信任来自一次次能验证的放手，不来自模型变强。每多一层验证能力，就能多交一类权限。

## 阶梯的五级

播客里 Lauren 把过程讲成一条梯子（S3）。

第一级是手动微管理一个 agent。2026 年初，大家在终端里比谁的自建 orchestrator 更强。她在做副业项目时也陷在这里，几个小时盯着一个 agent 改代码。

第二级是验证技能。agent 有了手和眼，能启动应用、点页面、抓 trace。她说这是第一个真正让她往上走的 skill，别的 skill 都做不到（S3）。

第三级是环境。厨房、刀具、代码库、lint、类型，都算这一级。目标是让省事的路就是正确的路。

第四级是协调 agent 加多项目。Cursor 的 projects 里有一个云端协调 agent，自己不写代码，只分派和监督。片子里 Lauren 的幕僚长和 GrokBot 团队就是这一级（S2、S3）。

第五级是 agent 自己合并。pstack 的全自动模式给每个 PR 派验证小队，跑完再落地。她第二天早上看提交历史，出问题就回滚或加 lint 规则（S1、S3）。

## 她的路径

在 Meta 做 React， burnout 后休假，顺手做了个副业项目，开始攒第一批 skill（S3）。2026 年 3 月加入 Cursor，后来负责 agent window 的性能。她天天看火焰图，发现自己是瓶颈（S3）。她把自己叫 agent 和 Chrome 开发者工具之间的人肉代理（S1、S3）。

验证技能出来后，她才开始真正放手。8 月交付约 2,500 个 PR，平均一天 80 个，代码由 agent 自己合并（S1 自述）。播客里她补了一句：这些 PR 不都是新功能，很大一部分是给代码库加约束的园艺工作（S3）。

## 两个杠杆

播客里她把话收得很紧：能让她走开的，是验证加环境这两件事的组合（S3）。验证负责证明这次改对了，环境负责让下一次不容易错。缺一个，人都得回到循环里。

## 2000 还是 2500

这次分享的口径是 2000 个 PR（S8）。B 站简介注明原帖写 2500，视频口述写 2000。S1、S2 用的是 2500。

两个数都指「上个月」或「8 月」，差异没有解释。信任阶梯的形状不受影响，但引用规模时要标明出处。

## 成立前提

领域要可验证。软件比多数领域好验证，所以她能在软件里走到第五级。数学的一部分也可验证，比如写证明。换成很难程序化验证的领域，她承认自己也没答案（S3）。

代码库要统一。一种做法一个目录，lint 才能拦住。CI 要快，规则才不拖慢每一轮。这些在 [[环境与约束]] 里展开。

## 边界

第五级不等于完全不管。她仍然抽样看 PR，仍然在早上读提交历史。她也不认领「黑灯工厂」的标签，理由是代码和环境仍然是核心，环境差，输出就差（S3）。

单向门的改动要单独看。她的办法是提高验证强度，让单向门在流程里尽量变成双向门。验证做不到的领域，这套办法会失灵（S3）。
