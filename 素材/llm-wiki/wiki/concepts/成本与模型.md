# 成本与模型

一句话：同样的任务，token 成本降下来，能同时跑的 agent 就多起来。成本是规模的前置条件。

## 一次发布

MTS 访谈当天，Cursor 和 SpaceX 联合发布 Grok 4.6（S2）。两位嘉宾说，同样的 token 成本，4.6 比 4.5 智能很多，速度也快（S2）。

劳伦说她的日常工作以软件工程为主，经常用 Grok 4.6 写代码。她也会用 Fable 和 Sol，但 Grok 又快又便宜（S2）。

## 两个数字

主持人给了 CursorBench 3.2 上的一组对比（S2 自述）：

| 模型 | 得分 | 每任务平均成本 |
| --- | --- | --- |
| Grok 4.6 Extra High | 70.8% | 2.81 美元 |
| Fable 5 Max | 70.5% | 17.32 美元 |

差 0.3 个百分点，成本差约 6 倍。主持人的判断是，这个变化会改变普通用户和 agent 打交道的方式。

## 便宜之后多出什么

罗尚的说法是效率。他在 Cursor 内部有不限量的 token，但客户对成本敏感。一个能力接近大模型、价格只有零头的模型，能让更多公司把 agent 铺开（S2）。

他举了个很朴素的例子：如果预算是 20 美元，每项任务便宜了，同一个预算就能多做几件事（S2）。

劳伦补的是另一头：成本降下来，资源不多的创业公司和独立开发者也能用上更强的能力。token 费用自己掏腰包的人，感受最直接（S2）。

## 和规模的关系

pstack 的 2,500 个 PR、全自动验证小队、多项目并行，都建立在 token 便宜的前提上。验证小队每个 PR 派好几个 agent，播客里 Lauren 直接说这套很费 token，可以调小（S3）。

成本不下来，规模就起不来。这是 [[信任阶梯]] 第五级的经济前提。

## 成立前提

基准要能代表真实任务。单点分数和每任务成本，不等于所有工作类型都按这个比例省钱。

价格会变。今天的对比过几个月可能就不成立。

模型组合要按公司自己的要求定。罗尚也说了，每家公司对模型搭配的要求不同（S2）。

## 边界

便宜不等于够用。得分接近，长任务、工具调用、多轮稳定性可能仍有差别，视频没有展开。

内部不限量 token 是员工待遇，不代表客户。罗尚自己把这一点说清楚了（S2）。
