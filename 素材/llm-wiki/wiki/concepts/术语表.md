# 术语表

按主题分组。每条给一句解释和出处代号。代号见 [[overview]]。

## 角色与循环

| 术语 | 解释 | 出处 |
| --- | --- | --- |
| agent | 能自己读代码、改代码、跑命令的智能体。文中也直接写 agent。 | 全部 |
| harness | 跑 agent 的外壳，负责上下文、工具、权限和子 agent。 | S3、S5 |
| 内循环 | agent 在仓库里写代码、验证、合并这一圈。 | S3 |
| 外循环 | 从 Slack、X、邮件、Linear 等外部系统收集问题，再送进内循环。 | S3 |
| 协调 agent | 只做分派和监督、不自己写代码的 agent。也叫幕僚长、chief of staff。 | S2、S3 |
| 人肉代理 | 人充当 agent 和工具之间的中转，比如把 trace 从 Chrome 开发者工具搬给 agent。 | S1、S3 |
| 前沿票 | 依赖已经满足、现在就能开工的 ticket。多个前沿票可以并行。 | S4、S5、S6 |

## pstack 相关

| 术语 | 解释 | 出处 |
| --- | --- | --- |
| pstack | Lauren Tan（poteto）公开的一套 agent skills，Cursor 插件，内置 50 个 skill、23 本 playbook。 | S1、S3 |
| poteto mode | pstack 的一键入口，后面接任务描述，由它挑 playbook。 | S1 |
| playbook | 任务剧本，比如修 bug、做功能、优化性能、发布上线。 | S1 |
| 修正阶梯 | 修同一个错误的优先级：架构高于类型，类型高于 lint，lint 高于测试，测试高于文字指令，人审垫底。 | S1 |
| /correct | pstack 里把重复错误变成规则的技能。读提交、回滚和评审意见，错两次算一个模式。 | S1 |
| fix-root-causes | pstack 的一条规则，要求把每个症状追到根因。 | S1 |
| recall | pstack 里回读历史会话、压缩成可复用流程的技能。 | S3 |
| NGMI | not gonna make it 的缩写。Lauren 用它标记「靠人审兜底」这一档。 | S1 |
| 园艺 | Lauren 对「给代码库绑铁丝」的比喻，对应大量用来加约束的 PR。 | S1、S3 |
| 米其林厨房 | Lauren 对多 agent 协作的比喻。人从厨师变成主厨，负责定标准、摆盘和质检。 | S2、S3 |
| 软件工厂 | 把 agent 流水线化的说法。Lauren 嫌它带低质量联想，改用厨房。 | S3 |

## 验证与评审

| 术语 | 解释 | 出处 |
| --- | --- | --- |
| 验证技能 | 教 agent 启动应用、点页面、抓截图和 trace，自己证明改动有效。 | S1、S2、S3 |
| 证据 | before 和 after 的实跑结果。编译通过和绿灯单测都不算。 | S1、S5 |
| 爬山 | 给一个评分标准，让 agent 在循环里反复改进。 | S3 |
| 模糊测试 | 让验证 agent 像真人一样乱点应用，找回归和 bug。 | S1、S3 |
| 抽样评审 | 不逐行看，每天抽一部分 PR 细看，找共同模式。 | S1、S3 |
| 单向门 | 合进去很难退回的改动，比如删数据。 | S5、S3 |
| 双向门 | 合进去也能便宜地回滚的改动。 | S5、S3 |
| 影响范围 | blast radius，改动出问题会波及多大。 | S5 |
| 合并危险 | PR 模板里的一栏，写门的方向和影响范围。 | S5 |
| 黑灯工厂 | 无人值守、agent 自己合并的极端形态。讲者只部分认同。 | S3 |

## Matt Pocock 工作流

| 术语 | 解释 | 出处 |
| --- | --- | --- |
| skill | 一段可复用的流程说明，本质是 markdown 加自然语言。 | S3、S4 |
| grill | 让 agent 反过来面试你，把计划里没定的决策逐个问出来。 | S4 |
| grill-with-docs | grill 的加强版，边问边维护仓库里的词汇表。 | S4、S5 |
| 决策树与迷雾 | 把功能拆成一棵决策树，父节点定了，子节点才亮出来。 | S4 |
| 词汇表 | glossary，记录领域词、定义和要避免的说法。原名 CONTEXT.md，v1.3 改名 GLOSSARY.md。 | S4、S5 |
| spec | 目的地。把谈定的决策写成问题、修法和用户故事。 | S4、S5、S6 |
| ticket | 旅程。把 spec 切成一个个能独立跑的会话。 | S4、S5、S6 |
| 智能区 | 上下文大约 15 万 token 以内，模型推理还锋利。超过叫变笨区。 | S4、S5、S6 |
| to-spec | 把 grill 的结论写成 spec 的技能。 | S4、S5、S6 |
| to-tickets | 把 spec 拆成带阻塞关系的 ticket 的技能。 | S4、S5、S6 |
| implement | 在干净会话里实现单张 ticket 的技能。 | S4、S5、S6 |
| implement-spec | 用一个编排 agent 带 sub agent 跑完整个 spec 的技能，v1.3 新增。 | S5、S6 |
| worktree | 同一仓库的独立工作副本，用来并行开 agent。 | S5、S6 |
| pr | 写 PR 正文的技能，四栏：摘要、证据、合并危险、影响范围。 | S5 |
| retro | 回读真实会话，找仓库、规则和指令里的低效，只给建议。 | S5 |
| 无操作指令 | 模型本来就会遵守、写进指令也没用的句子。retro 会挑出来。 | S5 |
| 工具经济 | tool economy，指工具和指令占的上下文与调用成本。 | S5 |
| 接单 | backlog 里的任务被 agent 领走并开工。 | S7 |
| 沙箱 | 把 agent 关进隔离环境，放开权限也伤不到宿主机。 | S7 |
| AFK | away from keyboard，无人值守。 | S7 |
| Sandcastle | Matt Pocock 写的 TypeScript 库，用一行 run 调用把 agent、沙箱和提示词串起来。 | S7 |
| 计划者 | planner，读未阻塞的 issue，产出可执行的计划。 | S7 |
| 实现者 | implementer，每张 issue 一个，在独立分支写代码。 | S7 |
| 评审者 | reviewer，实现者提交多于一次时介入，看 diff 和项目规范。 | S7 |
| 合并者 | merger，把各分支合回主干，处理冲突并关掉 issue。 | S7 |

| --- | --- | --- |

## Software Factories 课程补充（S9）

| 术语 | 解释 | 出处 |
| --- | --- | --- |
| 领域语言 | domain language。用户、产品、代码和 agent 共用的一套词。DDD 叫 ubiquitous language。 | S9 第 1 集 |
| bounded context | 限界上下文。一套语言生效的范围。两个语境想挤进同一份术语表时，就该拆。 | S9 第 11 集 |
| 场景测试 | 把候选词放进不同场景，看句子是否自相矛盾。矛盾说明概念需要拆。 | S9 第 3 集 |
| ADR | architecture decision record，架构决策记录。一到三句话，记录决定和原因。 | S9 第 4 集 |
| 三条标准 | ADR 的准入条件：难逆转、无上下文会意外、真实取舍。三条同时成立才写。 | S9 第 4 集 |
| 地图 | Wayfinder 的总 issue，存目的地、已做决定、迷雾和范围外。 | S9 第 13 集 |
| 决策票 | 地图下的子 issue，处理一个决策。 | S9 第 13 集 |
| 战争迷雾 | 还看不全的决策空间。随着票被解决，更多票浮现。 | S9 第 13 集 |
| 保真度 | fidelity。讨论、面包板、线框、原型、生产代码，承诺和成本依次上升。 | S9 第 12 集 |
| grilling ticket | 一次 grilling 会话，回答一组问题。 | S9 第 13 集 |
| prototype ticket | 做一个便宜、粗糙、可反应的产物，提高讨论保真度。 | S9 第 13 集、第 22 集 |
| research ticket | 查第三方文档、API 或知识库，补一个决定等待的事实。AFK，由子代理解决。 | S9 第 13 集 |
| task ticket | 做只有人才能做的手动步骤，比如注册服务、开通密钥。 | S9 第 13 集、第 20 集 |
| one-shot | 不先规划，直接让 agent 做，之后评审。适合很小的改动。 | S9 第 28 集 |
| 三层刹车 | 自动检查、自动评审、人工评审。 | S9 第 29 集 |
| coding-standards.md | 编码标准文件，自动评审的规则来源。 | S9 第 33 集 |
| data clumps | 数据泥团。同一组字段反复一起出现，应该抽成对象。 | S9 第 35 集 |
| branded types | 给基础类型加标记，让纯文本和 Markdown 在类型系统里区分开。 | S9 第 38 集 |
| wizard | 生成交互式 bash 向导的技能，带人完成注册、开通密钥等手动步骤。 | S9 第 20 集 |
