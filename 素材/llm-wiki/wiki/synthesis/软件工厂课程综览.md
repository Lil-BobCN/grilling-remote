# 软件工厂课程综览：从领域语言到 retro

一句话：这门课把 Matt Pocock 的技能链展开成一条完整流水线，前半段解决「说什么」，中段解决「怎么规划」，后半段解决「怎么验收和改进」。

## 课程在讲什么

38 集可以分成四段：

| 段落 | 集数 | 解决的问题 | 关键产出 |
| --- | --- | --- | --- |
| 领域语言 | 1–11 | 用户、代码和 agent 说的不是一套词 | `GLOSSARY.md`、ADR |
| Wayfinder | 12–25 | 一次会话装不下大块工作 | 地图、决策票、spec |
| 实现 | 26–27 | 把决定落进代码 | spec、票、PR |
| 评审与 retro | 28–38 | 怎么知道做对了，怎么让下次更好 | PR 正文、评审报告、编码标准 |

## 论点链

1. agent 会生造词，也会在找不到东西时重复代码。共享术语表把语言固定下来。
2. 代码只说明最后做了什么，不说明排除了什么。ADR 补上被排除的方案和取舍。
3. 术语表和 ADR 都会膨胀，需要修剪。实现细节和通用词是主要杂质。
4. 一次会话有上下文上限。Wayfinder 用地图和决策票把大块工作拆到多次会话。
5. 不同问题要在不同保真度上回答。讨论、原型、研究、任务四种票补不同的缺口。
6. spec 把地图压缩成执行指令，票把 spec 切成能独立跑的会话。
7. 实现和评审分开。实现负责让它能跑，评审负责让它变好。
8. PR 正文是评审界面：可视化摘要、前后证据、合并风险。
9. 人工评审不只修代码，还要改进系统。同一条评论不该留第二次。
10. retro 把评审意见变成编码标准和仓库示例，规则和代码一起改。

## 和现有来源的关系

现有 wiki 里的 S4、S5、S6 都是 Matt Pocock Skills 的短材料：

- S4 是 grill 到 retro 的动画拆解。
- S5 是 v1.3 的 implement-spec、pr、retro 讲解。
- S6 是中文全流程演示。

这门课（S9）是同一套方法的长课程版，细节多得多，尤其是：

- 领域语言和 ADR 的建表、修剪、bounded context。
- Wayfinder 的地图、决策票、战争迷雾、frontier 和四种票型。
- 保真度阶梯和 one-shot / grilling / Wayfinder 的决策树。
- 三层刹车、PR 技能的 Show Me 摘要和证据分级、code-review 的两轴评审。
- retro 的会话读取、规则和代码同步更新。

课程和现有来源不是替代关系。S5 更适合快速查技能行为，S9 更适合理解整套方法为什么这样设计。

## 和现有来源的出入

- **技能版本。** S5 讲的是 v1.3；本机 Wayfinder 技能文件是 1.3.1。课程里的标签写法是 `wayfinder map`、`Wayfinder grilling`，本机文件是 `wayfinder:map`、`wayfinder:<type>`。这可能是版本差异或口头简写，暂不合并结论。
- **流程细节。** 课程说 `implement-spec` 八张票并行、15 条评审发现；S5 说九步流程。两者可以同时成立，但票数和步骤的对应关系没有核实。
- **数字。** 61 条用户故事、10.7 万 token、7.29 万 token 等是课程演示的观察，不是稳定基准。

## 这门课新增的可迁移素材

- 场景测试表：同一个词放进不同场景，看句子是否自相矛盾。
- ADR 三条件：难逆转、无上下文会意外、真实取舍。
- 术语表两条删除规则：删实现细节、删通用词。
- Wayfinder 四票型：grilling、prototype、research、task。
- 保真度阶梯：讨论、面包板、线框、原型、生产代码。
- PR 三段：可视化摘要、前后证据、单向门/双向门加爆炸半径。
- 三层刹车：自动检查、自动评审、人工评审。
- retro 规则：同一条评论不留第二次；规则和代码一起改。

## 阅读路线

- 先看方法：第 1、4、12、13、28、29、30、33、36 集。
- 跟着做：按 1–38 顺序，练习集和解答集成对读。
- 只看落地：第 3、6、8、10、15、17、19、21、23、25、27、32、35、38 集。
