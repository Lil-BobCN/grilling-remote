# Sandcastle 编排能力的外部核实：`sandcastle.run()`、沙箱与分支策略

本页针对研究问题「查明 Sandcastle 这类沙箱编排工具在自动接单之外，从自动领取开发任务到直接产出（可评审/可合并变更）的完整链路」整理外部证据。目前仅收集到一条外部来源，即 AI Hero 上关于 [[Sandcastle]] 的官方说明页，且可引用的内容为其 “How it works” 概述段[1]。因此本页的定位是**证据边界说明 + 与既有 wiki 知识的交叉引用**，而非对完整链路的结论性描述。

## 来源能确认的最小事实集

AI Hero 的 Sandcastle 页面在 “How it works” 下给出了两条机制性描述[1]：

1. **单一调用入口**：通过一次 `sandcastle.run()` 调用来驱动 agent。也就是说，编排层对外暴露的 API 表面被压缩为一个函数调用，agent 的生命周期（启动、执行、收尾）由 Sandcastle 而非调用方逐步编排[1]。
2. **内置沙箱化 + 可配置分支策略**：Sandcastle 自身负责把 agent 放进沙箱中运行，并在此之上应用一个**可配置的 branch strategy**；原文将该链接指向 `/...` 下的分支策略文档[1]。

这两点足以把 Sandcastle 归入 [[沙箱与自动接单]] 所讨论的工具类别：它提供的是「隔离执行环境 + 分支落点约定」这一层能力，而不是业务侧的任务来源。换言之，从证据看，`sandcastle.run()` 是一个**执行原语**，其输入边界与触发者并未在该段落中说明[1]。

## 与既有页面的交叉引用

- **沙箱语义**：可配置分支策略意味着每个 agent 的执行结果有明确的落点约定（不同分支、不同工作树），这正是 [[沙箱与自动接单]] 中「隔离 + 可回收」的前提条件；分支策略的具体枚举值（例如按任务分支、按 agent 分支、共享分支）在来源中未展开[1]，属于待补证据。
- **任务拆分与上下文**：`run()` 作为单点入口，天然要求调用方在调用前把任务与上下文准备好，这与 [[任务拆分与上下文]] 的结论一致——拆分的责任在编排层之上，而非沙箱工具内部。
- **环境与约束**：[[环境与约束]] 所述「用环境而非提示词约束 agent」在 Sandcastle 中体现为沙箱 + 分支策略这一对硬约束[1]。
- **验证与评审**：来源完全没有提到测试执行、验证门禁或 PR 生成[1]，因此 [[验证与自证]] 与 [[评审与验收]] 所描述的环节在 Sandcastle 中**是否内置、还是交由调用方/上层技能补齐**，目前无证据。
- **对照工具**：[[pstack]] 与 [[matt-pocock-skills]] 属于「流程/技能层」，[[Sandcastle]] 属于「执行/沙箱层」；三者分工参见 [[pstack-与-matt-pocock-技能的分工]]。若把 `sandcastle.run()` 视作被上层流程调用的原语，则 [[技能与流程]] 中的许多环节（grill、implement-spec、pr、retro）需要在 Sandcastle 之外完成。
- **信任演进**：是否允许无人值守地从领任务一路走到产出变更，取决于 [[信任阶梯]] 上所处的位置；沙箱与分支策略是提升自动化等级的技术前置条件，但不等于授权。
- **相关素材**：[[matt-pocock-sandcastle]] 记录了 Sandcastle 的自接单用法；[[口播素材综览]] 汇总了验证、约束、拆分、验收四条主线。

## 尚未解答的问题（证据缺口）

以下问题在现有来源[1]中**均无答案**，需要补充材料才能闭合研究问题：

1. **任务来源**：谁调用 `sandcastle.run()`？是人工逐次触发、CLI 循环、还是由看板/issue 事件驱动？「自动领取开发任务」这一步是否属于 Sandcastle 的职责范围，来源未说明[1]。
2. **分支策略的具体形态**：可配置项有哪些、默认值是什么、是否支持「一任务一分支」与冲突回收，来源仅给出链接文字[1]。
3. **链路终点**：沙箱内的产出是否直接转化为 commit / PR / 合并？是否存在人工评审闸门？来源未提及 PR 或 CI 相关能力[1]。
4. **失败处理**：`run()` 的返回语义（成功/失败、部分完成、超时）与重试/回滚策略未知[1]。
5. **并发与成本**：「single `sandcastle.run()`」是单次单 agent，还是可并发多实例？与 [[成本与模型]] 相关的计费/资源上限未见描述[1]。
6. **与技能层的耦合度**：`run()` 接受的输入是提示词、规格文件还是技能名，直接决定它能否承接 [[matt-pocock-skills]] 的 `implement-spec` 产物。

## 矛盾与不确定性

- 本页仅基于一条来源，且该来源为产品文档的概述段，**存在推广性表述的可能**，不宜据此推断端到端能力[1]。
- 术语层面存在潜在混淆：「sandboxing」在来源中指 agent 执行隔离[1]，而 [[沙箱与自动接单]] 中该词同时涵盖任务领取的自动化；两者不是同一层次的概念，引用时需区分。
- `concepts/沙箱与自动接单` 若已包含对 Sandcastle 的描述，本页可作为其**外部证据脚注**，但不应覆盖该概念页中来自 [[matt-pocock-sandcastle]] 的一手观察。
