## 新增来源概览

**[1] LLM 深度研究中的来源归因（Source Attribution）**：LLM 驱动的 deep research agent 会综合数百个网络来源，生成带引用的研究报告；随之而来的核心问题是，引用是否真的支撑正文主张，以及如何解析并评估这种支撑关系 [1]。这一来源把“验证”问题从“答案对不对”推进到“答案是否有可追溯的证据链”。

**[2] 代理工作流综述（PPIO）**：该文把 RAG、Deep Research 与代码助手放在同一个“代理工作流”框架下讨论 [2]。它的价值不在于提供新实验证据，而在于提示这三类应用共享相似的流程骨架：理解任务、检索或调用工具、生成产物、再对产物做某种形式的检查。具体环节的划分需回到原文核实，本页仅作概括。

## 要点提炼：引用作为一种外部证据

深度研究 agent 的产出之所以能被验收，关键不在报告写得像不像，而在于每条主张后面是否挂着可独立核查的来源 [1]。这与编码 agent 的验证逻辑同构：测试、diff、CI 日志都是“可复核的外部痕迹”，让评审者不必完全信任 agent 的自我声明。

由此可以提炼出一个适用于口播素材的表述：**验证的本质不是让 agent 说“我做好了”，而是让它留下别人能查的证据。** 在深度研究中这个证据是引用，在编码中这个证据是测试与变更记录；两者都是把“自证”外化为“他证”的手段。

## 可用于口播的类比

以下类比均为本页基于来源 [1][2] 的推断，并非原文结论：

1. **引用是深度研究 agent 的“测试”**：一份只有结论、没有引用的报告，和一个只有“已完成”、没有 diff 的 PR 一样，都不可验收 [1]。
2. **信任来自痕迹，不来自声明**：无论是引用列表还是测试日志，作用都是把“我相信你”换成“我可以查你” [1]。
3. **三类 agent 共享同一条验证主线**：RAG、Deep Research 与代码助手都要经历“生成—检查—修正”的循环 [2]，区别只在检查手段不同。
4. **验证越贵，越需要分层**：数百来源的逐条核对不可能全量人工完成，因此需要自动归因评估与人工抽查结合 [1]，这与大规模 PR 流中的评审分层一致。

- **概念滑动风险**：source attribution（来源归因）与 self-verification（自证）并非同一概念。本页把两者并置在“外部证据”框架下，属于类比迁移，口播时应明说这是类比而非等同。
- **缺少反例**：是否存在“引用齐全但结论错误”的情况？引用质量与结论正确性之间的相关性，现有来源未覆盖。
- **领域偏置**：现有 wiki 的验证讨论以编码 agent 为主，deep research 的证据仍偏薄，尚不足以支撑跨领域的一般化结论。
- **成本维度缺失**：两条来源都未量化验证成本，[[成本与模型]] 中的相关讨论目前缺少外部数据支撑。
