## 口播文章

### 先承认：现在决定选哪家，保真度不够

好，我拿 16 号票，进入 agent，清掉上一个会话，然后说 `Wayfinder` 加 issue 16 号。

它的第一个问题是我们要不要承诺用 Knock。这其实是个棘手的决定，而且我觉得我们是在错误的保真度上做这个决定。只有注册了、玩一玩、真正知道它能做什么，甚至看过一个原型之后，我们才能真正知道能不能承诺 Knock。所以我现在这样告诉 agent：我觉得只有看过原型，才能真正承诺 Knock。所以我很乐意先试一把，但我觉得我们应该保持开放，如果 Knock 不是我们真正想要的，也许要换方向。

### 额外的注册和每月费用

好，下一个。它说有些服务商需要额外的注册。Web push 需要一个 Firebase 项目，因为 Knock 通过 FCM 发 web push。我不太知道 FCM 是什么，我猜是需要 Firebase 项目的意思。好吧，这有点烦。

它还说，据它所知，Knock、Courier 和 MagicBell 都通过一个你自己连接的供应商来发送，没有一家自己发生产邮件。〔待确认：ASR 原文为 "knock, career, and magic bell"，"career" 从上下文看可能是 Courier〕它本质上在问：我们现在就注册，还是等到确定需要时再注册？问题二，我同意，先推迟任何服务注册，直到我们真正知道需要。

下一个问题三：每月 250 美元的悬崖价可以接受吗？问题三，可以，这个价格我没问题。

好，这些看起来都可以。我总觉得跑 Wayfinder 的时候能感觉到眼前的雾。我之前不知道基于我们选的服务商还需要那些额外注册。这挺烦的，也不完全是我想象的样子。但有时候你只能通过讨论、通过把它想清楚，才能弄明白这些事。

### 两张原型票，而不是一张

它现在问：原型必须证明什么？看起来地图里已经有一张「Cadence 里的通知信息流长什么样」，但那张票是关于界面和布局的，不是服务商是否合适。它建议再加一张更小的原型票：Knock 能不能撑住 Cadence 的场景。

对，我很喜欢这个。我喜欢把事情拆成小票，这样我们甚至可以在不同的工作树里同时原型这两件事。问题四，我同意，来两张原型票。

问题五：如果 Knock 失败，备选是什么？问题五，Courier 听起来可以作备选。

问题六：什么在等这个原型？原型目前被「注册通知服务商并开通开发密钥」阻塞着。它本质上在问：图会是什么形状？那里应该有什么阻塞关系？我接受它的建议。对，你的建议听起来可以。

好，感觉是一次很短的 grilling 会话。事实上，它直接把这些记录到票上。很酷。好，我们有地图了。

### 地图长出新票

地图上有了一个新决定：选通知服务商。可以看到现在有两张新票开着：一张任务票，然后另一次 grilling 会话。两次原型会话看起来都接近尾声。我的版本里，19 号是原型会话，21 号是「Knock 能不能撑住 Cadence」。看 21 号，右侧能看到 `blocked by` 关系：注册通知服务商并开通开发密钥。所以看起来我们下一步应该做那个。

这一课我们看到了新东西：你学得越多、做的决定越多，地图就能扩展。我也希望你有同样的感觉：我们对实际在构建什么，越来越清楚了。干得好，下一集见。

> **思考一下｜保真度和承诺的关系**
>
> 作者拒绝在当前保真度上承诺 Knock，但他没有直接跳到「做完整原型」，他拆出一张更小的原型票，专门验证服务商是否合适。
>
> **可以追问**：一张原型票要证明到什么程度，才算够格做承诺？
>
> **可延展方向**：给原型票写一句「证伪条件」：看到什么就说明这个方案不行。

> **思考一下｜新信息让地图长大**
>
> Firebase 注册和每月 250 美元的费用，是 grilling 过程中才冒出来的。它们变成任务票和阻塞边，而不是留在对话里。
>
> **可以追问**：哪些新信息应该变成票，哪些只需要写进当前票的决议？
>
> **可延展方向**：给「新发现」定一条规则：会改变后续工作顺序的，开票；只影响当前决定的，写决议。

## 综合解读

论点链：选服务商需要原型级证据；作者拒绝在讨论保真度上承诺；grilling 发现额外注册和费用；把「Knock 是否适合」拆成独立原型票；把注册和开通密钥设为任务票；用阻塞关系重排图。

成立前提：地图支持新增票和阻塞边；原型成本足够低；服务商有免费或可接受的开发额度；团队接受先注册再验证。

待核验主张：Knock、Courier、MagicBell 的发送机制和价格是 agent 的 research 结论，作者在讲解中接受，但未独立验证；「每月 250 美元」是当时的价格，可能变化；FCM 是 Firebase Cloud Messaging 的缩写，这是常见事实，但 ASR 没有展开。

边界：如果服务商承诺成本很高，先原型再决定可能不划算；如果备选服务商差异很小，提前选一个也更省事。作者自己说「有时只能通过讨论才能弄明白」，说明地图不是一次画完的。

可迁移素材：在正确保真度上做承诺；把「验证方案是否可行」拆成独立原型票；把外部依赖（注册、密钥、费用）变成任务票；用阻塞边表达先后。
