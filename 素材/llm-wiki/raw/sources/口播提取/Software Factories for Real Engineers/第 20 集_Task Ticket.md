## 口播文章

### 任务票：注册服务，开通密钥

好，Wayfinder 地图上的下一张票是任务票，内容是注册 Knock 并开通一些开发密钥。可以看到它是任务票，因为有 `Wayfinder task` 标签，而且它未被认领、可以开始。

注册这些服务、做这些任务其实挺烦的，尤其是你要注册五个服务再把它们接起来。所以我有一个技能可以帮忙。

如果你跑 `npm run reset add wizard skill`，本地会发生一件有意思的事：目录里会出现一个新技能，叫 `wizard`。它会生成一个交互式 bash 向导，带着人完成只有他们才能做的步骤。适用于开通基础设施、设置凭证或 CI secret、在不熟悉的第三方后台里操作，或者跑一次性的迁移/切换。

换句话说，`wizard` 技能就是让这些任务尽可能简单、尽可能不用动脑。因为它是模型可调用的技能，也就是模型自己能调用它，所以它通常会在合适的时机用上。我们这次拿到的任务就是 wizard 的经典用例。

你的任务和其他决策票一样：用 `Wayfinder` 加票号调用。我们应该会看到它给我们创建一个向导，然后我们跑一遍这个向导。一个小提醒：你必须在新的终端里跑向导，因为向导是交互式的，不能从 Claude Code 或你自己的 agent 的 bash 模式里跑。它应该会让设置这个环境变量变得非常简单。祝你好运，解答集见。

> **思考一下｜哪些步骤必须留给人**
>
> 注册、登录、在第三方后台里点按钮，这些涉及账号和密钥，agent 不应该代做。向导的作用是把人的操作步骤降到最少。
>
> **可以追问**：如果向导里的某一步需要判断（比如选免费版还是试用版），应该由人决定，还是由 agent 预先写死？
>
> **可延展方向**：把「只有人能做的步骤」和「agent 能做的验证」分开，向导只负责人做的那部分。

## 综合解读

这一集是练习说明，不是论证。可迁移的是：把「需要人操作的外部流程」做成可重复的向导，而不是每次让 agent 临场发挥。

成立前提：agent 能判断何时调用 `wizard`；向导在独立终端里运行；人愿意按步骤操作；密钥只留在本地。

待核验主张：「wizard 通常会在合适的时机被调用」是作者对技能描述质量的判断，实际是否触发取决于模型和提示词。

边界：向导适合步骤明确、变化不快的流程；如果第三方后台经常改版，向导里的路径会过期。向导也不适合需要复杂判断的步骤。

可迁移素材：任务票 + 向导；把注册和密钥留在本地；向导只做人才能做的步骤；agent 负责验证结果。
