### 新会话，带票号启动

这一课的设置很简单。如果你想完全重置到这个状态，像我一样开始，下面有一个可以跑的脚本。如果你想基于自己的 Wayfinder 地图做，那我建议你跑第一次 grilling 会话。

我们要做第一次 grilling 会话，问题是：Cadence 发哪些通知，发给谁？我会复制 issue 链接，复制链接地址，然后在 agent 里打开。关键是，我不会接着上次的会话继续，我会先清空，然后直接用 `wayfinder` 加上 issue 的 URL 启动。其实我在这里就打断，因为那是解答集的内容。

到这一课结束时，我们会 grill 完 Wayfinder 地图上的第一张决策票，并把它关掉。祝你好运，解答集见。

> **思考一下｜为什么必须新开会话**
>
> 旧会话里残留着上一张票的上下文，新票需要从地图和依赖票重新读起。新会话是一次「重新读盘」。
>
> **可以追问**：如果新会话读不到旧会话里某个口头决定，应该把决定写回哪里？
>
> **可延展方向**：每张票结束时，把关键决定写进票的 resolution，而不是留在会话里。

## 综合解读

这一集是练习说明，不是论证。可迁移的是：每张决策票用独立会话处理，用 issue 链接把地图上下文带进去。

成立前提：地图和票已经在 issue tracker 里；agent 能读 issue 和依赖关系；第一张票是 grilling 类型。

待核验主张：没有需要外部核验的事实。

边界：如果票很小、依赖很少，新开会话会增加重复读盘的成本；如果依赖票的结论没有写进 issue，新会话可能漏掉。

可迁移素材：用 issue URL 启动会话；先清空再启动；每张票独立上下文；结束时把结论写回票。
