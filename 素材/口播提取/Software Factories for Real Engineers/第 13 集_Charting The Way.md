## 一句话摘要

Wayfinder 用两个数据结构工作：一张地图（map）和挂在它下面的决策票（decision tickets）。地图是 GitHub issue，票也是 issue；每关掉一张票，就多看清一段路，直到目的地清晰到可以转成 spec。作者还定义了四种票和两种使用方式。

## 口播文章

### 地图和决策票

上一集我们了解了 Wayfinder 为什么存在、解决什么问题。现在看看它是什么、怎么运作。你可以跑 `npm run reset add Wayfinder skill` 自己拿到它。我会重置当前分支，然后 agent skills 文件里就会有 Wayfinder 技能。

它的开头相当有诗意：「一个松散的想法到来了，对一次 agent 会话来说太大，还被雾包裹着。」它描述了两个数据结构：一张地图（map），以及挂在地图下面的决策票（decision tickets）。看起来是这样：你有一张地图，然后有基于它的子票。每一张在技术上都是你 issue tracker 里的票，在我们的场景里就是 GitHub issue。地图是一个 GitHub issue，每张决策票也是它下面的一个 GitHub issue。

你一张一张地解决这些决策票。等所有票都解决、也就是把 issue 都关掉，你的地图就准备好了。换句话说，你已经做出了所有需要的决定，你找到了路，找到了通往目的地的路。

### 先定目的地

但目的地是什么？这是你在第一次会话里要决定的东西。从这里到目的地的路还看不见，Wayfinding 就是找这条路。目的地因任务而异，而给它命名是 charting（绘制地图）的第一个动作。它塑造每一张票。所以目的地是你第一件要决定的事，因为有了目的地，你才能想怎么去。

Wayfinder 一个很酷的地方是，它也能用于非编码工作。我其实有一张这门课自己的 Wayfinder 地图，目的地是「完成这门课」。不过，我推荐的编码用法，也是这门课要用的方式，是把目的地定成一份 spec。换句话说，我们要决定可能进入规格的所有东西，创建一份非常详细的 spec，然后交给一些 agent 去构建。

也就是说，到目前为止，我们一直把 `grill with docs` 当作写 spec 前的仪式，用于大块工作。但现在我们看到，`grill with docs` 适合范围很整齐的东西；Wayfinder 适合大项目、大块工作，可以从中做出大 spec，再走我们正常的循环。

### 地图是索引，票是细节

我们再深入看看这两个数据结构。地图是这个仓库 issue tracker 里的一个 issue，标签是 `wayfinder map`；它的决策票是地图的子 issue。地图就像所有已做决定的索引。这意味着，当我们用 `to-spec` 把地图转成 spec 时，spec 会把地图当作索引，当作通往所有决定的入口。每张票则承载所有 grilling 会话的细节，以及导致决定的一切。

换句话说，整张地图是一个低分辨率视图。它包含几样东西：目的地、一些一般性笔记、到目前为止的所有决定，以及这些决定周围的「战争迷雾」（fog of war）。

### 战争迷雾

「战争迷雾」是我很骄傲的一个比喻。规划大块工作时，你往往不知道通往目的地的路。如果你知道路，知道所有要做的事、所有要做的决定，工作会容易得多。但在任何时刻，你只能看见眼前几个决定，看不见整个棋盘。所以我把这个概念叫战争迷雾：你一边走，一边揭开更多地图。

### 阻塞关系和 frontier

同样关键的是，票之间可以有阻塞关系。比如上面这些决策票里，这两个决定可能都需要先做，我们才能做这个决定。换句话说，只有这两张决策票关闭，我们才能打开那一张。

很酷的是，我们可以用 issue tracker 原生的依赖跟踪。比如 GitHub 有 `blocked by` 功能，允许一张票被其他票阻塞。当所有阻塞它的票都关闭时，这张票就解除阻塞。我们还有一个「frontier」的概念：frontier 是开放的、未阻塞的、未被认领的子票。比如这张地图里，4 号被阻塞，因为 2 号和 3 号还没关闭；2 号和 3 号是开放票的 frontier，意味着它们可以同时处理。

### 怎么清雾

你可能会问：怎么清除战争迷雾？怎么真正走到目的地？

规划是这样运作的：随着你做决定，这些决定会揭示更多需要做的决定。也就是说，在 2 号的 wayfinding 会话里，你可能会发现又冒出一张票，于是创建 5 号票，加到地图上。5 号做完后，你意识到：哦，其实我能看见通往目的地的路了，现在我们有需要的一切了。等 6 号完成，目的地就完成了，地图可以转成 spec。

这些票构成一张图，严格说是 DAG（有向无环图）。你在这些票里做决定，决定打开更多空间，清除战争迷雾，你就能找到通往目的地的路。有些地图可以有 50、60 张票，能扩展到极大的 spec、极大的项目。

### 四种票

你现在可能在想：我在这些票里到底做什么？这些票是干什么的？

Wayfinder 里有四种票，用途不同。

最常见的是 grilling ticket（追问票）。在追问票里，你在一次 agent 会话里回答一组问题，就是标准的 `grill with docs` 会话。技能里写了票的类型，这里就是 grilling，默认情况，总是调用两次 skill 工具，分别做 grilling 和 domain modeling。但正如我们之前看到的，grilling 保真度相当低，是讨论。如果我们需要更高保真度呢？如果我们需要先看到某个东西，才能决定往目的地怎么走呢？为此，我们有 prototype ticket（原型票）。原型票允许你在真正需要看到东西跑起来的问题上提高保真度。它通过做一个便宜、粗糙、具体的产物，让人可以对着它反应，从而提高讨论的保真度。它实际调用一个叫 `prototype` 的单独技能。技能里写：当「它应该长什么样、应该怎么表现」是关键问题时，用它。

另一种是 research ticket（研究票）。当需要你没有本地访问权限的第三方信息或数据时用它。比如读文档、第三方 API，或者本地资源如知识库，为了把一个决定所等待的事实找出来。换句话说，有时在拿到信息之前，我们什么都 grill 不了，研究票就去把信息拿回来。和其他票不同，这一种不需要你帮忙，它是 AFK（away from keyboard，离开键盘）的，由子代理立即解决。也就是说，票创建后立刻被安排给一个子代理，子代理做研究，把研究结果附到票上。非常有用，因为这意味着你做完 grilling 会话后，可以立刻去做那个原型。

最后是 task ticket（任务票）。当有一个必须发生的体力活、而且它挡在一个决定前面时用它。比如注册一个服务，好让我们能建原型；或者开通某个访问权限；或者把数据整理成某种形状。这一种不太算决策票，更像「这里有一组手动步骤」。agent 会给你列一份步骤清单，让你去开通服务或者做该做的事。

### 两种使用方式

你最后一个问题大概是：我怎么让 Wayfinder 做这些？怎么让它创建地图、跑票？

很简单。Wayfinder 有两种使用方式，它会自己判断在做什么。如果你直接说 `wayfinder` 加一段提示词，它会给你创建一张新的 Wayfinder 地图，并和你做一次 grilling 会话，决定你要去哪里、目的地是什么。用它创建地图之后，你可以在新会话里说 `wayfinder` 加上你想处理的票号，它就会跑那次 Wayfinder 会话，处理那张具体的票。

信息量很大。继续之前，我想确认你掌握了。去页面底部做一些关于地图和票的测验。做完测验、觉得舒服了，我很期待和你一起 Wayfinding。祝你好运，下一集见。

> **思考一下｜地图和 frontier 的关系**
>
> 地图给方向，frontier 给下一步。没有地图，frontier 只是待办列表；没有 frontier，地图只是一张画。
>
> **可以追问**：如果 frontier 上的两张票互相影响，应该先合并成一张，还是保持并行？
>
> **可延展方向**：给每张票记录「它被哪张票阻塞、它又解锁了哪张票」，让 frontier 的变化可追踪。

> **思考一下｜四种票其实是四种保真度**
>
> grilling 是讨论，prototype 是实物，research 是拿外部事实，task 是开通条件。它们对应的是「现在缺什么才能做决定」。
>
> **可以追问**：一张票如果既需要研究又需要原型，应该拆成两张，还是一张票里串行做两件事？
>
> **可延展方向**：按「缺信息、缺感觉、缺访问、缺决定」四类缺口来选票型。

## 综合解读

论点链：大块工作无法在一次会话里规划完；用地图承载目的地和已做决定，用决策票承载细节；票之间的阻塞关系形成 DAG；frontier 是当前可做的票；做决定会揭示新票，逐渐清除战争迷雾；四种票对应不同保真度和缺口；最后地图可以转成 spec。

成立前提：issue tracker 支持父子 issue 和 `blocked by`（GitHub 可以）；agent 能创建、关闭、更新 issue；团队接受把计划放在 issue tracker 而不是文档里；目的地可以被清楚命名。

待核验主张：「地图可以有 50、60 张票」是作者观察到的规模，不是上限；「能扩展到极大的项目」是主张，取决于工具和团队执行；Wayfinder 技能的具体行为以技能文件为准，本集是作者讲解。

边界：如果工作很小，地图和票的开销大于收益；如果决定之间没有清晰的先后关系，DAG 会退化成待办列表；战争迷雾意味着地图必须持续更新，否则会误导后续会话。

可迁移素材：用地图做索引、票做细节；先定目的地；用 `blocked by` 表达依赖；用 frontier 决定并行；按缺口选票型（讨论、原型、研究、任务）。
