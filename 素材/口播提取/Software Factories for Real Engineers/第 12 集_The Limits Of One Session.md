## 口播文章

### 瓶颈从干活转移到规划

这门课后面，我们会看怎么自动创建工作任务：你有一个想法要做，把它交给 agent，它就去把它做出来。这非常令人兴奋。我第一次注意到这件事时意识到：瓶颈移动了。以前的瓶颈是「活需要有人干」，现在的瓶颈是「活需要有人规划」。

我开始想，怎么搭一个规划环境，让我能规划足够大的工作块，大到能喂满我手头所有可用的 agent。让我烦的是，`grilling` 对我来说不太够用。原因很简单：`grilling` 是一次会话。随着你回答更多问题、添加更多问题、和 agent 聊得更多，最终你会进入「变笨区」（dumb zone）。这是我经常被问的问题：做 `grill with docs` 会话时，到了 20 万 token、30 万 token 怎么办？

烦人的是，这段会话历史非常有价值，里面有你的所有回答、所有材料。如果你压缩它、让它变小，往往会丢掉很丰富的信息。所以有些人把它拆成多次会话：好，我有个想法要弄清楚，我先在一个会话里 grill 一部分，再在另一个会话里 grill 另一部分。但这很棘手。如果第一个会话里的问题和第二个会话里的问题相关呢？那会很痛苦。

做原型时尤其如此。假设你在做 `grill with docs`，然后意识到想做个原型，于是另开一个原型会话，弄清楚那件事，再交回 `grill with docs`。你得做大量上下文管理、会话切换，我觉得很痛苦。最糟的是，你必须事先知道这件事的形状，才能算出要拆成几个会话。这一切都让我觉得很别扭。

### 回到 AI 之前找方法：Shape Up 的保真度

每当我感觉和 agent 协作的流程不对、哪里别扭，我就会回到 AI 之前的工作方式里找灵感。我在这方面的「圣经」是 Ryan Singer 的《Shape Up》。这本书讲的是找到工作的正确形状、在正确的保真度上讨论、然后交付正确的东西。

值得定义一下这里的保真度（fidelity）。规划工作时，你可以在低保真或高保真上做。低保真就是你只是在讨论，比如 grilling，弄清楚描述功能要用的语言。从那里，你可以走到 breadboarding（面包板）：用方框和箭头把需要的动作画出来。再往上，你可能会看页面怎么组织，也许画线框图，把东西链接到不同页面，理解它的形状。再往上，你可以做原型，也就是半可运行的代码。最后，你可以一直到真正在生产里运行的代码。

低保真意味着低承诺：你只是在谈论，还没为构建投入任何 token。高保真意味着更高的承诺：要花更多 token 才能到达，但你会更清楚自己要往哪走。当然，也更慢。

agent 的好处是，它们让你能承受比以前更高的保真度，因为原型的生产成本现在非常低。所以，有些事情应该保持在低保真的讨论阶段；但我想要一个技术，在有用的时候把我往高保真推。

### Wayfinder 要解决的两个问题

所以，我想解决两个问题：规划期间烦人的会话管理，以及始终在正确的保真度上工作。这就是 Wayfinder 的由来。

它是一个规划技能，让你跨多次会话规划任意大小的工作，并且为计划的每个部分选择正确的保真度。它非常适合规划有大量未知未知（unknown unknowns）的事情：有很多东西需要验证，你完全不知道它怎么集成进应用、怎么构建。本质上，如果你不知道怎么到达目的地，你可以用 Wayfinder 找路。

这一节我们会掌握怎么用 Wayfinder 规划非常难的事，也规划非常大的事。干得好，下一集见。

> **思考一下｜保真度是一种承诺管理**
>
> 低保真便宜但模糊，高保真清楚但昂贵。作者追求的是「在对的地方用对的保真度」，并不追求「总是更高」。
>
> **可以追问**：怎么判断一个决定值得升到原型，而不是继续讨论？
>
> **可延展方向**：给每类决定配一个默认保真度，比如命名用讨论、交互用原型、第三方集用研究。

> **思考一下｜单会话的「变笨区」**
>
> 会话历史越丰富，压缩损失越大；不压缩，模型又会变笨。作者把这个两难当成规划工具的设计前提。
>
> **可以追问**：如果模型上下文继续变大，「变笨区」会消失，还是只是往后移？
>
> **可延展方向**：把长会话的决策即时写进地图或 ADR，让会话历史不再是唯一载体。

## 综合解读

论点链：agent 降低实现成本，瓶颈转向规划；单会话 grilling 有上下文上限，压缩会丢信息，拆会话会增加跨会话依赖；于是需要跨会话的规划结构；同时借用 Shape Up 的保真度阶梯，按部分选择讨论、面包板、线框、原型或生产代码。

成立前提：有多个 agent 可并行；工作块足够大，值得跨会话规划；原型成本足够低；团队接受把计划拆成地图和决策票。

待核验主张：「20 万、30 万 token 进入变笨区」是作者的经验判断，不同模型和工具的实际阈值不同；Shape Up 的保真度阶梯是方法论框架，不是经过实验验证的模型；「原型现在很便宜」取决于工具链和项目。

边界：小任务不需要 Wayfinder，单次 `grill with docs` 就够；保真度越高，成本和承诺越大；跨会话规划要求决策能被清晰记录，否则地图会变成另一份过时文档。

可迁移素材：用保真度阶梯决定「讨论、画图、原型还是写代码」；把长会话的决策即时外化到地图/ADR；先判断工作大小，再决定用单会话还是 Wayfinder。
