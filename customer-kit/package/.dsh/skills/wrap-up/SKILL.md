在本票 `## 结论` 写完、`Status:` 改成 `resolved` 之后跑。跑完再用 `next`。

列出本次对话漏记的四类东西：没记下的新想法，做了别张票的活的越界产出，和旧结论冲突的地方，地图和票头对不上的先后。四类都由 Agent 自己处理。只有需要客户拿主意时才问，一次一句。

数据在 `.scratch/{需求名}/` 内。对客户不提技能名，也不提子代理。

## 步骤

1. **扫对话，查漏。** 从头读本次对话。每出现一个新想法，记一条，附客户原话一句。新想法指客户想要、但还没落到票或地图里的事。然后起一个带着整段对话的子代理，用 `subagent_fork`。只问它一句：「这份清单漏了对话里的哪些新想法？」补出的并进清单。起不来，就自己再读一遍对话。不卡客户。完成条件：每一轮都读过，子代理答「无遗漏」或补出的已并入。

2. **查冲突。** 读 `map.md` 和涉及的票。给每个新想法找它碰到的旧结论。完成条件：每条新想法写明碰到的票，或写「无冲突」。有冲突，照 `map-gate` 第 3、4 步：问客户，客户说改才改。

3. **查越界产出。** 本次对话改过、新建过的文件，写过的评论，逐项归到三档：本票内、属于别的开放票、哪张都不属于。属于别票的，写清做到哪一步：全做、做了一半、只定了方向。再自己处理，不给客户出表：
   - 全做完：在那张票的 `## 评论` 记「这张的一部分已在第 N 张做过：……」，附文件相对路径。地图「接下来」那一行末尾补一笔。票保留，`Status` 不改，开工时先把已有成果拿给客户看。
   - 做了一半：同样记在评论里，写清做到哪，开工时从那里接着做。
   - 只定了方向，且成果已经把那张票的答案定死：问客户「认这个方向吗」。认了，在那张票的 `## 评论` 记「客户认了第 N 张里定下的方向」，开工时只确认一遍。不认，记「客户没认这个方向，成果只当参考」，那张票照常开放。
   - 哪张都不属于：当新想法，进第 4 步。

   对客户只说一句，例如「第 3 张的一部分，我刚才顺手做了，记在那张票里了」。

4. **记新想法。** 每个新想法归到一处：
   - 有对应的开放票：记到那张票的 `## 评论`，附客户原话。
   - 没有对应的票：写进 `map.md` 的 Not yet specified，一句话。
   - 客户明说不做：写进 Out of scope。
   - 新想法是另一个软件：照 `AGENTS.md` 里「一个工作区一个软件」那一条，问客户，不记进这份地图。

   不当场建票，不当场展开。对客户说一句，例如「这次多了一个想法，我记到第 5 张后面了」。

5. **核对先后。** 票头是准的，地图只是索引。逐项核对，不一致就改地图：
   - 「接下来」里有已 resolved 的票：删掉这一行。
   - `issues/` 里有没 resolved 的票，却不在「接下来」里：补在最后一行。
   - 「接下来」某行写着「等 03」，和票头 `Blocked by:` 不一致：以票头为准改这一行。
   - 每张 resolved 的票，在 Decisions so far 里有一行索引，缺了就补：票名加一句结论。
   - 每张 resolved 的票，`## 结论` 下有「产出文件」一行，缺了就补，没有产出文件写「无」。这一行列的是这张票写过的文件，内容是别张票的也算。后面那张票用到时，在它的结论里写「沿用第 N 张的 …」。

   改了地图，对客户说一句。完成条件：以上五项都核对过。

6. **跑 `next` 收尾。** 不要只写一句「交给 `next`」，现在就调用 `next`。核对它给的那一行指向一张 `Status:` 不是 `resolved` 的票。指向已做完或不存在的票，先改票头或地图，再跑一次；修不好就先别把这一行给客户。收尾的前三句和固定的最后一句，不在这里写。完成条件：`next` 已跑，给出的行指向没做完的票。
