name: map-gate
description: 写结论前用。起一个没参与这段对话的子代理，读地图、全部票和已有的产出文件，查这次要写的结论有没有推翻前面的结论或文件，有就问客户。
---

在写本票 `## 结论` 之前跑一次。读 `.scratch/{需求名}/` 下的地图、全部票和产出文件，查三件事：这次的结论和前面的结论有没有冲突；前面的文件有没有被这次的结论推翻；开放票的前提有没有变。

客户在一张票里说的话，可能和前面某张票已经定的事相反，客户自己没发现。本技能在结论写进文件之前把这种矛盾拦住。

除第 4 步的改动和第 5 步的评论外，本技能只读。对客户不提技能名，也不提子代理。

## 步骤

1. **备材料。** 先在对话里拟好本票的结论草稿，还不写进文件。列出本票产出的文件，写相对路径，只限 `.scratch/{需求名}/` 内。再读 `map.md` 和 `issues/*.md`。完成条件：草稿、本票产出文件、地图、全部票都在手上。

2. **起新子代理读全图。** 用 `subagent`，它是新上下文，没见过这段对话。提示里放：地图正文；每张 resolved 的票的正文、`## 结论` 和 `## 评论`；每张开放票的正文；各票 `## 结论` 下「产出文件」列出的文件全文；本票的结论草稿和产出文件。第一行标了「已被第 N 张取代」的文件，归入「已废」，不当成现行。让它给每张票写一行状态（现行、已废、部分取代），再报四类问题，每条带票名和原文一句：
   - 互相矛盾：两条结论读起来都现行，但不能同时成立。
   - 旧句仍在：地图 Notes、Decisions so far 或某个文件里的句子，已经被后来的结论推翻，读起来还像现行。
   - 开放票仍指向旧前提。
   - 文件矛盾：某个产出文件（`research/`、`prototypes/`、`pending.md`、`需求草稿.md`）的说法，和结论草稿相反。

   完成条件：每张票有一行状态，每条问题带原文和票名。子代理起不来，就自己重读同样的材料，按同样四类问题查。不卡客户。

3. **问客户。** 有冲突，一次问一条。用日常话讲两边各是什么，再问「要改前面那句吗？」。例：「你前面说价格只有老板能改，刚才说店员也能改，要改前面那句吗？」不替客户判。完成条件：每条冲突客户都答了。

4. **按客户的答案改。** 客户说改前面的：

   | 对象 | 怎么改 |
   | --- | --- |
   | 开放票 | 原地改正文，删掉被推翻的前提，末尾记一行「按第 N 张更新」 |
   | 已 resolved 的票 | 正文不动，在 `## 评论` 加「被第 N 张部分取代：……」，写明哪一部分 |
   | 地图 Decisions so far 的那一行 | 保留原行，行首标「已废，见第 N 张」 |
   | 文件 | 第一行加「已被第 N 张取代」。不移动，不删除，不改文件其余内容。只限 `.scratch/{需求名}/` 内 |

   客户说改这次的结论：只改结论草稿，不动前面。改完对照冲突点再读一遍，不必重新起子代理。

5. **留痕。** 在本票 `## 评论` 末尾写一句，没有 `## 评论` 就新建。三种写法选一种：
   - 查过：和前面没有冲突
   - 查过：和第 N 张冲突，客户选择改第 N 张
   - 查过：和第 N 张冲突，客户选择改本票的结论

   自己重读的，写成「查过（自查）：……」，运营者能分清是独立检查还是自查。

做完回到写 `## 结论`。结论下加一行「产出文件：相对路径」，没有产出文件就写「无」。
