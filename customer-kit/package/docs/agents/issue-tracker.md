# 任务管理：本地 Markdown

本工作区的任务和澄清记录都存成 Markdown 文件，放在 `.scratch/`。不用 GitHub，不用 git。

客户侧产物是给运营者审阅的澄清材料，不是最终规格。后面的事运营者自己处理。

## 约定

- 一个需求一个目录：`.scratch/<需求名>/`。需求名用英文短词或拼音。
- 小需求的澄清记录：`.scratch/<需求名>/需求草稿.md`。开头写 `Status: 进行中`，问完改成 `Status: 已问完`
- 走 `wayfinder` 的子任务：一个任务一个文件，`.scratch/<需求名>/issues/NN-<任务名>.md`，从 `01` 编号，不合并成一个文件。每个需求目录各自从 `01` 编号
- 领取状态写在文件开头的 `Status:` 行：`claimed`（已领取）或 `resolved`（已完成）。没有这一行就是没人领
- 讨论记录追加在文件末尾的 `## 评论` 下

## 当技能说“发布到任务系统”

在 `.scratch/<需求名>/` 下新建文件。目录不存在就建。

## 当技能说“读取相关任务”

读对应路径的文件。客户通常会直接给路径或编号。

## Wayfinder 用法

地图是一个文件，每张子票是一个文件。

- **地图**：`.scratch/<需求名>/map.md`，含六段：Destination、Notes、接下来、Decisions so far、Not yet specified、Out of scope。
- **接下来**：按客户定的顺序列开放票，一行一张。每行写编号、票名、这次怎么做。被挡住的，行末写“（等 03 做完）”。做完的票，这一行由 `wrap-up` 核对后删掉。
- **子票**：`.scratch/<需求名>/issues/NN-<任务名>.md`，从 `01` 编号，骨架见下。
- **类型**：票头 `Type:` 行写 `research`、`prototype`、`grilling`、`task` 之一。这里没有标签，类型只读这一行。
- **阻塞**：票头写 `Blocked by: 01, 02`。列出的票都 `resolved` 后，这张票才算解除阻塞。没有阻塞就不写这一行。
- **选票**：读地图「接下来」，取第一行没被挡、没人领的。按行序，不按编号。有 `Status: claimed` 的票，说明上次停在半路，先接着做它。
- **顺序**：拆完票，客户定完先做哪张，顺序写进「接下来」的行序，之后不再改。客户中途想换，按 `AGENTS.md` 的跳步规则处理。
- **领取**：开工前先把 `Status:` 改成 `claimed` 并保存。
- **完成**：在 `## 结论` 下写答案，再加一行“产出文件：相对路径”，没有就写“无”。`Status:` 改成 `resolved`，再把标题和一句结论补进 `map.md` 的 Decisions so far。

四个词对四类票。每张票开头，对客户说一句，用这四个词之一：

| 对客户说的词 | `Type:` |
| --- | --- |
| 聊 | `grilling` |
| 看个样子 | `prototype` |
| 我去查 | `research` |
| 动手做 | `task` |

票文件的骨架：

```markdown
# 03 我在哪改价格和库存

Type: prototype
Status: claimed
Blocked by: 02

## Question

老板在手机上改价格和库存，改完顾客那边马上能看到。要定的是后台首页长什么样、改一个价格点几下。

## 评论

客户原话：「我早上忙，最好扫一眼就知道哪个卖完了，点两下就改完。」

## 结论

（做完才写）

产出文件：prototypes/03-后台首页.html
```

没人领时不写 `Status:` 行。没有阻塞时不写 `Blocked by:` 行。

地图的「接下来」样子：

```markdown
## 接下来

- 03 我在哪改价格和库存 —— 看个样子，我做个原型给你看
- 04 取货了怎么通知顾客 —— 我去查，查完告诉你（等 03 做完）
```

GitHub 里的 issue、label、assignee、close、comment 这些词，在本工作区都按上面这套文件操作理解。
