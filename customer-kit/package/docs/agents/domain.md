# 领域文档

本文件说明工程类技能了解本工作区时，该怎样读取领域知识。

## 开始前先读什么

- 根目录存在 `GLOSSARY.md` 时，先读它。
- 根目录存在 `GLOSSARY-MAP.md` 时，先通过它找到与当前工作相关的那份 `GLOSSARY.md`。
- 读 `docs/adr/` 中与当前工作相关的决定记录。

这些文件不存在时直接继续，不提示缺失，也不提前建议创建。等术语或重要决定真正明确后，再由 `domain-modeling` 按需创建。

## 文件布局

本工作区是单一上下文：

```text
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-示例决定.md
│   └── 0002-另一项决定.md
└── .scratch/
```

## 使用已经定下的说法

写子票标题、结论、假设时，领域概念用 `GLOSSARY.md` 里定的名称，不要换成近义词。

需要的概念还没定义时，先判断是不是自己造了工作区里不存在的说法。确实缺失，再记为需要通过 `domain-modeling` 解决的问题。

## 明确指出与决定记录的冲突

建议与已有决定冲突时，直接指出冲突和重新讨论的理由，不要悄悄覆盖。例如：

> 这与 ADR-0007 的决定冲突，但值得重新讨论，因为……
