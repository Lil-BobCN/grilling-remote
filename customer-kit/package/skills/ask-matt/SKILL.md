# 问 Matt

客户不知道下一步怎么走时，看这里选。先读你要推荐的那个技能的 `SKILL.md`，再回答。这张表只用来找方向。

## 八个技能

| 客户现在的情况 | 用哪个 | 一句话 |
| --- | --- | --- |
| 刚说完想做什么，问题一次对话能问完 | `grilling` | 一轮一轮问清楚，每题给推荐答案 |
| 有词分不清，一个词指好几件事，或有以后难改的决定 | `grilling` + `domain-modeling` | 边问边把词定下来，必要时记一条决定 |
| 一次对话装不下：要分阶段、多角色、多模块，客户自己也说不清终点 | `wayfinder` | 先建地图，再一张票一张票解 |
| 地图里有 `prototype` 票，客户想看界面或逻辑怎么走 | `prototype` | 做一个单文件 HTML，给客户点 |
| 需要一个外部事实：官方文档、API、政策、价格 | `research` | 派子代理查一手资料，写成带出处的 Markdown |
| 第一次装配，或技能、配置文件坏了 | `setup-matt-pocock-skills` | 重写追踪器和领域文档配置 |
| 客户没听懂上一条 | `wait-what` | 用更短的话重讲。客户也可以自己输入 `/wait-what` |
| 不知道下一步、该不该开新对话、该不该做原型 | `ask-matt` | 就是这里 |

## 选择规则

1. **一次对话最多解决一张票。** 当前票没做完，不推荐开新票，也不推荐做下一张。
2. **拿不准就选小的。** 能 `grilling` 解决的，不要上 `wayfinder`。
3. **原型默认被动。** 地图里没有 `prototype` 票，不要推荐现场做。客户主动要，先劝“现在还不能做”，把当前问题答完。
4. **技术题不转人工。** 先给推荐答案；客户说不懂，就按推荐往下问，记进 `.scratch/{简称}/pending.md`。推荐答案先联网查证，写出处。
5. **备案、账号、付款、合同**这类只有运营者能办的事，说“这一步找运营者”，记进 `pending.md`。
6. **只推荐这八个技能。** 不要提没装的技能，不要把客户送到不存在的命令上。

## 怎么回答

先说下一步做什么，再说为什么，最后给客户一句能直接照做的话。

如果下一步要新开对话，给客户一句可以粘贴的话，例如：

> 继续做需求澄清。请读取 `.scratch/{简称}/map.md` 的 Notes，再选下一个子任务。本次对话只做这一个。

不要替客户做决定，不要替客户回答澄清问题。
