# 自动关票：待关票记录与合并触发

状态：accepted（2026-11-13）
来源：[实现自动关票：待关票记录、合并触发与安全检查](https://github.com/Lil-BobCN/grilling-remote/issues/186)
背景：D-0032、D-0033、D-0034、ADR 0002、ADR 0006、`中台/设计.md`

## 问题

关票原来靠主代理在 PR 合并后手工做：写四条评论、建决定、跑 `dt issue close`。合并和关票之间要有人一直盯着，记录还容易随会话丢掉。

现在改成：干活的 agent 开完 PR 就写一条待关票记录，运营者合并后由服务展开记录并关票。要定清楚记录长什么样、谁来触发、失败怎么处理、哪些动作仍然只能人做。

## 决定

### 记录

1. 记录由一条 `close.prepare` 事件创建，编号 `CL-0001` 起。
2. 记录字段：票号、PR 号、head SHA、四条关票评论、决定草稿、写入人、写入时间、状态、核对结果。
3. 状态四个：`等合并`、`已展开`、`过期`、`失效`。同一张票同时只有一条等合并记录；再写一条时，旧的标失效。
4. 决定草稿只写陈述、产出文件和依据。编号在写记录时分配，评论里的 `{{D1}}`、`{{D2}}` 占位符替换成真实编号，保证四列表和决定对得上。
5. 记录撤销或过期后，已经分配的决定编号不回收。

### 事件

v5 新增四个 op。

| op | target | payload |
| --- | --- | --- |
| `close.prepare` | 票号 | `record`、`pr`、`sha`、`comments`（正好四条）、`decisions`（决定草稿） |
| `close.revoke` | 票号 | `record` |
| `close.mark` | 票号 | `record`、`status`（只能是过期）或 `verify`（null 或无法核对）、`check`、`detail` |
| `issue.close` | 票号 | `record`、`pr`、`comments`（四条，带评论号）、`decisions`（带决定号） |

`issue.state` 升 v5，多一个可选字段 `close_record`。运营者强制关票时带上它，折叠时把记录标失效。

`issue.close` 一条事件装下四条评论、决定和票状态。写到一半失败不会留下半套关票，符合 ADR 0002 的「一次动作一条事件」。

### 触发

1. 服务现有的 WorkStatePoller 每 2 秒读 orca，顺带读 `linkedPR`。看到票上有等合并记录且 PR 是 `merged`，调一次 `gh pr view <号> --json state,headRefOid`。
2. `gh` 返回 `MERGED`，且 `headRefOid` 等于记录里的 SHA，写一条 `issue.close`。不相等标过期。
3. `gh` 返回 `CLOSED`，或者 orca 先说 PR 已关闭，标过期，不关票。
4. `gh` 调不到，记录标「无法核对」，不关票。30 秒后重试；恢复后照常核对。
5. 写 `issue.close` 失败时保留记录，错误写进 `workstate.json` 的 `close_errors` 和服务日志，下一轮轮询重试。
6. 记录已展开，或票已关闭，跳过，不重复写。

### 关票内容

折叠 `issue.close` 时一次做四件事：按记录里的正文建四条评论、按决定草稿建决定（来源票是本票）、把票置 closed、把记录标已展开。

自动关票只新建决定。取代、作废、开影响清单仍走原来的命令，由运营者确认，见 D-0026。

### 权限

| 动作 | 谁做 |
| --- | --- |
| 写记录 `close.prepare` | 干活的 agent |
| 撤回记录 `close.revoke` | agent 或运营者 |
| 展开记录 `issue.close` | 中台服务 |
| 强制关票 `dt issue close --force` | 只给运营者，事件 actor 必须是 `human:` |

有等合并记录时，`dt issue close` 和屏幕的关票都拒绝，避免绕过合并。

### 屏幕

1. 票卡在有等合并记录时显示「等合并」。
2. 新增五类信号：待关票记录过期、缺待关票记录、关票 SHA 不符、关票无法核对、关票写入失败。
3. 票的侧边栏列出记录号、状态、PR 号、SHA、写入人、最近核对结果和决定草稿。

## 考虑过的做法

| 做法 | 不采用的原因 |
| --- | --- |
| 合并后主代理手工关票 | 合并和关票之间要有人盯；记录随会话丢掉 |
| 另起一个盯 PR 的 watcher | 中台每 2 秒已经在读 orca，多一个进程没必要（D-0032） |
| 合并前把评论写进票里 | 提前断言合并；PR 可能被关掉 |
| 记录放临时文件 | 随会话和 worktree 丢（D-0033） |
| 每条评论、每个决定各写一条事件 | 写到一半失败会留下半套关票 |
| 不比对 SHA | 合并的可能不是记录时看到的那次提交 |
| 自动关票里顺带处理取代和作废 | 决定变化要开影响清单并由运营者确认，不能藏在合并里 |

## 后果

- 自动关票要求中台服务在线，且能读到 orca 的 `linkedPR`。服务要用新代码重启后才生效。
- 记录展开前，评论和决定只在事件日志和屏幕里。同步到 GitHub 仍由运营者按地图触发。
- 撤销或过期的记录会留下空的决定编号。
- 取代、作废和影响清单不在自动关票范围内。
