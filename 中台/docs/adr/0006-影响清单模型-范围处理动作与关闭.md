# 影响清单模型：范围、处理动作与生命周期

状态：accepted（2026-11-12）
来源：[影响清单模型：范围、处理动作与生命周期](https://github.com/Lil-BobCN/grilling-remote/issues/151)
背景：地图 #139、ADR 0002、ADR 0003、ADR 0004、`中台/设计.md`

## 问题

决定一变，要能算出哪些决定和票受影响，逐项处理，处理完关闭清单。这份 ADR 定触发、范围算法、范围项、处理动作、多清单和关闭。屏幕怎么排布、同步怎么触发、事件外层字段不在本 ADR。

## 实体

影响清单 `IC-0001`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `IC-0001` | 服务分配，不复用。前缀沿用发起时的 `IC-` |
| `trigger_event` | 事件 `seq` | 打开它的那条事件 |
| `trigger` | `overturn` / `void` / `premise_broken` / `root_replaced` | 触发类型 |
| `trigger_decision` | 决定 id | 触发指向的决定 |
| `items` | 数组 | 范围快照，每项 `{ kind, ref, relations[] }` |
| `status` | `open` / `closed` | 折叠出来 |
| `opened_at` / `opened_by` | | 从触发事件取 |
| `closed_at` / `closed_by` | | 从 `impact.close` 取 |

范围项的状态不单独存，由处理事件折叠：

| 状态 | 含义 |
| --- | --- |
| `待处理` | 没有任何处理事件 |
| `已处理` | 有处理事件，带动作 |
| `已失效` | 决定在别的清单里变成被取代或作废，自动结清 |

同一项可以再处理，后一次覆盖前一次，两次事件都留在日志里。清单关闭后不能再处理。

## 触发

只有四类事件打开影响清单：

| 触发 | 条件 | 触发决定 |
| --- | --- | --- |
| `decision.overturn` | 被取代的决定是 active，且不是根决定 | 被取代的旧决定 |
| `decision.void` | 被作废的决定是 active | 被作废的决定 |
| `premise.judge` 判 `已破` | 前提所属决定是 active | 前提所属决定 |
| 根决定被取代 | 旧根决定是 active | 旧根决定，触发类型记 `root_replaced` |

不打开清单的事件：`decision.create`（普通新建决定）、票的编辑和状态变化、评论、标签、阻塞。

`decision.overturn`、`decision.void`、`premise.judge` 的 payload 带上影响清单：

```
"impact_case": "IC-0003",
"impact_items": [
  { "kind": "decision", "ref": "D-0012h", "relations": ["derived_from"] },
  { "kind": "ticket", "ref": "I-0004", "relations": ["source_ticket"] }
]
```

范围为空时不带 `impact_case`，不打开清单。前提判破的清单至少有决定本身，总会打开。

`decision.overturn` 只能在清单外触发打开新清单。在清单内处理时走 `impact act`，见「处理动作」。清单内产生的替代决定不另开新清单，因为它影响的决定和票已经在当前清单的范围里。

## 范围

从触发决定出发，沿声明过的因果边走，算到没有新对象。用已访问集合防环。

1. **向下派生**：受影响的决定 A → `derived_from` 含 A 的票 → 这些票用 `source_ticket` 产出的决定 → 继续。这是主链。
2. **来源票**：受影响的决定 A → `A.source_ticket` 那张票进范围。到这里停，不拉这张票产出的其他决定，否则兄弟决定会一起进来。
3. **覆盖边**：换根时，旧根决定的拆句 → `covers` 指向这些拆句的票进范围。从这里也不往下拉产出的决定。
4. **前提**：受影响决定挂的前提跟在决定下面显示，供重判用。前提不单独成项，也不再往下传。
5. **取代**：触发项是旧决定本身。新的替代决定不进范围，它是原因，不是受影响项。

同一个对象只进一项，`relations[]` 记全部进入原因。一张票既从派生进、又覆盖旧拆句进，仍然只有一项。

## 范围项

| 对象 | 收不收 | 说明 |
| --- | --- | --- |
| active 决定 | 收 | 要选四档 |
| 被取代、作废的决定 | 不收 | 只作链路背景显示，不给动作 |
| 开着的票 | 收 | 选五种动作 |
| 已关闭的票 | 收 | 可能要重开 |
| 前提 | 不收 | 挂在所属决定下面显示 |
| 覆盖句 | 不收 | 换根时通过它把承接票拉进范围 |
| 触发决定 | 分情况 | 被取代、作废、换根的旧决定不收；前提判破的决定收 |

## 处理动作

### 决定四档

| 动作 | 写什么事件 | 结果 |
| --- | --- | --- |
| `仍成立` | `impact.act` | 决定状态不变；红色按下面的规则消 |
| `需修改` | `decision.overturn`，带 `impact_case`、`impact_item`、`impact_action` | 旧决定变 superseded，新决定 active；新决定不另开清单 |
| `作废` | `decision.void`，带 `impact_case`、`impact_item`、`impact_action` | 决定变 void |
| `要补问` | `issue.create`，带 `impact_case`、`impact_item`、`impact_action` | 决定保持 active，红保持；跟进票关掉后再判 |

`要补问` 建的票型是 grilling 或 research。票的 `derived_from` 至少含这条决定，`split_reason` 写清为什么要补问。跟进票关掉后，如果决定要改，走正常推翻流程，会打开新的影响清单。

根决定不能作废。根决定选 `需修改` 时，新决定是新的根，`root_of` 指同一张地图，覆盖表按新拆句重算。换根后新出现的覆盖缺口由覆盖表信号处理，不往当前清单加项。

### 票五种

| 动作 | 写什么事件 | 说明 |
| --- | --- | --- |
| `保留` | `impact.act` | 票不动 |
| `改范围` | `issue.edit`，带 impact 字段 | 改正文、`derived_from`、`covers` |
| `关掉` | `issue.state`，带 impact 字段 | 状态变 closed，理由写在事件外层 `reason`；合并时带 `impact_merged_into`，写并入哪张 |
| `重开` | `issue.state`，带 impact 字段 | 状态变 open |
| `新建` | `issue.create`，带 impact 字段 | 新票 `derived_from` 至少含受影响的决定，写 `split_reason` |

合并不单独算一个动作：选 `关掉`，带上 `impact_merged_into` 记目标票号，屏幕按「并入 <目标票>」显示。不搬评论，不生新实体。票上不单独写评论，理由在事件里，镜像需要时由同步引擎生成。

### 事件形状

动作事件在自己原有的 op 上带三个可选字段：

```
"impact_case": "IC-0003",
"impact_item": { "kind": "decision", "ref": "D-0012h" },
"impact_action": "需修改"
```

`仍成立` 和 `保留` 不改任何对象，单独写 `impact.act`：

```
op: impact.act
target: IC-0003
payload: { "item": { "kind": "decision", "ref": "D-0012h" }, "action": "仍成立" }
reason: "..."
```

关闭写 `impact.close`，target 是清单号，payload 空，理由写在事件外层 `reason`。

## 红色怎么消

设计稿的颜色规则是「至少一条前提已破就红」。判了 `仍成立` 以后，前提还是已破，要按处理过算，否则这条决定会一直红着。

规则：决定挂着的前提里，当前状态有 `已破`，且这些前提里最近一次 `已破` 判定晚于该决定最近一次 `仍成立`，才红。前提后来重判成 `成立`，红自然消。`要补问` 不算消红。判了 `需修改` 或 `作废` 以后，决定已经变成被取代或作废，按划线显示，不再用红色。再破一条前提，红再亮。

## 多清单与关闭

- 同一对象可以同时在多个影响清单里。各清单独立记动作，不合并清单。
- 决定在另一个清单里已经变成被取代或作废，本清单里这一项自动算 `已失效`，不再要求四档动作。
- 所有项都是 `已处理` 或 `已失效`，才能关闭清单。`要补问` 算 `已处理`，因为留了跟进票。
- 关闭要人显式执行 `impact close`，不自动关。
- 清单外的新变更另开新清单，不往已开的清单里加项。清单内处理产生的替代决定不另开清单，也不改当前清单的范围。
- 关了的清单不再打开。要重判就走新的触发。

## 命令

自动打开清单，没有 `impact open` 命令。读和写：

```
dt impact show IC-0003
dt impact list
dt impact act IC-0003 D-0012h 仍成立 --reason "..."
dt impact act IC-0003 #145 保留 --reason "..."
dt impact act IC-0003 D-0012h 需修改 --statement "..." --source-ticket #149 --reason "..."
dt impact act IC-0003 D-0012h 作废 --reason "..."
dt impact act IC-0003 D-0012h 要补问 --title "..." --type grilling --derived-from D-0012h --split-reason "..." --reason "..."
dt impact act IC-0003 #145 改范围 --body "..." --derived-from D-0012 --reason "..."
dt impact act IC-0003 #145 关掉 --reason "..."
dt impact act IC-0003 #145 重开 --reason "..."
dt impact act IC-0003 #145 新建 --title "..." --type task --derived-from D-0012 --split-reason "..." --parent 139
dt impact act IC-0003 #145 合并 --into #147 --reason "..."
dt impact close IC-0003 --reason "..."
```

`impact act` 是底层命令的包装：它把影响清单字段带上，只写一条事件。直接跑 `decision overturn` 等底层命令，算清单外变更，另开清单。参数细节归《实现内核》。

## 例子：D-0012 取代 D-0011e

D-0011e 是 14 个 op 的清单。D-0012 把事件模型升到 v2，取代 D-0011e。按当前 ADR 能确认的边：

| 对象 | 关系 | 处理 |
| --- | --- | --- |
| D-0011e | 触发决定，不处理 | 已被 D-0012 取代，划线 |
| #141 | D-0011e 的来源票 | 保留，工作已完成 |
| D-0012h | 由 #149 产出；#149 的 `derived_from` 含 D-0011e | 仍成立，v2 的 op 清单仍然要 |
| #149 | `derived_from` 含 D-0011e 的票 | 保留，它就是推翻动作的来源 |
| #145 | 实现内核；`derived_from` 含 D-0011e | 改范围，按 v2 的 18 个 op 实现 |
| #147 | 验收；`derived_from` 含 D-0011e | 改范围，按 v2 核对 |

每项有动作后执行 `dt impact close`，清单关闭。D-0012 本身不进范围，它是原因。D-0011f、D-0011g 也不进范围，它们由 #141 产出，来源票这条边只上一跳。

## 考虑过的做法

| 做法 | 不采用的原因 |
| --- | --- |
| 影响清单只做现算视图 | 处理状态和关闭时间没地方存，跨会话接不上 |
| `impact.open` 单独一个 op | 一次推翻会写两条事件，崩在中间留下半套；ADR 0002 已禁止 |
| 触发事件只记触发决定，范围每次现算 | 边一变范围就变，处理到一半范围漂移 |
| 手工加项或删项 | 边界又变成手画，和「算出来的边界跟着决定变」相反 |
| 清单外新变更并进旧清单 | 清单永远关不掉，范围越滚越大 |
| 多个清单合并成一个 | 清单号、触发历史、关闭条件都变复杂；各清单独立加已失效规则更简单 |
| 合并单独做成一个动作和 op | 没有合并实体，评论也不能搬；关掉加 `impact_merged_into` 够了 |
| 屏幕按五种边分栏 | 运营者看不出该做什么；每项带一句问题和一个动作，按待办显示 |
| 判破前提自动改决定 | 和 ADR 0004 冲突，人判 |

## 后果

- 事件模型 v2 加 `impact.act` 和 `impact.close` 两个 op，从 16 个变 18 个。
- `decision.overturn`、`decision.void`、`premise.judge` 的 payload 加可选字段：触发用 `impact_case` 和 `impact_items`；动作用 `impact_case`、`impact_item`、`impact_action`。
- 范围在写触发事件之前算好，算失败不写事件。
- 屏幕读影响清单显示待办，不按五种边分栏。
- 地图 Destination 第 6 句和 Notes 的「票六种」改成「票五种」。
- 旧设计稿「推翻的时候发生什么」一节按这份 ADR 改写。
- 问题目录作为 v1 的限定写进 `中台/设计.md`。
