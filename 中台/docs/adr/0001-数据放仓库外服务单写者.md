# 数据放仓库外，服务是唯一写者

状态：accepted（2026-11-10）
来源：[数据位置与读写路径：服务、CLI、events.jsonl](https://github.com/Lil-BobCN/grilling-remote/issues/140)
背景：`中台/设计.md`

中台的数据放在仓库外的 `~/.grilling/中台/`，`events.jsonl` 是权威记录，`board.db` 是可以随时删掉重建的索引。所有读写都经过本机服务，服务只监听 `127.0.0.1:8788`，是唯一写者。这样定的原因：本机十几个 worktree 共用主仓，数据放主仓会让每个分支看到不同版本；事件日志只追加，适合多会话读、单进程写。

## 决定

### 数据目录

- 默认 `~/.grilling/中台/`，首次运行 `dt` 时创建。
- `events.jsonl` 存事件，`board.db` 存折叠出来的索引。
- `service.json` 记端口和 pid，`service.log` 记服务日志，`backups/` 存修复前的副本。
- 测试和临时实例用 `GRILLING_HOME` 覆盖根目录，用 `GRILLING_PORT` 覆盖端口。

### 访问路径

- 服务只监听 `127.0.0.1:8788`。端口被占时退出并提示占用者，不自动换端口。
- CLI 读写都发 HTTP 请求，不直接打开数据文件。
- CLI 先读 `service.json` 找服务；文件缺失或健康检查失败视为服务未启动。
- 服务没启动时，CLI 后台拉起 `dt serve`，最多等 5 秒。并发拉起时抢到端口的服务赢。
- 拉起的服务脱离调用它的会话，会话结束不退出。机器重启后不自启，下一次 `dt` 调用或 `dt open` 时再拉起。
- 写请求失败或超时不自动重试，报「结果未知」，退出码 4，提示先用读命令查。读请求可以重试一次。

### 启动与重启

- 启动顺序：拿 `flock`，扫描事件日志，打开或重建 `board.db`，重放事件比对哈希，写 `service.json`，打印地址。
- 锁被占时读 `service.json` 的 pid。进程活着就退出并提示已在运行。
- 锁随进程释放，崩溃后不留残锁。
- 重放失败说明事件本身坏了，拒绝启动并报行号。

### 屏幕

- 页面已打开时服务断开，顶部显示「服务已断开，正在重连」，动作按钮禁用，每 2 秒重试。
- 重连成功后重新拉全量状态，不补播断开期间的事件。
- 服务没启动时直接访问 URL，浏览器报连接失败。
- `dt open` 先拉起服务，再打开浏览器。

### 快照

- 数据目录独立成 git 仓，分支 `main`，v1 不配远端。
- 只有服务提交。写入空闲 60 秒后提交，两次提交至少隔 10 分钟；服务正常退出时补一次。
- `dt snapshot` 手动提交。
- `board.db`、`service.json`、日志、锁文件写进数据仓的 `.gitignore`。
- git 提交失败只记 `service.log`，不挡写事件。

### 损坏恢复

- 一条事件一行，加 `flock` 后追加，写完 `fsync`。
- 启动时扫描 `events.jsonl`。最后一行不完整或不是合法 JSON，把这段残片搬到 `events.jsonl.torn-<时间戳>`，截到最后一个完整行，记日志后继续。
- 文件中间有坏行，拒绝启动，报行号，不自动修。
- `board.db` 打开失败或哈希和重放结果不一致时，删掉重建。
- 每次修复前和每次 `rebuild` 前，在 `backups/` 留一份 `events.jsonl`，保留最近 10 份。
- v1 不做异机备份。

## 考虑过的做法

| 做法 | 不采用的原因 |
| --- | --- |
| CLI 直读 `events.jsonl` | CLI 要自己折叠状态，还要处理残片，单写者约束也保不住 |
| 数据提交到主仓的单独分支 | 本机多个 worktree 共用主仓，分支和 ref 会被别的会话动 |
| 写请求自动重试 | 事件可能已经写入，重试会重复记一条 |
| 异机备份 | v1 多一套凭据和发布判断，先不做 |

## 后果

- 服务必须先运行。CLI 会自动拉起，第一次调用会慢几秒。
- 数据不在代码评审里，回滚靠数据仓的 git 历史。
- 数据仓没有远端，磁盘坏了会丢数据。v1 接受，后续可以加私有远端。
