# 图、票与评论模型

状态：accepted（2026-11-10）
来源：[图、票与评论模型：根决定、拆票理由、字段与关系](https://github.com/Lil-BobCN/grilling-remote/issues/149)
背景：地图 #139、ADR 0002、`中台/设计.md`

## 问题

中台要存四类记录：地图、决定、票、评论。地图的终点是一句主句，存成根决定；根决定拆成票，票再产出或推翻决定。这份 ADR 定四类记录的字段、因果边和编辑动作，事件模型升到 v2。

## 实体

### issue：地图和票

地图是 `kind: map` 的 issue，票是 `kind: ticket` 的 issue。两者共用实体、编号、评论、标签、父子关系。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 导入的 issue 用 GitHub 号，如 `139`；新建的用 `I-0001` |
| `kind` | `map` / `ticket` | 建时固定，不能改 |
| `type` | `grilling` / `research` / `prototype` / `task` | 票才有 |
| `title` | 字符串 | |
| `body` | 字符串 | 地图正文放 Notes、未定、范围外、索引；不放 Destination 主句和拆句 |
| `state` | `open` / `closed` | |
| `labels` | 字符串数组 | 自由文本，只存名字；不含 `wayfinder:map` 和 `wayfinder:<type>` |
| `parent` | issue id | 票必填，且必须是地图；地图为空 |
| `blocked_by` | issue id 数组 | 票才有，挡它的票 |
| `split_reason` | 字符串 | 票才有，新建必填；导入的老票可空 |
| `derived_from` | 决定 id 数组 | 票才有，新建至少一条；可多条 |
| `covers` | 拆句 id 数组 | 票才有，可空 |
| `created_at` / `updated_at` / `closed_at` | 时间 | |
| `created_by` | actor | |

`children`、`blocks`、`产出决定`、`覆盖行` 都不存，从这些字段反算。

### 决定

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `D-0012` | 导入保留原号，新建取最大号加一 |
| `statement` | 字符串 | 一句话写清定了什么 |
| `fragments` | 数组 | 根决定才有；每项 `{ id: "D-0012#1", index: 1, text }` |
| `root_of` | issue id | 根决定才有，指地图 |
| `source_ticket` | issue id | 非根决定通常是来源票；可空，屏幕标「无源决定」 |
| `output_files` | 字符串数组 | 相对路径 |
| `status` | `active` / `superseded` / `void` | 折叠出来；先看是否被取代，再看是否被作废 |
| `created_at` / `created_by` | | |

决定没有 `group` 字段。旧的「组」由 `source_ticket` 取代。

### 评论

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `C-0001` | |
| `issue` | issue id | |
| `body` | 字符串 | 删除后为空 |
| `author` | actor | 创建时的 actor |
| `created_at` / `edited_at` | 时间 | |
| `deleted` | 布尔 | 删除是墓碑 |

删除后不能再编辑或恢复；要补内容就新发一条评论。

### 覆盖行（视图）

不单独存，由根决定的拆句和票的 `covers` 联接出来：

```
拆句 id | 原文 | 序号
票列表：[{ 票号、标题、状态、工作状态、拆票理由 }]
状态：缺口 | 进行中 | 已落 | 失效
```

- 缺口：没有票接这句。
- 进行中：有票开着。
- 已落：接它的票全关了。
- 失效：这句属于旧根决定，当前根决定里没有。

覆盖表只列当前根决定的拆句。旧拆句上还挂着的票，由「吃旧决定」信号单独显示。工作状态不存进 issue，由《工作状态同步：orca → 中台》单独提供。

## 因果边

| 边 | 方向 | 存哪 | 说明 |
| --- | --- | --- | --- |
| `source_ticket` | 决定 → 票 | 决定 | 这条决定是哪张票产出的；一条决定最多一个 |
| `derived_from` | 票 → 决定 | 票 | 这张票从哪条决定拆出来；可多条 |
| 取代 | 新决定 → 旧决定 | 旧决定的 `status` | `decision.overturn` 写 |
| 前提依赖 | 决定 → 前提 | 前提 | 见《前提模型：状态、判定与命令》 |
| `covers` | 票 → 拆句 | 票 | 覆盖边；一张票可接多句，一句可落多张票 |

决定的派生不单存。B 从 A 派生，通过 B 的 `source_ticket` 和那张票的 `derived_from` 算出。整条链是决定 → 票 → 决定。

## 编辑动作

| 对象 | 能改什么 | 事件 |
| --- | --- | --- |
| 地图 | 标题、正文 | `issue.edit` |
| 地图 | 状态 | `issue.state` |
| 地图 | 标签 | `issue.label` |
| 地图 | Destination | 新根决定加 `decision.overturn` |
| 票 | 标题、正文、类型、拆票理由、`derived_from`、`covers` | `issue.edit`（v2） |
| 票 | 状态 | `issue.state` |
| 票 | 标签 | `issue.label` |
| 票 | 阻塞 | `issue.block` |
| 票 | 父票 | v1 不开放 |
| 评论 | 新建、编辑、删除 | `comment.create/edit/delete` |
| 决定 | 新建 | `decision.create` |
| 决定 | 取代 | `decision.overturn` |
| 决定 | 作废 | `decision.void` |
| 覆盖 | 不单独改，随票的 `covers` | 无 |

### 命令

命令名在《实现内核：事件日志、CLI、导入与同步》里定。每条写命令只写一条事件。

| 命令 | 事件 |
| --- | --- |
| `issue create --kind map --destination ...` | `issue.create` |
| `issue create --kind ticket --parent ... --type ... --derived-from ... --split-reason ...` | `issue.create` |
| `issue edit <id>` 带标题、正文、类型、拆票理由、`derived_from`、`covers` 中至少一项 | `issue.edit` |
| `issue state <id> open\|closed` | `issue.state` |
| `issue label <id> --add ... --remove ...` | `issue.label` |
| `issue block <id> --add ... --remove ...` | `issue.block` |
| `comment add <issue> --body ...`、`comment edit <id> --body ...`、`comment delete <id>` | `comment.create/edit/delete` |
| `decision create --statement ... --source-ticket ... --output-files ...` | `decision.create` |
| `decision overturn <id> --statement ... --source-ticket ...` | `decision.overturn` |
| `decision void <id> --reason ...` | `decision.void` |

## 事件模型 v2

ADR 0002 的 v1 保留。v2 加这些字段和一个 op：

- `issue.create`：加 `kind`；票加 `type`、`split_reason`、`derived_from`、`covers`；地图加 `destination: { decision, statement, fragments[] }`。折叠时同时建地图和根决定。
- `issue.edit`：payload 从 `title`、`body` 扩到可带 `type`、`split_reason`、`derived_from`、`covers`，至少一个字段。
- `decision.create`：删 `group`；加 `fragments`、`root_of`（根决定才有）。
- `decision.overturn`：`new_decision` 是对象，带 `id`、`statement`、`source_ticket`、`output_files`，根决定再带 `fragments`、`root_of`。
- `decision.void`（新增，第 15 个 op）：target 是决定，payload 带 `reason`，可带 `impact_case`。决定状态变 `void`。
- `issue.block`：target 是被挡的票，`add[]` / `remove[]` 是挡它的票。
- `issue.parent`：v1 不开放，命令层拒绝。

根决定不能作废。要换终点，用新根决定加 `decision.overturn`；要放弃地图，关地图。作废只用于非根决定。

## 编号

- 新建 issue：`I-0001` 起，地图和票共用一个序列。
- 导入的 issue：保留 GitHub 号，如 `139`。
- 新建决定：现有最大 `D-` 号加一，导入的保留原号，含 `D-0001a`、`D-0002e` 这类后缀。
- 根决定：编号见 ADR 0005，统一 `D-<地图号>-ROOT`，如 `D-117-ROOT`。
- 评论：`C-0001` 起。
- 前提：`P-0001` 起。
- 拆句：`D-0012#3`，决定号加序号，不另发 `F-` 号。
- 同步到 GitHub 后拿到的编号进同步映射，本地号不变。

## GitHub 映射

| 中台 | GitHub |
| --- | --- |
| `kind = map` | `wayfinder:map` 标签 |
| `type` | `wayfinder:<type>` 标签 |
| `parent` | sub-issue |
| `blocked_by` | issue dependency 的 blocked by |
| `labels` | 标签名字 |
| 评论 | issue comment |
| 状态 | open / closed |

决定、前提和覆盖表的 GitHub 形式见 ADR 0005：写在地图正文的生成段里，不单独发评论。只读镜像的触发、失败和生成段规则也由 ADR 0005 定。

不搬：assignees、milestones、projects、reactions、通知、PR 关联、issue 模板、转移、置顶、GitHub issue types、自定义字段、多用户和权限。状态只 `open` / `closed`，不记 not planned。issue 只关不删；评论可删，留墓碑。

## 规则

- 地图和票一层：票的 `parent` 必填，且必须是地图；票不能有子票。
- 父票 v1 不改。建错地图就关掉重建。
- 票型是封闭四值，必须有一个。
- 新建票必须有 `split_reason` 和至少一条 `derived_from`。
- 导入的老票按 ADR 0005 处理：`derived_from` 挂根决定，`split_reason` 留空，屏幕标「拆票理由：未记录」。
- 一条决定最多一个 `source_ticket`。非根决定新建时必须给；导入的可以是空，屏幕标「无源决定」。
- `covers` 在新建和编辑时只指当前根决定的拆句。根决定换掉后，旧 `covers` 变失效，屏幕标「吃旧决定」。
- 阻塞允许跨地图；地图不参与阻塞；拒绝自挡和环。
- 关闭一个挡路的票不删边；算 frontier 时只数还开着的。
- 根决定不能作废。
- 设计初稿里票的「消费 [D-]」不进 v1。票从哪条决定来用 `derived_from` 表达；动手时认定有效的决定由前提和 `derived_from` 覆盖。

## 考虑过的做法

| 做法 | 不采用的原因 |
| --- | --- |
| 地图单独一个实体 | 事件模型只有 issue 的 op；GitHub 镜像里地图就是 issue；分家要多一套实体和事件 |
| Destination 留在地图正文 | 改终点会绕过决定历史；正文可改，根决定不可改 |
| 覆盖表单独存记录 | 要多一个实体和一套 op；拆票理由本来就在票上，联接就够 |
| 决定之间单存派生边 | 同一件事写两遍，票和决定可能互相矛盾；来源票加 `derived_from` 能算出 |
| 票型用标签 | 零个或两个票型拦不住；字段能保证封闭四值 |
| 标签固定集合 | 挡掉已有标签和迁移数据 |
| 建地图写两条事件 | 中间崩了会留下没有终点的地图；一次操作一条事件 |
| 保留 `group` | `source_ticket` 已经表达来源，组是迁移便利 |
| 拆句另发 `F-` 号 | 拆句属于决定，决定号加序号就够 |
| 作废写一条假决定 | 决定列表会多出不是承诺的行；`decision.void` 直接标记 |

## 后果

- 事件模型从 14 个 op 变 15 个，v2 事件和 v1 事件分开折叠。ADR 0002 加一条指针。
- 覆盖表不存状态，每次从票和拆句算；屏幕要能算联接。
- 导入老数据时，`derived_from` 挂根决定，`split_reason` 留空并显示「未记录」，`source_ticket` 从评论所在票还原。规则见 ADR 0005。
- 影响案《影响案模型：范围、处理动作与生命周期》用 `decision.void` 落「作废」，用 `decision.overturn` 落「需修改」。
- 屏幕《屏幕原型：决策图、影响案与视觉信号》按覆盖行的四个状态和覆盖缺口、无主票、无源决定、吃旧决定这几个信号画。
