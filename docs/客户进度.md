# 客户进度和消息

2026-11-07 定，来源 [客户交完之后怎么知道进度](https://github.com/Lil-BobCN/grilling-remote/issues/52)。客户看不到工单。网站以后有一个进度模块，另开票；这份文件定客户看到的档位、三条消息和通道。

## 一、客户看到的五档

```text
已收到
├─ 校验未通过 → 客户补完重传 → 已收到
└─ 安排中 → 开发中 → 待客户验收
                       ├─ 点头 → 已完成
                       └─ 驳回 → 已驳回（新开发需求）
                                    └─→ 开发中 → 待客户验收
```

| 顺序 | 客户看到 | 内部标签 | 内部在做什么 | 卡在谁 |
| --- | --- | --- | --- | --- |
| 1 | 已收到 | 还没建单 | 上传成功，服务器校验 | 服务器 |
| A | 校验未通过 | 还没建单 | 校验不过，只存快照；客户补完重传，回第 1 步 | 客户 |
| 2 | 安排中 | 已提交 → 排队中 | 建单 → 技术闸门 → 写 spec → 拆票 → 点头 | 运营者 |
| 3 | 开发中 | 开发中 | 点火 → 子票开发 → 验证 → 评审 → 合需求分支 | 工厂 |
| 4 | 开发中 | 待验收 | 合主干 → 部署 | 工厂 |
| 5 | 待客户验收 | 待验收 | 地址加代码 zip 交给客户，等客户试用 | 客户 |
| B | 已驳回（新开发需求） | 开发中 | 记 `驳回：`，开修复子票；修完接回第 3 步 | 工厂 |
| 6 | 已完成 | 关闭 | 客户点头，关票；要仓库才过户 | 运营者 |

- 内部「待验收」覆盖第 4、5 步。部署完，客户页才从「开发中」跳到「待客户验收」。
- 第 3 步子票可并行。每张走完开发、验证、评审、合需求分支，全部合完才进第 4 步。
- 卡住是旗子，不是档位。可插在第 2、3、4、B 上；触发是同一张票三圈没进展、超额度、碰禁区、验证队和评审修不过、`needs-info`、点火超时。管理视图标出来，客户页只让最后更新时间变旧，不写原因，默认不发消息。
- 改口走 `改口：`，回到 spec 或票，不推消息；跟驳回分开。

## 二、三条消息

只推三条。第 2、3 步合用一条 24 小时提醒。

| 触发 | 谁发 | 通道 | 说什么 |
| --- | --- | --- | --- |
| 校验未通过 | 运营者加服务器 | 微信加邮件 | 缺什么、怎么补，附订单页链接 |
| 部署好，待客户验收 | 运营者加服务器 | 微信加邮件 | 地址、试哪 2 到 3 件事、怎么反馈，附链接 |
| 从上传算满 24 小时还没到待客户验收 | 运营者 | 微信 | 还在做，附链接；只发一条，之后由运营者判断 |

模板：

- 校验未通过：「B 店 · 预约送货：你传的包收到了，还差两样才齐：①… ②…。补好再传一次就行。缺口和进度看这里：<链接>」
- 待客户验收：「B 店 · 预约送货：做好了，可以试了。<链接> 麻烦试这三件事：①… ②… ③…。哪里不对，直接微信说。」
- 满 24 小时：「B 店 · 预约送货：还在安排或开发中，没忘。进度看这里：<链接>」

驳回时不推消息；改好后按「待客户验收」再推一次。

验收不设时限，也不提醒。客户什么时候反馈由客户决定；不反馈，这单就算结束。

## 三、通道

- 微信人工：三条都发；运营者发；以后有客服，照这三条发。
- 邮件自动：服务器发，只发前两条。邮件短，一句加链接，详情在页面。不判断微信是否已读。
- 24 小时那条不发邮件。
- 邮件要 SMTP、发信域名、SPF/DKIM、退信处理，归 to-spec；送达没验。

## 四、进度模块（[#109](https://github.com/Lil-BobCN/grilling-remote/issues/109)）

方向定了，实现归新票。

- 网站有登录态。账号我们建，密码微信发，忘了找客服重设。上传页用登录态认人，不再手填简称和邮箱；教程加一步登录；上传页保留「已问完」和隐私提示。
- 首页或顶部栏放「我的订单」，登录后看自己的单。
- 客户视图：五档进度条，走过的节点打勾、带到达时间，当前高亮。鼠标移上去或点按，展开这一档的细步骤、到达时间、当前小步。客户看到的细步骤用客户话写。
- 管理视图：全部单一行一单，列客户、需求名、当前档、内部细阶段、停留天数、卡住标记、交付地址；带小进度条；只读，点进 GitHub 工单；标「该发消息了」。答闸门、拆票仍在 GitHub 和 Orca。
- 状态来源：调度器每次转档写一句状态，页面读它。只读标签不够。
- 驳回后进度条退回「开发中」，挂「第 2 轮」；上一轮的时间收进「经历」。
- 先出单文件 HTML 样品，至少四屏：登录、订单列表、订单详情、管理列表。详情页放四个状态：正常开发中、校验未通过、待客户验收、驳回后第 2 轮。再写进上传服务需求。
