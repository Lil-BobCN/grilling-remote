# 客户侧流程样本

一句话：把客户侧走 wayfinder 的全过程摆开，配一个水果店样本，看「票的类型」和「票要解决的任务」该在哪一步出现。

状态：2026-11-06 起草，配合 [客户侧 map 的每张票怎么标类型和任务](https://github.com/Lil-BobCN/grilling-remote/issues/55)。是讨论材料，不是结论。

## 一、原技能的口径

wayfinder 原技能只定语义，把物理形态交给追踪器文档。GitHub 和本地 Markdown 是同一套语义的两种写法。

| 原技能说的 | 语义 | GitHub 写法 | 客户侧 Markdown 写法 |
| --- | --- | --- | --- |
| 地图 | 索引，只放五段 | 带 `wayfinder:map` 标签的 issue | `.scratch/{简称}/map.md` |
| 子票 | 一个决定一张 | sub-issue | `issues/NN-*.md` |
| 类型 | 四种之一 | `wayfinder:<type>` 标签 | `Type:` 行（原技能没写，后来补的） |
| 领取 | 一个会话一个人做 | assignee | `Status: claimed` |
| 阻塞 | 挡着的票全关才能做 | 原生 blocked_by | `Blocked by: 01, 02` |
| 可选范围 | 开放、无阻塞、没人领 | 查询 | 扫 `issues/` 目录 |

原技能的三条原话：

- 地图是索引不是仓库，开放票不列在地图上，靠查询子票找（`wayfinder/SKILL.md` 第 30 行）。
- 每张票正文只写 `## Question`（第 60 到 64 行）。
- 类型读标签，不读正文（第 125 行）。

客户侧没有标签、没有查询界面，这三条都被改写成了本地做法。改动写进了 `issue-tracker-local.md`，技能里的原话没跟着改，所以现在两处对不上。

## 二、客户侧现在的流程

走 wayfinder 那一支，从开口到回传。

1. **装配。** 解压技能包，提示词①写 `AGENTS.md`、`docs/agents/`、装八个技能、建 `.scratch/`。
2. **开口。** 客户粘提示词②「开始需求澄清」，或直接说想做的东西。
3. **讲第一段。** 客户装好技能、还没说需求时，Agent 先讲这一段。

   > 我先说说这件事接下来会怎么走。
   >
   > 你先说你想做什么。我会判断这件事是大还是小。小的当场问清楚就完事了，之后会交给开发者；任务量大就需要拆分了，拆分成几个小任务，分几次做。
   >
   > 你可以开始跟我说你模糊的想法了。

4. **客户说需求。** 这段话是判断大还是小的依据。
5. **评估。** 三条全满足才算小需求，缺一条走拆分。拿不准走拆分。
6. **小的话，说一声。** 草稿：

   > 这件事不大，今天就能问清楚。问完我整理成一份需求草稿，交给开发去做。

7. **大的话，讲这一段。** 说完进入澄清：

   > 已经确定需要拆分。
   >
   > 拆的话，第一步是我跟你把它最后要做成什么样定下来。这就是终点。终点是一句话，比如「顾客在微信上看今天的水果、下单、选到店取还是送货，你在后台改价格和库存」。这一句可能要聊一阵，我一次问一件。
   >
   > 我问的问题请你自己答，一定要重视，因为问题和问题之间是有逻辑联系的，一步错，后面全跟着错。
   >
   > 那我们现在开始。我会围绕你刚才说的想法一段一段问，直到把终点定下来。

   **2026-11-06 运营者确认，这一段定稿。** 运营者原话是「使用 grilling 技能对你进行提问」，按乙处理：不说技能名，改成「一段一段问」。`AGENTS-TEMPLATE.md` 第 10 行「对客户不提技能名」保留不动。

8. **定终点。** 用 grilling 把终点问出来，可能跨几轮。终点一句话，客户看得懂。现在这一步和拆议题在同一次对话里做（`wayfinder` 的 Chart the map 第 1 步）。**2026-11-06 运营者定：不单独占对话。** 第一次对话一次走完开口、评估、定终点、拆议题、看清单；之后每次对话解一张票。
9. **讲第二段。** 终点定完、拆议题之前说。

   > 终点定了。接下来我把它拆成一张一张的议题，一张议题代表一个任务。这些任务都做完，你要的东西就做成了。
   >
   > 一张议题就是一次对话，只定这一件事。这张做完，我提醒你新开一个对话，说「继续」，接着下一张。
   >
   > 拆完我把清单给你看：一共几张、每张做什么、按什么顺序做。哪张要先做，你说，我按你说的排。
   >
   > 每张开头会写一句，这次是聊、看个样子、动手做，还是我去查。
   >
   > 这个做法最怕三件事，我提前说：
   >
   > 一，在一张议题里聊另一张的事。想到了就先说一声，我记到那张去，这张先做完。
   >
   > 二，说着说着拐到别处。拐了就拐了，你照说，我记下来，再拉回来。
   >
   > 三，在后面的议题里改前面已经定过的事。要改就说，我去改当初那一张，在地图上记一笔，不在新议题里悄悄改。
   >
   > 进度我写在这个文件夹里，你不用打开，也不用改。想改什么直接跟我说。

   **2026-11-06 运营者确认，这一段定稿。** 拆完给客户看清单，顺序由客户定；类型四个词在这段里说。

   四条规则现在这样分：第 1、4 条进第 7 步那段，第 2、3 条进第二段。原文在 `AGENTS-TEMPLATE.md` 第 58 到 63 行。

   | 条 | 原文 | 落在哪 |
   | --- | --- | --- |
   | 1 | 一次对话只解决一个小问题 | 第 7 步（大的那段） |
   | 2 | 解决完我会提醒你新开一次对话 | 第二段 |
   | 3 | 进度记在 `.scratch/{简称}/`，不要自己改 | 第二段 |
   | 4 | 我提的问题请你自己回答 | 第 7 步（大的那段） |

   **客户会遇到的场景**：

   | 场景 | 会发生什么 | 客户做什么 |
   | --- | --- | --- |
   | 第一次开口 | 先讲怎么走，再请客户说想法 | 说想做什么 |
   | 说完想法 | 判断大还是小；小的说一声，大的进澄清 | 听，接着答 |
   | 定终点 | 一次问一件，可能聊几轮 | 自己答 |
   | 拆成议题 | 存进文件夹，一个议题一个文件 | 不用管 |
   | 每次新对话 | Agent 自动接上，先说走到哪、这次做什么 | 说「继续」 |
   | 中途想起别的事 | 记进文件，先不做 | 说一声 |
   | 想先做后面的 | 说明为什么排在后面；坚持三次就照做 | 坚持就说 |
   | 技术问题答不上 | 给推荐答案，记下来，之后有人确认 | 说「不懂，按你的」 |
   | 这一件做完 | 三句话总结 | 新开对话说「继续」 |
   | 全部做完 | 打包回传（模板还没写，归 #44） | 等我们联系 |

10. **建地图、拆议题。** 写 `.scratch/{简称}/map.md`，六段：Destination 写终点，Notes 记约束，接下来列开放票，Decisions so far 先空着，Not yet specified 放还问不清的，Out of scope 放明确不做的。每个决定一个文件 `issues/NN-任务名.md`，从 01 编号，票头写 `Type:`，有先后就写 `Blocked by:`。拆完把清单给客户看，问一句顺序。
11. **每次会话开头。** 读 `.scratch/`。只有一个目录就读 `map.md`，用三句话说：最后要做什么、现在走到哪、定了几条、下一步是什么。然后只做当前这一步。
12. **选票。** 读地图「接下来」，取第一行没被挡、没人领的。
13. **领取。** 把票头的 `Status:` 改成 `claimed`。
14. **做票。** 按 `Type:` 走：grilling 问客户；research 查资料写 `research/`；prototype 做个单文件 HTML 放 `prototypes/`；task 按清单做。
15. **偏题和跳步。** 偏出去的内容先存成独立文件，再往地图加一行指针。客户想跳步，按跳步规则：说明排在哪、记进地图、回到当前问题；提醒满 3 次照客户做，记一笔。
16. **写结论前查漏。** 用 `subagent_fork` 读这次对话和进度文件，列出该新增、该改、该合并、该删的票，以及客户说过没记下的话。子代理起不来就自己重读一遍。
17. **写结论。** 在票的 `## 结论` 下写答案，`Status:` 改成 `resolved`，把标题和一句结论补进地图的 Decisions so far。
18. **收尾。** 三句话：最后要做什么、这次走到哪、定了什么、下一步是什么。然后提醒客户新开一次对话。
19. **回传。** 全部问完打包上传。这一步还没写进模板，归 [客户包收尾](https://github.com/Lil-BobCN/grilling-remote/issues/44)。

## 三、样本：鲜果铺

客户是一人经营的水果店，想在微信上接单。

工作区长这样：

```
.scratch/xianguopu/
├── map.md
├── issues/
│   ├── 01-顾客怎么看到今天有什么.md
│   ├── 02-下单要不要先付钱.md
│   ├── 03-我在哪改价格和库存.md
│   └── 04-取货了怎么通知顾客.md
├── prototypes/
└── research/
```

`map.md`：

```markdown
## Destination

顾客在微信里看到今天有什么水果，下单，选到店取还是送货。我在后台改价格和库存。

## Notes

- 老板一个人看店，只在手机上用
- 先做老顾客，不接陌生流量
- 取货和送货都要，送货收 5 元

## 接下来

- 03 我在哪改价格和库存 —— 看个样子，我做个原型给你看
- 04 取货了怎么通知顾客 —— 我去查，查完告诉你（等 03 做完）

## Decisions so far

- [01 顾客怎么看到今天有什么](issues/01-顾客怎么看到今天有什么.md)：店里贴二维码，扫进小程序看当天清单

- [02 下单要不要先付钱](issues/02-下单要不要先付钱.md)：到店取的不先付，取货时付；送货的微信转账

## Not yet specified

- 送货范围怎么定，超区怎么办

## Out of scope

- 会员积分
```

`issues/03-我在哪改价格和库存.md`：

```markdown
# 03 我在哪改价格和库存

Type: prototype
Status: claimed
Blocked by: 02

## Question

老板在手机上改价格和库存，改完顾客那边马上能看到。要定的是后台首页长什么样、改一个价格点几下。

## 评论

客户原话：「我早上忙，最好扫一眼就知道哪个卖完了，点两下就改完。」

## 结论

（做完才写）
```

`issues/04-取货了怎么通知顾客.md` 的票头是 `Type: research`、`Blocked by: 03`。

## 四、一次会话的样子

第四次会话，客户说「继续」。

**Agent 开头三句**（`AGENTS.md` 要求）：

> 这件事最后要做到：顾客在微信里看今天的水果，下单，选到店取或送货，你在后台改价格和库存。现在定了 2 条。下一步是 03，要定你在哪改价格和库存。

**选票。** 地图「接下来」第一行是 03，没被挡、没人领，做 03。04 还等 03。

**领取。** 把 03 的 `Status:` 改成 `claimed`。

**开场那句**（本票要定的事）：

> 这张是 03，要定的是你在哪儿改价格和库存。我先做个样子给你看，你看着改。

**做票。** 写 `prototypes/03-后台首页.html`，单文件，客户双击就能开。客户看图说话，Agent 改两轮。

**查漏。** `subagent_fork` 读对话和文件，回一句：04 还挡着；客户提过「下午进的货要能一次改一批」，没记下。

**写结论。** 03 的 `## 结论` 写定下来的东西，`Status:` 改 `resolved`，地图 Decisions so far 加一行。

**收尾。**

> 这件事最后要做成：顾客在微信里看今天的水果，下单，选到店取或送货，你在后台改价格和库存。这次定了 1 条，后台首页的样子。下一步是 04，我去查取货通知怎么发。

> 请新开一次对话，我们接着下一张。

| --- | --- | --- | --- |

## 六、顺序

拆完议题，Agent 把清单给客户看，问一句「哪张要先做」。客户定完，那个顺序写进地图「接下来」的行序，之后不再改。编号只是文件名，不是顺序。

选票规则跟着改：读地图「接下来」，取第一行没被挡、没人领的。

客户中途想换顺序，按跳步规则处理：说明为什么排在这儿、记进地图、回到当前问题；提醒满 3 次就照客户做，记一笔。

## 七、原样本暴露的四件事，现在什么状态

1. 技能说类型在标签里，客户侧没有标签。改成读正文 `Type:` 行，归 #44 改文字。
2. 票模板只有 `## Question`，缺 `Status:`、`Blocked by:`、`## 评论`、`## 结论`。本票给出骨架，归 #44 写进追踪器文档。
3. 地图五段没有开放票。加「接下来」一段，本票定的。
4. 顺序只有编号一条规则。改成地图行序，本票定的。

## 八、两条设计目标

运营者 2026-11-06 原话记在这里，后面改文字时拿它当判据。

- 「用一种更自动化的方式，保姆级的方式，把我们本机这套流程复制到客户侧，让客户和我们达到同样的效果。」判据：客户侧不用懂技能名、不用打命令，Agent 主动接上。
- 「开发者那边要手动输入对应技能才能继续，客户侧不用。」第二段里的「我会自己接上，不用你记命令」就是这句。

## 九、和第二段第三忌有关的一张开放票

第二段第三忌说「我去改当初那一张，在地图上记一笔」。这句话预设了两件事：新旧结论并存要防，防法是回到原议题改、在地图上记。这两件事归 #53「客户侧新旧结论并存怎么防」定。那边定完如果做法不同，这句话要跟着改，不能两处说法打架。
