# 后端服务部署与运维

日期：2026-11-15
状态：占位服务已跑通，真实服务接进来时按最后一节换包。
适用：`afkfactory.dev` 源站。地址和私钥在本地 `private/服务器.md`，不进仓库。

一句话：登录、订单、上传、注册机、邮件共用一个 Node 服务，用独立系统用户跑，只听 `127.0.0.1:8787`，Caddy 把 `/app/api/*` 反代进来。

## 服务单元

| 项 | 值 |
| --- | --- |
| 服务名 | `afkapp` |
| 系统用户 | `afkapp`，`nologin`，不登录 |
| 监听 | `127.0.0.1:8787`，不对公网 |
| systemd 单元 | `/etc/systemd/system/afkapp.service`，开机自启 |
| 程序目录 | `/data/app/current`，软链到 `/data/app/releases/<版本>` |
| 环境文件 | `/etc/afkapp/app.env`，`600 root:root` |
| 数据目录 | `/data/customers`、`/data/uploads`，`700 afkapp:afkapp` |
| 日志 | journald，`journalctl -u afkapp` |
| 对外入口 | 只有 Caddy 的 `/app/api/*` |

D-0166 定了一个 Node 服务，登录、订单、上传同进程。注册机和发信也用这个进程，不另起常驻服务。机器上已有 Node 26，不装第二个运行时。

服务不监听公网。`ufw` 和云安全组不用改，80、443 仍只由 Caddy 用。

## 目录和权限

| 路径 | 属主 | 权限 | 放什么 |
| --- | --- | --- | --- |
| `/data/app` | `root:root` | 755 | 发布根目录 |
| `/data/app/releases/<版本>` | `afkapp:afkapp` | 700 | 一版程序，运行时只读 |
| `/data/app/current` | `root:root` | 软链 | 当前版本 |
| `/data/app/previous` | `root:root` | 软链 | 上一版，回滚用 |
| `/data/app/bin` | `root:root` | 755 | `deploy.sh`、`rollback.sh`、`check.sh` |
| `/data/customers` | `afkapp:afkapp` | 700 | 私有仓 `grilling-customers` 的工作副本，账号、管理员、订单 |
| `/data/uploads` | `afkapp:afkapp` | 700 | 上传件临时目录，导入完成就删，失败留 7 天 |
| `/etc/afkapp` | `root:root` | 750 | 环境文件目录 |
| `/etc/afkapp/app.env` | `root:root` | 600 | 密钥，只有 root 能读 |

`/data/customers` 由服务写，别手改里面的 JSON。订单文件只有一个写入模块负责加锁和原子替换，见 D-0166。

## 密钥

| 密钥 | 放哪 | 干什么 | 怎么换 |
| --- | --- | --- | --- |
| `GITHUB_TOKEN` | `/etc/afkapp/app.env` | 读写私有仓 `grilling-customers` | 在 GitHub 换新 token，改环境文件，`sudo systemctl restart afkapp` |
| `SMTP_PASSWORD` | 同上 | 发提醒邮件 | 在邮件服务商换密码，改环境文件，重启 |
| `SESSION_SECRET` | 同上 | 签 `afk_session` Cookie | `openssl rand -base64 32` 生成新值，改环境文件，重启。换掉会让所有登录态失效 |

规则：

- 密钥不进仓库。仓库里只有 `deploy/backend/app.env.example` 的占位值。
- 环境文件 `600 root:root`。systemd 以 root 读，再把变量交给 `afkapp` 进程。服务用户自己不读这个文件。
- 密钥不要写在命令行里。`ssh ... "TOKEN=..."` 会进 shell 历史和进程列表。

## 一次性安装

要 sudo，运营者跑。

1. 把 `deploy/` 传到服务器：

```bash
tar -C deploy -czf - . | ssh dev@<服务器地址> 'rm -rf /tmp/afk-deploy && mkdir -p /tmp/afk-deploy && tar -xzf - -C /tmp/afk-deploy'
```

这台 Mac 上普通 `scp -r` 可能报 `Connection closed`。用上面的 tar 管道，或者给 `scp` 加 `-O` 传单个文件。

2. 跑安装脚本：

```bash
ssh -t dev@<服务器地址> 'sudo bash /tmp/afk-deploy/backend/install.sh'
```

脚本做五件事：建 `afkapp` 用户；建数据目录和 `/data/app`；写 `/etc/afkapp/app.env`（已存在不覆盖）；装 systemd 单元并把三个运维脚本放到 `/data/app/bin/`；备份旧 Caddyfile，换新的，`caddy validate` 通过后 `reload`。

脚本不启动服务。第一版发布前先填密钥：

```bash
ssh -t dev@<服务器地址> 'sudoedit /etc/afkapp/app.env'
```

填完权限保持 `600 root:root`。没有第一版时 `/app/api/*` 回 502，静态页和下载不受影响。

3. 复核 Caddy 和防火墙：

```bash
ssh -t dev@<服务器地址> 'sudo caddy validate --config /etc/caddy/Caddyfile && sudo systemctl reload caddy'
```

`ufw` 和安全组不用加端口。

## 发布

在开发机打包：

```bash
bash deploy/backend/package.sh deploy/backend/placeholder 0.1.0
```

传上去，在服务器上发布：

```bash
ssh dev@<服务器地址> 'cat > /tmp/afkapp-0.1.0.tgz' < output/afkapp-0.1.0.tgz
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/deploy.sh /tmp/afkapp-0.1.0.tgz 0.1.0'
```

发布脚本做这些：

1. 解包到 `/data/app/releases/<版本>`，属主给 `afkapp`。
2. `/data/app/current` 切到新版本。
3. `systemctl enable afkapp`，`restart`。
4. 轮询健康检查：`/app/api/health` 回 200，`/app/api/session` 回 401。
5. 检查不过就切回上一版，打印服务状态和最近日志，退出码 1。
6. 通过后把旧版本记到 `/data/app/previous`。

版本号不能重复。要重发同一版，先删掉旧目录，或者换个版本号。

## 回滚

```bash
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/rollback.sh'
```

脚本把 `current` 切到 `previous`，重启，跑同一组健康检查。检查不过会切回原版本。回滚成功后，原来的版本记进 `previous`，可以再切回去。

回滚后确认版本：

```bash
curl -s https://afkfactory.dev/app/api/health
```

回的是旧版本的 `version` 才对。

## 巡检

巡检脚本只读，普通用户就能跑。agent 用 `dev` 登录跑；运营者跑 `sudo` 版，能多查证书到期。

```bash
ssh dev@<服务器地址> 'bash /data/app/bin/check.sh'
```

检查项：

| 项 | 通过的样子 |
| --- | --- |
| 进程 | `afkapp` 是 `active` |
| 端口 | `127.0.0.1:8787` 在听，不是 `0.0.0.0` |
| 健康检查 | `/app/api/health` 回 200 |
| 未登录会话 | `/app/api/session` 回 401 |
| 磁盘 | `/` 和 `/data` 低于 90% |
| Caddy | `caddy` 是 `active` |
| 源站证书 | 打印 `notAfter`；没有 sudo 时跳过 |
| 日志 | 过去 24 小时没有 error 级日志 |
| 最近请求 | 打印最后 3 条请求行 |

自动巡检和告警归 I-0047，本文只写手工检查。I-0047 的每日体检脚本还没建；建的时候把 `afkapp` 的 `active`、`127.0.0.1:8787`、`/app/api/health` 200 和 `/app/api/session` 401 加进去。`afkapp` 重启不在免密白名单，要运营者 sudo；当前先用 `check.sh` 手工跑。

失败时先看 `journalctl -u afkapp -n 100 --no-pager`。发布坏了就回滚；磁盘满了先清旧发布和过期上传件；证书问题按 `docs/服务器操作手册.md` 第四节。

## 日志

服务把每个请求写成一行 JSON 到 stdout，journald 收走。字段：`ts`、`request_id`、`method`、`path`、`status`、`ms`，失败时多一个 `msg`。

```bash
# 跟日志
ssh dev@<服务器地址> 'journalctl -u afkapp -f'

# 找一次失败的请求
ssh dev@<服务器地址> 'journalctl -u afkapp --since "1 hour ago" | grep "\"status\":401"'

# 看警告和错误
ssh dev@<服务器地址> 'journalctl -u afkapp --since "24 hours ago" -p warning'
```

日志轮转由 journald 统一管，不使用 logrotate。看占用：

```bash
ssh dev@<服务器地址> 'journalctl --disk-usage'
```

默认上限够用。要改保留量，改 `/etc/systemd/journald.conf` 的 `SystemMaxUse`，这是全局设置，改前先看现状。

日志不记请求体和密钥。真实服务接进来后保持这条。

## 真实服务接进来时要改什么

占位服务在 `deploy/backend/placeholder/`，只证明部署路径。真实服务的代码不在这个仓库，接进来时保持下面这几条：

- 入口仍是 `server.mjs`，监听 `PORT`，默认 8787，只绑 `127.0.0.1`。
- 必须提供 `GET /app/api/health`，不带登录，回 200。
- 未登录访问 `GET /app/api/session` 回 401，和前端 `site/src/api/account.js` 对上。
- 有依赖就在开发机装生产依赖再打包，或在发布包里带 `node_modules`；服务器不跑 `npm install`，发布时没有网也要能装。
- 登录、订单、上传仍在一个进程里（D-0166）。注册机做成同一个服务的入口，或用同一个 `EnvironmentFile` 的 one-off 命令，不新开常驻单元。
- 发信只从服务里发，SMTP 密码从环境变量取。
- 新增端口要另开票，不能绕过 Caddy 直接对外。
