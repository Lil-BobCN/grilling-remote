# 客户澄清启动提示词

客户每次开始澄清时输入一句。规则都在 `AGENTS.md`，提示词只做触发器。

版本：v2，2026-11-05。取代 v1.1。v1.1 把选档、C 档话术和追踪器约定写在提示词里，和 `AGENTS.md` 重复。

## 提示词②

新需求：

```
开始需求澄清。
```

同一需求续做：

```
继续。
```

## 为什么只剩触发语

- `dsh` 在新会话第一次请求时自动注入 `AGENTS.md`。规则写在那里，客户不用记着粘贴。
- 提示词只负责“现在开始”。写多了会和 `AGENTS.md` 重复，改一处漏一处。
- v1.1 的选档、C 档四条规则、追踪器约定已移进 `customer-kit/package/AGENTS-TEMPLATE.md`。

## 使用前提

- 客户工作目录根目录有 `AGENTS.md`。提示词①负责复制。
- `docs/agents/issue-tracker.md` 和 `domain.md` 已装好。
- `grilling`、`domain-modeling`、`wayfinder` 三个技能在 `.dsh/skills/`。
- Agent 要有读写文件的工具。查漏要用 `subagent_fork`。

## 客户侧产出什么

客户侧只落澄清材料，不写 spec。

- 小需求：`.scratch/{简称}/需求草稿.md`。
- 走 `wayfinder`：`.scratch/{简称}/map.md` 和 `issues/`。

运营者拿到材料后自己决策。决策完，运营者调用 `ask-matt` 问能不能 `to-spec`，能就手动跑。调度器不触发 `to-spec`。

## 已知缺口

- 两类分流、跳步、原型、查漏子代理都还没实测，见 #26。
- 上下文压缩后 `AGENTS.md` 的规则还在不在，没测到。
- 客户机上 `subagent_fork` 起不起得来，没测到。起不来时规则要求 Agent 自己重读，不卡住客户。
