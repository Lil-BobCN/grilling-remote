# 客户澄清启动提示词

2026-11-07：按 `docs/客户工作区方案.md` 更新。改了提示词②（取消提示词①，只剩两句）、使用前提、产出路径里的 `{简称}` 和已知缺口，版本升到 v3。

版本：v3，2026-11-07。取代 v2（2026-11-05）。v3 取消提示词①，提示词②只剩两句。v2 取代的 v1.1 把选档、C 档话术和追踪器约定写在提示词里，和 `AGENTS.md` 重复。

## 提示词②

没有提示词①。解压后文件已摆好，第一次打开由 agent 按 `AGENTS.md` 自检。提示词②只剩两句。

第一次：

```
开始需求澄清。
```

之后每次新开对话，复制上一次收尾给的那一行，形如：

```
继续：tanxin-yuyue 01 空档怎么放
```

只发「继续」二字时，由 `next` 选下一张票。

## 为什么只剩触发语

- `dsh` 在新会话第一次请求时自动注入 `AGENTS.md`。规则写在那里，客户不用记着粘贴。
- 提示词只负责“现在开始”。写多了会和 `AGENTS.md` 重复，改一处漏一处。
- v1.1 的选档、C 档四条规则、追踪器约定已移进 `customer-kit/package/AGENTS.md`（原名 `AGENTS-TEMPLATE.md`）。
- 提示词①（装配）取消。文件由工作区 zip 带好，第一次自检写在 `AGENTS.md` 里。

## 使用前提

- 客户工作区根目录有 `AGENTS.md`。zip 解压后就在，不再由提示词①复制。
- 客户多套一层文件夹时，根目录没有 `AGENTS.md`，agent 读不到自检规则。这只能靠官网第 2 步的肉眼检查。
- `docs/agents/issue-tracker.md` 和 `domain.md` 已预生成，在 zip 里。
- 技能都在 `.dsh/skills/`，共九个，含新增的 `next`、`map-gate`、`wrap-up`。
- Agent 要有读写文件的工具。`map-gate` 和 `wrap-up` 要用子代理，起不来时 Agent 自己重读。

## 客户侧产出什么

客户侧只落澄清材料，不写 spec。

- 小需求：`.scratch/{需求名}/需求草稿.md`。
- 走 `wayfinder`：`.scratch/{需求名}/map.md` 和 `issues/`。

运营者拿到材料后自己决策。决策完，运营者调用 `ask-matt` 问能不能 `to-spec`，能就手动跑。调度器不触发 `to-spec`。

## 已知缺口

- 两类分流、跳步、原型、查漏子代理都还没实测，见 #26。
- 上下文压缩后 `AGENTS.md` 的规则还在不在，没测到。
- 客户机上 `subagent` 和 `subagent_fork` 起不起得来，没测到。起不来时规则要求 Agent 自己重读，不卡住客户。
- 第一次自检、三句触发、只发「继续：需求名 编号 票名」能不能接上，都没测到。见方案第十节第 2、3、5 条。
