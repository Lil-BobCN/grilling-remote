### 镜像对比

- 旧镜像 `sandcastle:probe`、`sandcastle:demo-xianguopu`：容器里 `uid=502(agent)`，`/home/agent` 属主 agent，`/etc/passwd` 有 agent。
- 新镜像 `sandcastle:demo-tanxin-yuyue-4-c6a69ec24ed7`：`uid=0(root)`，没有 `/home/agent`，`/etc/passwd` 没有 agent。

旧镜像由 `sandcastle init` 生成，自带用户。新模板 `backend/scaffold/.sandcastle/Dockerfile` 只有 `FROM`、`apt`、`npm`、`WORKDIR`，没有 `useradd` 或 `chown`，传进去的 `AGENT_UID` 也没用。

### 为什么之前没发现

- `docs/research/Sandcastle-本机跑通验证.md`（对应 #8）记过宿主侧同样的 `git config --global --add safe.directory` 报错，绕法是 `GIT_CONFIG_GLOBAL`；文末还写了「自动化里同样要处理这一步的写权限」。
- `docs/工厂流程.md` 记过「docker 整链没跑完」的已知风险。

第三轮演练用的是从 `sandcastle:probe` 派生的镜像，自带 agent 用户，所以容器路径能跑。第四轮用新模板 Dockerfile 现建镜像，第一次真跑整链，第一步就炸。
