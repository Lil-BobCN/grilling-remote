## 结论

1. 内地 4G 能打开 `afkfactory.dev`。两条记录：手机中国联通 4G（江西南昌，2026-11-15 14:27），2 到 3 秒；插卡 4G 路由上的 Mac，HTTP 200，首字节 2.69 秒。能打开，但首字节接近 3 秒，不算快。
2. `upload.afkfactory.dev` 任何网络都打不开。公共 DNS 两个解析器都返回 NXDOMAIN，域名还没上线。固定宽带没测，转 I-0098「内地固定宽带实测：两个域名」。
3. 能打开不等于客户能看到官网。现在根路径返回 3 字节的占位页「ok」，`/download.html`、`/tutorial.html`、`/skills.html` 都是 404。官网内容还没部署。部署不在本票范围，地图执行边界里归 to-spec。
4. 原型页不加保护时能把数据发出去。Chrome 157 和 Firefox 151 都实测过：fetch、XHR、图片、`sendBeacon`、EventSource、外链脚本、iframe、表单、顶层跳转、弹窗都能把 URL 或请求体送到外部服务器。
5. 原型页读不到本地文件（Chrome）。fetch 和 XHR 读 `file://` 被挡，iframe 读不到内容，图片读不了，`window.open` 能打开文件但页面读不到内容。Firefox 正式版没复核。
6. 严格 CSP 挡住大部分外联，但挡不住顶层跳转、顶层表单提交和 `window.open`。`sandbox` 指令写在 meta 里浏览器直接忽略。所以「让模型自己写 CSP」不能当作安全边界。
7. 当前客户包里没有「原型不引网络」的规则，也没有 CSP 要求。票的 Evidence 说 `prototype/UI.md` 有这条，实际文件里找不到。这条按冒头记录，等运营者判。

## 原型页安全实验

实验设置：

- 浏览器：本机 Google Chrome 157.0.8103.51；Playwright 自带的 Firefox 151.0。
- 测试页放在 `/tmp/issue-228-proto-test/`，不提交进仓库。
- 本地接收端 `127.0.0.1:18928` 记录每个到达的请求。请求到达就算外联成功，响应能不能被页面读到另说。
- 三种页面：不加 CSP；严格 CSP（`default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:`）；严格 CSP 加 `sandbox`。

### 外联通道

| 通道 | 不加 CSP | 严格 CSP |
| --- | --- | --- |
| `fetch`（no-cors） | 到达 | 被挡 |
| `fetch`（cors） | 到达，状态 200 | 被挡 |
| `XMLHttpRequest` | 到达，状态 200 | 被挡 |
| 图片 `img.src` | 到达，响应被 ORB 挡 | 被挡 |
| `navigator.sendBeacon`（文本和 Blob） | 到达 | 被挡 |
| WebSocket | 握手请求到达 | 被挡 |
| EventSource | 到达 | 被挡 |
| 外链 `<script src>` | 到达并执行 | 被挡 |
| 外链样式 `<link rel=stylesheet>` | 到达 | 被挡 |
| CSS `background-image` | 到达 | 被挡 |
| `<iframe src>` | 到达 | 被挡 |
| 表单提交到隐藏 iframe | 到达 | 被挡，按 `frame-src` 处理 |
| 表单提交到顶层 | 到达 | 到达，页面跳走 |
| `location.href` 顶层跳转 | 到达 | 到达，页面跳走 |
| `window.open` | 到达 | 到达，弹窗打开 |

严格 CSP 下，`sandbox allow-scripts` 写在 meta 里，Chrome 控制台报「The Content Security Policy directive 'sandbox' is ignored when delivered via a <meta> element」，跳转和弹窗照样通。

### 本地文件读取

测试文件：同目录的 `secret-local.txt`，以及绝对路径 `/etc/hosts`。

| 读取方式 | Chrome 157 | Firefox 151（Playwright 默认） | Firefox 151（`privacy.file_unique_origin=true`） |
| --- | --- | --- | --- |
| `fetch` 同目录文件 | 被挡 | 读到内容 | 被挡 |
| `fetch` `/etc/hosts` | 被挡 | 读到内容 | 被挡 |
| `XMLHttpRequest` 同目录文件 | 被挡 | 读到内容 | 被挡 |
| iframe 读 `contentDocument` | 读不到 | 读到内容 | 读不到 |
| 图片加载 `file://` | 失败 | 失败 | 失败 |
| `window.open` 打开本地文件 | 能打开，打开它的页面读不到内容 | 同上 | 同上 |

Firefox 那一列的差别来自测试设置，不一定是正式版默认值。Playwright 的 Firefox 把 `security.fileuri.strict_origin_policy` 默认设为 `false`（`playwright-core/lib/coreBundle.js:42944`），测试里显式把 `privacy.file_unique_origin` 设为 `true` 后本地文件读取全部被挡。正式版 Firefox 的默认值没复核，见「来源」。

## 来源

浏览器官方文档没查成。2026-11-15 本机 WebSearch 和 WebFetch 都报 403「用户额度不足」，没能复核一手网页。下面把已确认和未复核分开。

已确认（实测或仓库文件）：

- Chrome 157 和 Firefox 151 的外联与文件读取结果见上面两张表。测试页和接收端放在 `/tmp/issue-228-proto-test/`，没提交。
- Playwright 的 Firefox 默认设置：`playwright-core/lib/coreBundle.js:42944` 把 `security.fileuri.strict_origin_policy` 设为 `false`。显式设 `privacy.file_unique_origin=true` 后本地文件读取全部被挡。
- Cloudflare 节点和域名解析：公共 DNS 查询结果，见「内地访问实测」。
- 官网未部署：`deploy/README.md` 写着根路径是临时占位页；这次 curl 的 404 也印证了。

未复核（缺一手网页）：

- 正式版 Firefox 的 `privacy.file_unique_origin` 默认值。已知说法是 Firefox 68 起默认为 `true`，这次没查到 Mozilla 官方文档。
- Safari 的 `file://` 规则。
- Cloudflare 中国网络要求企业版和 ICP 备案的官方原文。仓库 `docs/research/基础设施自动供给.md:49` 有「内地服务器要备案，香港不要」，标的是部分验证。
- `.dev` 在浏览器 HSTS preload 列表里。这条没写进结论，这次没用上。

## 没验证

- 内地固定宽带。转 I-0098。
- 正式版 Firefox 的默认设置（`privacy.file_unique_origin`）和 Safari 的行为。
- Windows 上的 Edge。引擎和 Chrome 相同，但没实测。
- 内地其他网络形态：只测了中国联通 4G 两条，没测电信、移动、家庭宽带、DNS 污染和 SNI 阻断。
- 客户实机上双击打开原型页的默认浏览器，以及页面在真实客户机上的行为。
- 原型页被恶意内容利用的真实案例。实验只测了浏览器允许页面做什么，没有构造完整的攻击链。
