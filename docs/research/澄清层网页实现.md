# 澄清层网页实现

这份文档把 Issue 16 的澄清层收成一份网页契约。网页负责显示和收集答案。网页 agent 负责给题和待查事实。固定组件负责画题、示意图和原型容器。对应的静态交互样本在 `prototype/clarify.html`，可以直接用浏览器打开。

## 一轮题的数据

每轮只返回一个 JSON 对象。模型不返回 Markdown、HTML 或组件代码。

```json
{
  "schema_version": "clarify.v0",
  "round": 1,
  "segment": "business",
  "questions": [
    {
      "id": "Q1",
      "title": "给谁用？",
      "body": "这个页面主要给谁用？",
      "options": ["顾客", "员工", "自己"],
      "recommended": 0,
      "who": "customer",
      "diagram": {
        "type": "comparison",
        "left": { "label": "现在", "items": ["聊天里问"] },
        "right": { "label": "以后", "items": ["打开页面就能看"] }
      }
    }
  ],
  "facts_pending": [
    {
      "id": "F1",
      "claim": "同类店铺通常怎样接预约？",
      "status": "checking",
      "display": "这题我在查，先按其他题继续。"
    }
  ],
  "frontier_empty": false,
  "summary": null
}
```

字段约定如下：

| 字段 | 网页用途 | 约束 |
| --- | --- | --- |
| `round`、`segment` | 顶部进度和段名 | `round` 从 1 开始。段名只用 `business`、`carrier`、`technical`、`scenario`，网页映射为中文 |
| `questions[].id` | 回传答案和定位单题 | 会话内唯一，不能用数组位置代替 |
| `title`、`body` | 题卡标题和人话说明 | 不写技术词。题目只问当前一件事 |
| `options` | 固定选项组件 | 3 到 5 项。网页另外加“我自己说” |
| `recommended` | 推荐答案 | 0 起的数组下标。推荐值含数字时，`body` 必须说明是默认值 |
| `who` | 决定谁要答 | `customer` 客户答，`customer_lean` 客户给倾向、运营者最后定，`operator` 不显示在客户页 |
| `diagram` | 示意图数据 | 只允许 `null`、`flow`、`comparison`、`state`。模型给数据，网页用白名单组件画 |
| `facts_pending` | 待查事实 | 事实由 agent 查，不向客户提问。查询中显示“正在查”，结果回来后更新原题 |
| `frontier_empty`、`summary` | 结束确认 | 待问清单为空时，`questions` 必须为空，`summary` 给 5 到 8 行人话确认单 |

客户没点的题按推荐值继续。客户改了答案，网页只重算受影响的题。过期题保留在历史里，标明“这题因前面的答案变化而作废”。

## 固定组件

| 组件 | 负责什么 | 生成者 |
| --- | --- | --- |
| 题卡 | 题号、标题、正文、选项、推荐标记、自由输入和“看不懂” | 网页，数据来自 JSON |
| 示意图卡 | 流程、对照、状态三种图 | 网页，数据来自 `diagram` 白名单 |
| 待查条 | 显示查询中的事实和当前影响 | 网页，状态来自 agent |
| 重讲卡 | 显示 wait-what 返回的中文重讲 | wait-what 只给文字，网页保留原题和选项 |
| 原型小窗 | 显示单文件原型 | prototype 写文件，网页放入受限 `iframe` |
| 确认单 | 汇总已定、默认和仍待运营者决定的内容 | 网页按模板拼装 |

模型不能生成前端标签、按钮事件、CSS 或 SVG。这样可以避免每一轮输出破坏页面，也能让键盘操作、颜色对比和屏幕阅读器行为保持一致。

## 客户看到什么

| 客户状态 | 网页给什么 | 谁生成 | 等待 |
| --- | --- | --- | --- |
| 看选项 | 题卡、3 到 5 个选项、推荐标记、自由输入 | 网页用 agent JSON 渲染 | 固定组件立即出现。服务器实测首字 2.8–5.7 秒（6 次），整轮 JSON 14.3 秒（1 次） |
| 点“看不懂” | 原题不消失。题卡下方出现背景、换说法、客户业务例子。没有新建议和新问题 | wait-what 生成中文重讲，网页渲染 | 已有服务器实测 13.9 秒（1 次）。还没测网页真实链路 |
| 仍然不懂 | 原题和重讲保留。出现原型小窗，先显示模板骨架，完成后替换成单文件页 | prototype 生成文件，网页负责沙箱 iframe | 模板是本地毫秒级。服务器上写一页原型实测 59.2 秒（1 次），原文版 129.7 秒（1 次）；两次都不是真流式 |
| 题目依赖事实 | 题旁显示“这题我在查”，可继续答不依赖它的题。若是硬前置，则显示“查完后解锁” | 查事实子 agent 更新 `facts_pending` | 目前没有平台实测。要用轮询或推送补一条状态更新 |
| 技术题由运营者定 | 客户页只显示“我给倾向，运营者最后定”，不让客户假装批准 | 网页模板 | 立即显示。运营者处理时间待定 |

首 token（首个流式内容）仍需按网页平台真实路径测。现有数据来自服务器上的 Claude Code 加中转站，只能用于排量级，不能当网页 SLA。

## 示意图怎么画

示意图不是自由绘图。`diagram.type` 只选择一个固定组件：

- `flow`：`{ "type": "flow", "nodes": ["先选时间", "再留手机号", "看到已预约"] }`。网页画节点和箭头。节点最多 4 个。
- `comparison`：`{ "type": "comparison", "left": { "label": "现在", "items": ["聊天里问"] }, "right": { "label": "以后", "items": ["打开页面就能看"] } }`。网页画左右两列。每列最多 4 行。
- `state`：`{ "type": "state", "states": [{ "label": "未提交", "status": "done" }, { "label": "已收到", "status": "current" }, { "label": "已确认", "status": "pending" }] }`。网页画状态条。状态只允许 `done`、`current`、`pending`。

网页用 HTML 和 CSS 画这三类图。节点文字、颜色和连线数量都做长度限制。没有 `diagram` 时不占空白区域，题卡直接收紧。

## “看不懂”规则

wait-what 只重讲上一条消息，不改推荐答案，不增加新问题。中文重讲按四步写：先说这题在问什么，再说为什么现在问；一句话只做一件事；最后给一个客户自己的例子。它不写“你要做什么”，按钮由网页提供“清楚了”和“还是看不懂”。

## 原型页的隔离边界

原型只写入专用目录，前端使用如下容器：

```html
<iframe sandbox="allow-scripts" title="原型预览"></iframe>
```

不加 `allow-same-origin`。页面返回前由平台统一注入内容安全策略：

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:">
```

平台还要在写入前拒绝远程地址、外部脚本、外部样式、表单提交、存储 API 和超出大小上限的文件。CSP 可阻止常见的网络 API 和外部资源加载。沙箱可阻止脚本读取父页面和顶层跳转。

这不能证明恶意页面完全无害。`allow-scripts` 仍会运行原型里的脚本。脚本可能占用 CPU、显示诱导文字，或尝试在小窗内导航。平台需把预览放在独立临时来源，限制出站流量和运行时间，超时后销毁 iframe。内容中的提示注入也不会因 iframe 沙箱而消失，后续 agent 不能把页面文字当可信指令。

## 事实查询和客户本机分流

事实查询由 agent 查，客户只看到状态。查询结果要带来源和时间，回填后再解锁依赖它的题。

2026-11-04 已定客户本机分流规则：

| 情况 | 网页动作 |
| --- | --- | --- |
| 多数单不碰客户电脑 | 全部在服务器完成 |
| 只取信息 | 一步一屏网页指引，加上传入口 |
| 要长期运行在客户机器上 | 转人工确认环境和授权 |

## 一次真实调用记录

2026-11-04 在本机运行 Claude Code 2.1.316，`--no-session-persistence`、`--model haiku`，请求只返回一轮 JSON。客户端事件报告实际模型为 `claude-opus-5-5`，本机模型覆盖没有按指定别名执行。

| 指标 | 结果 |
| --- | ---: |
| 首个内容帧 | 3,668 ms |
| CLI 进程总时长 | 11,846 ms |
| 模型结果时长 | 8,908 ms |
| 输出 token | 159 |
| 思考 token | 103 |
| 报告费用 | $0.042823 |
| 请求失败次数 | 0 |

第一次命令少了 `--verbose`，CLI 在发请求前拒绝了参数，计为一次命令配置错误，不计入模型失败。成功返回后另有 SessionEnd hook 配置错误，CLI 仍以 0 退出码结束。这个调用不是网页平台真实路径，不能替代浏览器端 TTFT 和真流式测试。

`prototype/clarify.html` 里的按钮只切换静态示例，不会发模型请求。它用于看客户页面怎样变化，不是网页后端的实测。
