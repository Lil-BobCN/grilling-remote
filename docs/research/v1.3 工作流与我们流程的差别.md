# v1.3 工作流和我们这套流程，差在哪

> **2026-11-02 已改。** 仓库的词汇表按上游改成 `GLOSSARY.md`，多上下文用 `GLOSSARY-MAP.md`。本文凡是以「仓库还写 CONTEXT.md」为前提的结论，前提已不成立。现行写法见 `AGENTS.md` 和 `docs/agents/domain.md`。

一句话：视频是「一个开发者，在自己的仓库里，让 agent 跑完一份 spec」。我们是「不懂技术的客户在网页上说需求，一台 Mac 上的调度器把单子推到合并」。整条链能对上的只有中段，两头都换了人。

视频原文整理在 [Matt Pocock v1.3 工作流](<../../素材/口播提取/Matt Pocock v1.3 工作流：implement-spec、pr、retro.md>)。你这边的介入点单独写在 [介入点](../介入点.md)。

## 三处结构性差别

### 一、循环在 agent 里，还是在 agent 外

这是最大的一处。

视频里跑票的是 implement-spec：一个编排 agent 坐着，看所有票，派 sub agent 去实现，收回来，合并，再派下一批。循环长在这个会话里。作者自己说，这比确定性脚本差，因为每次跑法不一样。他把脚本留给「软件工厂已经调好的人」。

我们就是那个工厂。调度器在 agent 外面，每 30 秒读一遍工单，找该动没动的。好处很实在：电脑重启接得上，同一个活不会干两遍，出问题能问一句「它为什么觉得这张单不该动」。

代价也有。视频里的编排 agent 在同一个会话里，看到问题可以当场改主意；这一点视频没细讲，是它的结构决定的。我们的调度器只会看状态，遇到没预料到的情况只能停或者重试。所以 #6 那个岔口要人来点头，判错要能改道。

换句话说，我们用调度器替掉了 implement-spec 的编排角色。票还是逐张实现，但谁先谁后、什么时候派下一张，由状态决定，不由会话里的模型决定。

### 二、人看 PR，还是人看成品

视频把 PR 当主要瓶颈，整节 /pr 技能都在解决「怎么让人看得快一点」。四栏是摘要、证据、单向门还是双向门、影响范围。

我们把这一步推平了：四样证据齐了就自动合，你只在验收时看截图和改动摘要。省掉的是你逐行读 diff，风险是你看不到「这一改有多险」。

单向门 / 双向门这个判断，我们其实有对应物。#11 的禁区判据是「能不能验证、能不能回滚」，几乎就是同一件事。区别在用法：视频拿它写给人看，我们拿它决定停不停。前者是信息，后者是闸门。

结果是，我们的闸门比视频严，但信息比视频少。过了闸门的改动，你验收时手里只有截图和测试结果。

### 三、单子从哪来：视频不管这一步

视频开场就说 spec 和 tickets 是两个实体，然后直接讲怎么跑票。spec 从哪来，它默认已经有了，而且是懂技术的人写的。

我们的前半段它整段没有：三段问、双手机预览、五道技术闸门、24 小时提醒。原因是客户不懂技术，而且这套东西要多客户复用，要花钱、要合规、要能回滚。

## 为什么会长成这样

三个原因，按影响大小排。

**客户不懂技术。** 所以 spec 不能让他写，票不能让他批，PR 不能让他读。他只能做两件事：说清要什么，看成品对不对。中间全要换成机器能执行的形式。

**一对多。** 视频是一个人一个仓库；我们是一个运营者对着多个客户、多张单、多个容器。所以有了调度器、一客户一仓、账单、合规闸门。视频里这些都不存在，因为成本算在开发者自己头上。

**要无人值守。** 视频的 AFK 是「你走开一会儿，它跑完一份 spec」。我们的 AFK 是「你睡觉，它别把东西弄坏」。所以有了三圈上限、额度、禁区、两次失败叫人、夜间白名单。视频对失败的处理只有一条：retro 事后回看。

## 我们比视频多做的

- 澄清层。视频没有对应结构。
- 开工前的五道闸门。视频默认技术选择已经定了。
- 多客户隔离和账单。
- 崩溃恢复。状态在工单里，不在会话里。
- 中途改道。干到一半发现判错，已经写的代码保留。
- 停法。三圈、额度、禁区、两次失败。

## 视频比我们多做的

- retro 真在跑。我们只在原型里挂了一个条件触发的标签。
- 证据要求到「before / after 一对」。我们只要求「有截图或 trace」，没说必须一前一后。
- PR 正文有风险判断。我们没这一栏。
- 词汇表改名 GLOSSARY.md。我们仓库还写 CONTEXT.md。

最后一条要留意。v1.3 之后，/domain-modeling 找的是 glossary.md。我们的 AGENTS.md 和 `docs/agents/domain.md` 还按 CONTEXT.md 配。装新版技能，这条会对不上。

## 三条可以借的

一，PR 正文加两栏：单向门还是双向门、影响范围。不改变自动合的规则，只是让你在验收页一眼看到风险。#11 已经定了判据，这里只是换个写法。

二，截图改成一对：改之前一张，改之后一张。视频的理由比我们硬：证行为变了，不是证页面能开。

三，retro 定成抽样任务：一周挑三个会话，人看报告，只改工厂自己的指令，不动客户那张单。视频明确反对自动化，理由是假阳性会自我放大。这条和我们 #12 的停法是一个方向。

这三条都要动已经定好的东西，等你点头。
