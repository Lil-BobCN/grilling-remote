# 微信通知通道选型

> 调研时间：2026-11-01。价格、额度、限频都从官方文档现抓，正文里给出链接；拿不准的写在「待确认事项」。
> 结论先行：**默认用 Server酱 Turbo 的微信服务号通道**，3 分钟能收到第一条；**备选是企业微信自建应用 + 微信插件**，免费、官方、额度大，但要多花 20 分钟；**兜底用邮件**，iPhone 再加一条 Bark。

## 结论（默认 / 备选 / 第一步）

### 谁最适合这个项目

这个项目的通知有三个特点：事件稀疏（一个需求 2～3 条）、必须进微信、没人盯着服务器。所以选型的第一权重是**到得了、看得见**，第二才是额度。

**Server酱 Turbo 最适合做默认**，理由只有三条：

1. 从零到收到第一条是 3 步：微信扫码登录 → 复制 SendKey → 发一个 HTTP 请求。不需要注册企业、不需要实名材料、不需要装 App。
2. 消息直接落在微信会话里（方糖服务号），是真正意义的「推到微信」，不是「推到某个 App 再让你去装它」。
3. 同一个 SendKey 可以在控制台切换落点：企微应用消息、企微/钉钉/飞书群机器人、Bark、自定义 Webhook（PushDeer 通道虽然还在，但 PushDeer 本身已停更，别指望它）。以后微信这条路出问题，改配置不改代码。

**代价要提前知道**：

- 免费会员每天 **5 条**，会员每天 1000 条。按「每个需求 3 条事件」算，免费额度只够每天 1.6 个需求，稍一上量就见底。
- 免费版微信服务号卡片**只显示标题**；会员在其他通道能显示标题和内容，但官方把服务号通道单独排除在外，理由是「该通道展开内容易被举报」。所以**标题必须自带信息量**。
- 是第三方托管。微信模板消息的政策历史上调整过（Server酱自己的对比页也承认这一点），这是选它而不是直连某个通道的主要风险，也是它用「统一入口」来对冲的东西。

**备选（也是长期方案）：企业微信自建应用 + 微信插件。** 免费、腾讯官方、内容完整、额度是「同一成员 30 次/分钟、1000 次/小时」，个人用完全够。代价是要注册企业微信（创建时要求微信实名，部分情况要绑中国大陆银行卡）、建自建应用、拿 corpid/secret/agentid、再让运营者关注「微信插件」并打开「接收应用消息」，一共 6 步左右。**如果已经有企业微信，别绕 Server酱，直接用它。**

**兜底：邮件。** 不依赖微信生态，作为第二通道；出问题时至少还有一条独立的路。

### 第一步：今天就能收到消息

1. 手机微信扫码登录 <https://sct.ftqq.com>，在「SendKey」页复制 `SCT` 开头的 key。
2. 终端跑一条：

   ```bash
   curl -X POST "https://sctapi.ftqq.com/你的SENDKEY.send" \
     -d "title=【测试】通知链路已通" \
     -d "desp=如果你在微信里看到这条，第一步就完成了。"
   ```

   返回 JSON 里 `code` 为 `0`，并且微信收到，即成功。
3. key 放进 `.env` 或系统钥匙串，确认 `.gitignore` 覆盖它，**不要提交**。
4. 代码里先只接两条事件：**进队列**、**完成**。「开始开发」先写本地日志——省额度，也避免一次需求刷三条。
5. 加失败兜底：`code` 非 0、HTTP 超时、429 都算失败，重试 3 次后写日志并发邮件。

### 什么时候把默认换掉

| 情况 | 选择 |
| --- | --- |
| 想当天就有通知，不想折腾 | Server酱 Turbo（免费额度先跑） |
| 每天事件稳定超过 5 条，又不想付费 | 企业微信自建应用 + 微信插件 |
| 已经有企业微信，或愿意花 20 分钟配置 | 企业微信自建应用 + 微信插件 |
| 运营者用 iPhone，想再加一层保险 | Server酱 主 + Bark 备（双通道） |
| 需求内容敏感，不能经过第三方推送服务 | 自建（Bark server / ntfy）+ 邮件，通知里只放需求 ID |

### 通知内容怎么设计

不管选哪条通道，推送里**只放这三样**：需求编号、需求标题、当前状态。客户名、联系方式、需求正文都不放。原因有两个：微信服务号卡片本来就只显示标题；而且推送内容会在第三方服务器上留 1～7 天（Server酱 免费 1 天、会员 3 天；WxPusher 7 天）。

标题示例：`【新需求 #12】小程序不能登录`、`【完成 #12】耗时 23 分钟`。

## 逐个通道的细节

### 1. Server酱（SCT / SC3 是两条产品线）

**能不能用。** 能。Turbo（SCT，`sct.ftqq.com`）主打「推到微信」，文档 2026-07 更新；Server酱³（SC3，`sc3.ft07.com`）是另一条线，推独立 App、接手机厂商系统通道，两者用户和 SendKey 不通用（[通道对比](https://sct.ftqq.com/docs/getting-started/channels/)）。

**额度与价格。** 免费会员每天 5 条，新用户送 7 天全功能试用；会员每天 1000 条，8 元/1 个月、39 元/12 个月、180 元/60 个月，企业版 720 元/60 个月。每分钟最多 50 条，免费与会员一样。不自动续费、不退款，官方建议先用试用期测（[FAQ](https://sct.ftqq.com/docs/getting-started/faq/)）。另有按 IP 的 24 小时调用上限，超了返回 429。

**实名/企业主体。** 不需要。注册就是微信扫码登录，SendKey 页直接复制，不必提交身份证或营业执照（[30 秒获取 SendKey](https://sct.ftqq.com/docs/getting-started/sendkey/)）。

**延迟。** 经验上秒级到十几秒；微信端偶尔会因为消息折叠看起来「晚到」，不是接口慢。

**接入步数。** 3 步：

1. 微信扫码登录 <https://sct.ftqq.com>；
2. 复制 `SCT` 开头的 SendKey；
3. `POST https://sctapi.ftqq.com/<SendKey>.send`，`title` 必填且不能有换行，`desp` 支持 Markdown（不支持 HTML）。

**坑。** ① 免费版服务号卡片只显示标题，会员也只有标题（服务号通道被单独排除），所以标题要能独立看懂。② 免费 5 条/天按「每次 API 请求」计数，失败也计。③ 推送内容免费保留 1 天、会员 3 天。④ 微信端如果取关或屏蔽了服务号，接口仍可能返回成功但收不到；排查时必须看控制台推送日志，不能只看 API 返回值（FAQ 的排查顺序）。

### 2. WxPusher

**能不能用。** 能，但定位变了。官方文档写明：早期以微信公众号为主要触达通道，**当前主推独立全平台客户端**（安卓厂商通道、APNs、鸿蒙 Push Kit、桌面端长连接），微信侧改成 **ClawBot（iLink）补充渠道**（[官方文档](https://wxpusher.zjiecode.com/docs/)）。

**额度与价格。** 免费。接口限制：content 最多 4 万字符且不超过 65535 字节；单次最多 2000 个 UID、5 个 Topic；约 2 QPS；单个 UID 走客户端渠道单日约 3000 条后通知栏不提醒、约 2 万条后停止展示（[限制说明](https://wxpusher.zjiecode.com/docs/#/?id=limit)）。

**微信侧的关键限制。** 微信 ClawBot 渠道：用户激活后 **24 小时内最多收 10 条**，用尽后要用户**在微信里向 ClawBot 回复任意内容**才能再次激活。这个「人工续期」直接决定它不适合无人值守的稳定提醒——某天没回复，通知就静默断了。

**实名/企业主体。** 文档没有提实名要求，扫码即注册；但后台创建应用时是否要实名**没有读到明确说明**，列为待确认。

**延迟。** 秒级。

**接入步数。** 4 步：微信扫码登录管理后台（首次扫码自动注册）→ 创建应用拿 `appToken` → 让接收者关注应用/绑定客户端拿 `UID`（或者用不需要注册的 SPT 极简推送）→ `POST /api/send/message`。凭证：`appToken` + `UID`，或 `SPT_` 开头的极简 token（[SPT 文档](https://wxpusher.zjiecode.com/docs/spt.html)）。

**结论。** 免费、能多端，但「进微信」这条通道被加了 10 条/24 小时 + 手动激活的闸门，不适合当默认。如果运营者愿意装 App，它的客户端通道本身不错，可以当第二通道。

### 3. 企业微信群机器人（现在叫「消息推送」）

**能不能用。** 能。官方文档 2025-08 更新，产品名已从「群机器人」改成「消息推送（原群机器人）」（[文档](https://developer.work.weixin.qq.com/document/path/91770)）。

**额度与价格。** 免费；每个消息推送 **最多 20 条/分钟**。支持 text、markdown、markdown_v2、image、news、file、voice、template_card 八种消息。

**实名/企业主体。** 需要企业微信账号；创建企业微信时要求创建者微信已实名并绑定中国大陆银行卡（[注册帮助](https://open.work.weixin.qq.com/help2/pc/15422)）。纯个人用手机号注册的账号没有 Web 管理后台（[腾讯客服](https://kf.qq.com/touch/faq/170207FrmyMV170207neUVrE.html?platform=14)），建应用这类操作要走官网注册的「企业/团队」。

**延迟。** 秒级。

**接入步数。** 4 步：注册企微 → 建一个内部群 → 群设置里添加「消息推送」机器人 → 复制 webhook，`POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`。凭证只有 webhook 里的 key（官方特别提醒别泄漏，泄漏了谁都能往群里发消息）。

**关键缺陷。** 它只落在**企业微信群**，不进微信。想进微信得用「应用消息 + 微信插件」，见下一条。

### 4. 企业微信自建应用 + 微信插件

**能不能用。** 能。应用消息接口在维护（[发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)），微信插件的帮助文档也还在帮助中心里（[如何接收微信插件消息](https://open.work.weixin.qq.com/help2/pc/18121)）。

**额度与价格。** 免费。限制：每应用不超过「账号上限数×200」人次/天；**每应用对同一个成员不超过 30 次/分钟、1000 次/小时**，超出的部分直接丢弃不下发。官方还建议避开整点和半点调用（大家都在那个时间推）。

**实名/企业主体。** 要注册企业微信，创建时要求创建者微信已实名，部分情况还要求先绑中国大陆银行卡。企业认证（营业执照）是否是建自建应用的前置，没在文档里读到明确要求，列**待确认**。

**到微信的机制。** 成员关注「微信插件」后，**应用消息和会话消息可以在微信里收到**。要同时满足：微信插件里打开「接收应用消息」；应用没被停用；管理后台不能勾「成员需使用企业微信客户端」；不能勾「仅在企业微信中接收」（[帮助](https://open.work.weixin.qq.com/help2/pc/18121)、[消息同步说明](https://open.work.weixin.qq.com/help2/pc/14797)）。

**延迟。** 秒级。

**接入步数。** 6 步：

1. 注册企业微信（微信实名，部分情况要先绑卡）；
2. 管理后台 → 应用管理 → 自建 → 创建应用，记下 `AgentId`；
3. 「我的企业」拿 `CorpID`，应用详情页拿 `Secret`；
4. 设置应用可见范围，把运营者加进去；
5. 运营者用微信扫码关注「微信插件」，打开「接收应用消息」；
6. 服务端 `GET /cgi-bin/gettoken` 拿 access_token（[文档](https://developer.work.weixin.qq.com/document/path/91039)），再 `POST /cgi-bin/message/send`。

**结论。** 这是「免费 + 官方 + 额度够 + 内容完整 + 能进微信」的唯一组合。缺点全在配置：6 步、注册可能要绑卡、微信插件有几个开关容易漏。一次性配完，长期最省心。

### 5. Bark（iOS）

**能不能用。** 能。依赖苹果 APNs，开源可自建，官方写明「至少维持运营到 2031 年 7 月，期间不会有收费功能与广告」（[官网](https://bark.day.app/#/)）。

**额度与价格。** 免费。

**实名/企业主体。** 不需要，装 App 就有 key。

**延迟。** 秒级，APNs 系统级推送，App 不用在后台跑；支持时效性通知、关键警报。

**接入步数。** 3 步：App Store 装 Bark → 复制测试 URL 里的 key → `GET https://api.day.app/<key>/<标题>/<正文>`。凭证就是 device key。

**限制。** 只有 iOS。Android 用不了。自建服务器（[bark-server](https://github.com/Finb/bark-server)）可以完全掌握数据，但要自己运维——推送服务自己挂了，它没法通知你它挂了。

### 6. 飞书自定义机器人

**能不能用。** 能，官方文档在维护（[自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)）。

**额度/价格。** 免费；单租户单机器人 **100 次/分钟、5 次/秒**。

**实名/企业主体。** 需要飞书账号和群；不需要企业认证。

**接入步数。** 3 步：建群 → 群设置添加「自定义机器人」→ 复制 webhook 发 POST。凭证是 webhook，可选签名校验。

**结论。** 好通道，但不进微信，而且运营者得多装一个飞书。只在「本来就常用飞书」时选它。

### 7. PushDeer：不用再考虑了

官方 README 写得很直接：Android 官方版因接口权限问题「停止无法使用」，项目**已不在维护**，客户端和 API 都不再增加新功能，并建议改用 Server酱³（[README](https://github.com/easychen/pushdeer)）。官方 API 服务器还在跑，但没有维护承诺，不适合做「稳定通知」的地基。

### 8. 息知：状态待确认

官网旧域名 `xizhi.qqoq.net` 现在只剩一句「official website: xz.qqoq.net」，新域名是纯 JS 壳。本机 DNS 把 `xz.qqoq.net` 解析到 `198.18.0.212`（保留地址），**没能读到官网原文**，所以额度、限频、微信落点都只能引用二手资料：免费、无数量限制计划、30 条/分钟、微信卡片只显示标题（[第三方接入指南](https://github.com/magiccode1412/magicpush)）。

结论：不作为默认；要用就自己先注册发一条验证，别把它写进关键路径。

### 9. Telegram：技术上最顺，网络上最不顺

Bot API 免费且成熟（[官方文档](https://core.telegram.org/bots/api)，2026-08 更新到 10.3）。接入 3 步：@BotFather 建 bot 拿 token、取 chat_id、POST `sendMessage`。但中国大陆网络直连 `api.telegram.org` 通常不可用，要挂代理或中转——等于在通知链路上再加一个可能挂掉的环节。不适合做「稳定推到手机」的主力。

### 10. 邮件：兜底，不是主力

SMTP 最简单：一个邮箱账号 + 授权码，2 步。延迟秒级到分钟级，缺点是被扔进垃圾箱、手机通知取决于邮箱 App 的设置。它的价值在于**独立于微信生态**：微信通道整体出问题时，邮件是另一条路。

建议的兜底逻辑：

1. 每次推送记录 `event_id / 通道 / HTTP 状态 / 业务 code / 时间`；
2. 业务 code 非 0、超时、429 → 指数退避重试 3 次；
3. 仍失败 → 发邮件，同时写本地日志；
4. 每天固定时间发一条心跳；没收到就是链路坏了（心跳建议走邮件或会员额度，别占用免费 5 条）；
5. 用 `event_id` 去重，避免重试把同一条通知发两遍。
