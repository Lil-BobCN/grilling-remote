## 步骤与卡点

### 1. 分支对基

- 现象：worktree 建在了 `main`（`afebc6e`），不是约定的 `8da011e`，分支里没有 `factory/`。
- 根因：新建 worktree 时没指定基点。

- 影响：无。演练必须和线上 `rc.4` 同码。

### 2. 回传件到 Mac inbox

- 谁跑的：Agent 手动跑 `factory/bin/pull-inbox.mjs`。
- 现象：这一步没有自动触发。
- 证据：
  - `docs/工厂流程.md:58`：「Mac 拉一份存档，交付后删。」
  - `docs/工厂流程.md:196`：「服务器校验，自动建单、建仓；Mac 拉存档。」
  - `docs/后端服务.md:441`：「Mac 拉取桥：已做……导入后服务器保留快照，等 Mac 桥拉走存档再删远端。」
  - spec #456:195：「长期存档在 Mac。」spec #456:229 还把「Mac 拉取桥」列在「还没实现」。
- 根因：设计了组件和存档位置，没设计触发方式。服务器侧导入有 `afk-import.timer`，Mac 侧没有对应定时器。
- 现状：本机 `~/Library/LaunchAgents` 只有 `backup-sync` 和 `product-probe`。

### 3. 补缺口 Agent

- 谁跑的：Agent 手动跑 `factory/bin/gap.mjs apply-map`、`propose`。
- 现象：调度器没有启动补缺口 Agent。
- 证据：
  - `docs/工厂流程.md:118`：「父工单是 `状态:已提交`，闸门没答 → 启动补缺口 Agent 列闸门，推给你。」
  - `factory/lib/scheduler.mjs:351`：`已提交` 只等 `点头：补缺口`，没有启动动作。
  - `factory/lib/scheduler-jobs.mjs`：只有 `createDecompose`（拆票），没有补缺口 job。
  - spec #456:168 的路由表关键分支没有「已提交、闸门没答 → 启动补缺口」这一支。
- 根因：工厂流程写了，spec 路由表漏了，实现照 spec 写。

### 4. 网络与模型（环境，不是产品缺陷）

- Node 访问 GitHub 一律失败，报 TLS 断开。根因：默认 DNS 先解析到 IPv6 假地址。加 `NODE_OPTIONS=--dns-result-order=ipv4first` 后可稳定访问。
- Clash 节点频繁掉线。选中的节点几分钟就失效。处理：写了一个脚本，按 api.github.com 的延迟测试挑节点；演练期间多次手动切换。
- `claude -p --restricted` 用默认模型名（大写 `[1M]`）返回 403 额度不足。显式 `ANTHROPIC_MODEL='ccs-claude-deepseek--deepseek-v4-flash[1m]'`（小写）可跑。
- 以上都是本机环境问题，和工厂设计无关。运营者已知服务商当天有部分中断。
