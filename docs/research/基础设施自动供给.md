# 基础设施自动供给

> 调研时间：2026-11-03。对应议题 #17，样本是已关闭的 #7。
> 口径：只采信厂商官方文档、官方 Terraform provider（基础设施描述工具的厂商插件）文档和官方手册。读不到的写「未验证」。
> 边界：只读资料。没有买东西，没有建云资源，没有调用需要凭据的接口。服务器地址、域名、账号标识、令牌都不写在这里。

## 运营者的决定（2026-11-03）

买服务器、买域名、登录与授权，三步都由运营者自己做。客户不做，agent（自动干活的程序）也不自动买。

做法：问卷问完客户后，运营者通过网站的沟通渠道联系客户，再自己采购。

| 受影响的内容 | 变化 |
|---|---|
| 步骤 1、2、3 | 下文写的「人只做一次」，指运营者做一次。不再设计让客户或 agent 来做 |
| 额度线和白名单动作 | 暂时不用定。agent 不碰付款 |
| 买域名算不算禁区 | 暂时不用定。购买由运营者亲手执行 |
| 步骤 4、5、6 | 没定。它们是服务器买好之后的配置，不涉及付款。要不要交给 agent，运营者另定 |

这条决定和 #10 一致：要花钱的事归运营者定。下文的调研内容不改，只当作运营者手动采购和配置时的参考。

## 结论

六步里，3 步能全自动，3 步人只做一次，没有哪一步必须每次都要人。

这个结论有四个前提。前两个没验证，后两个要运营者定。

1. 厂商要有接口。腾讯云、阿里云、Hetzner、DigitalOcean、Lightsail 读到了官方文档。#7 的厂商是朝晞云，两次搜索没找到它的官网和接口文档。**未验证。**
2. Cloudflare 注册接口要什么令牌权限，没查清。接口指南写「Registrar 写权限」，官方权限清单里没有这个权限组。账号级令牌的兼容表还把 Registrar 标成不支持。**未验证。**
3. 域名注册后不可退款。`docs/工厂流程.md` 的禁区判据是「出事了能不能回滚」。按这条，买域名属于禁区，要运营者定规矩。
4. 免密 sudo 和预置主机密钥都做得到，但各有安全代价，要运营者先选。

| 步骤 | 结论 | 人要做什么 | 验证状态 |
|---|---|---|---|
| 1 买服务器 | 人只做一次 | 开户、实名、绑付款方式或充值、建令牌。之后建机全自动 | 部分验证。朝晞云、限额手段未验证 |
| 2 买域名 | 人只做一次 | 控制台设默认注册人、同意注册协议、绑付款、建令牌。之后查价和注册全自动 | 部分验证。令牌权限、.cn 未验证 |
| 3 登录与授权 | 人只做一次 | 每个账号点一次授权。新增权限要再点 | 部分验证。厂商令牌范围、授权有效期未验证 |
| 4 配安全组 | 全自动 | 无 | 部分验证。朝晞云未验证 |
| 5 sudo 密码 | 全自动 | 无，但要运营者先放宽规矩 | 部分验证。规矩出处、朝晞云镜像未验证 |
| 6 核对主机指纹 | 全自动 | 无，但要运营者先选信任方式 | 部分验证。从控制台读指纹未验证 |

「部分验证」指 Cloudflare 或主流厂商读到了一手来源，朝晞云没有。

## 逐步细节

### 1 买服务器：人只做一次

**人做一次。** 开户、实名、绑付款方式或充值、建令牌。阿里云的创建接口把「账号已实名」和「数量在配额内」列为前提。这些在文档里都是控制台操作。

**之后全自动。** 五家厂商都有创建接口，建机时都能带初始化数据，见上表。

**花钱的上限，文档没有现成手段。** 腾讯云和阿里云的创建接口，都要求调用前账户余额充足。腾讯云写明，按小时付费的实例会先冻结一小时的费用。合理推测：账户只放小额余额，余额不够时创建会失败，等于一道硬上限。依据只有这两处原文。余额用完后已有机器会怎样，没读到。Cloudflare 注册接口直接扣默认付款方式，文档没提额度。限额付款方式也没有官方文档。这些都未验证。

**朝晞云。** 本地文档只记了规格和月付，没有接口信息。两次搜索没有结果。能下的结论只有「没找到」。

### 2 买域名：人只做一次

Cloudflare 注册接口是测试版（beta），指南更新于 2026-09-16。

| 接口 | 作用 | 要点 |
|---|---|---|
| domain-search | 按关键词找候选 | 用缓存数据，只含接口支持的后缀。官方说不要只凭它做购买决定 |
| domain-check | 实时查能否注册和价格 | 直连注册局。一次最多 20 个。官方要求注册前紧接着调用 |
| registrations（创建） | 注册域名 | 扣默认付款方式。完成后不可退款。auto_renew 默认关。溢价域名不支持 |

**人做一次，只能在控制台做。** 绑付款方式。设默认注册人联系信息。同意域名注册协议。官方原文：控制台设置是目前管理这些联系信息的唯一方式。

**之后全自动。** 几个官方细节：

- 单个账号最多 500 个域名。这是读到的唯一硬上限。
- 同一域名只能注册一次。官方说域名本身就是幂等键（重复调用结果相同），所以失败重试不会买两次。
- 返回 201 表示已完成，202 表示还在处理，要轮询状态地址。

**后缀支持，两处原文冲突。** 指南的限制一节说只有一部分后缀可用。接口描述文件说，除 giving、mom、inc、lol、sh、link、cc、new 外，控制台支持的后缀都能用。指南里还留着「此处补后缀清单链接」的占位语，合理推测指南已过时。运行时以 `GET /accounts/{account_id}/registrar/extensions` 和 domain-check 返回的 reason 为准。

**注册人邮箱验证，可能变成每个域名都要人。** ICANN（互联网域名管理机构）要求验证注册人邮箱。15 天内没验证，注册局会加锁，域名服务器被换成停放服务器，网站停止解析。官方写明触发条件：注册人邮箱与已验证的账号邮箱不同。合理推测：默认注册人用账号邮箱，就不会触发。这一点没做实验验证。

**令牌权限，未验证。** 四处原文互相对不上：

- 指南前提写「带 Registrar 写权限的 API 令牌」。
- 权限清单页（更新于 2026-10-30）里，没有名字含 Registrar、Registration、Domains 的权限组。
- 账号级令牌页的兼容表写「Registrar：❌」。
- 创建注册的接口参考页没写所需权限。接口描述文件里，注册相关接口也没有权限标注，而 DNS 创建接口标的是 DNS Write。

权限清单页说，实时清单可用「列出权限组」接口取。它需要令牌，本次没调用。

**沙箱，未验证。** 接口描述文件里有一套平行的 registrar-sandbox（沙箱，测试环境）接口。它的创建描述里没有扣费和付款方式的前提。没有文档页说明它是否免费，所以不能当作安全。

### 3 登录与授权：人只做一次

**令牌可以按范围建。** 创建页说，可选 Client IP Address Filtering（限定来源 IP）和 TTL（有效期）。权限可以限定到单个区域。令牌密文只显示一次。账号级令牌要有令牌管理权限或超级管理员才能建，只能授予自己权限的子集。

**授权协议（OAuth）路线。** 连 Cloudflare 的 MCP 服务时，会跳到 Cloudflare 授权并选权限。2026-10-19 起支持分步授权。先选「Minimal」，之后工具缺权限时，服务器返回 insufficient_scope 提示，客户端请人再点同意。所以每新增一类权限，要人点一次。Cloudflare 对第三方 OAuth 客户端只支持授权码流程，不支持设备授权等其他流程。首次授权必须有人在浏览器里操作。

**授权范围可能比显示的大。** #7 的本地记录：授权链接只列了只读权限，实际写 DNS 成功。这是本地观察，没有官方文档解释。撤销入口已查到：控制台个人资料下的 Manage OAuth authorizations，点 Revoke。账号管理员限制公开 OAuth 应用，只拦新授权，不影响已有授权。

**无人值守用令牌。** 官方建议自动化场景建 API 令牌，当 Bearer 令牌用。MCP 服务支持用户令牌和账号令牌。改 DNS 记录的接口对应权限组 DNS Write。

**没验证的。**

- 授权的有效期和刷新规则。
- Hetzner、DigitalOcean 的 provider 文档只说令牌必填，没写权限范围。
- 腾讯云、阿里云的访问密钥权限，没读。
- 验证码和同意按钮是人机验证，没有官方文档提供自动化方式，也不该去找。

### 4 配安全组：全自动

五家厂商都能用接口配防火墙，见对照表。腾讯云、阿里云、Hetzner 还能在建机时就挂上，省掉建机后再改的一步。

两个要注意的点：

- Lightsail 的 PutInstancePublicPorts 会关掉请求里没列出的端口。必须把 22、80、443 一次带全。文档里提到的 OpenInstancePublicPorts 不会关端口。
- 阿里云的接口文档对 0.0.0.0/0 没写警告，来源范围由调用方定。腾讯云的页面这一点没读到，未验证。#7 的授权范围没核对（本地记录）。合理推测：白名单动作里要写死来源范围。

朝晞云：未验证。

### 5 sudo 密码：全自动，但要先放宽规矩

**做法。** 合理推测，各部件都有出处。在 cloud-init（开机初始化脚本）的 user-data（开机时交给服务器的初始化数据）里：

1. 建部署用户，写 `ssh_authorized_keys`。`lock_passwd` 默认是 true，即禁用密码登录。
2. 用 `write_files` 往 `/etc/sudoers.d/` 写限定命令的免密规则，权限设 0440。sudoers（sudo 的权限配置文件）手册说默认文件模式就是 0440。
3. 建完用 `visudo -c` 检查。通过退出码为 0，出错为 1。手册说，只检查单个包含文件不够，要连同主文件一起查。

**官方提醒。**

- cloud-init 不检查 sudo 规则的语法，要自己验。
- `write_files` 会覆盖已有文件。
- sudoers.d 里文件名含 `.` 或以 `~` 结尾的会被跳过。文件按字典序读入。
- 命令参数按整串匹配。以 `^` 开头的按正则。通配符能匹配空白，手册说多数情况用正则更安全。
- 手册警告：shell、编辑器、分页器、邮件、终端程序都可能逃出限制。用 `!` 从 ALL 里减命令基本无效，只算建议性限制。编辑器应改用 sudoedit。
- cloud-init 警告：user-data 里的密码和私钥，可能被服务器上的普通用户看到。所以只放公钥，不放密码。

合理推测：#7 记录的 journalctl 默认会调分页器。若要免密，参数必须写死 `--no-pager`。

**规矩出处，未验证。** 议题写的是「项目规矩要求运营者手敲」。我在 AGENTS.md、docs/、#7、#10、#12 里搜 sudo 和「指纹」，只命中 #17 本身。#7 的本地文档只记了部署用户在 sudo 组。放宽成「限定命令的免密 sudo」之前，先要找到这条规矩在哪。

朝晞云的镜像是否带 cloud-init、能否传初始化数据，未验证。

### 6 核对主机指纹：全自动，但要先选信任方式

#7 的做法是运营者在服务器上手敲核对（本地记录）。官方手册里有三种自动做法：

| 做法 | 怎么做 | 代价 | 状态 |
|---|---|---|---|
| A 预置主机密钥 | 本地生成主机密钥对，放进 cloud-init 的 `ssh_keys`。公钥提前写进本机 known_hosts（已知主机清单）。连接时用 `StrictHostKeyChecking=yes` | 私钥要进初始化数据。cloud-init 提醒可能被普通用户看到，要确保数据源通道安全。阿里云接口文档也要求避免明文传私钥 | 原文已读。朝晞云未验证 |
| B 首次连接即信任 | `StrictHostKeyChecking=accept-new`。自动记下新主机密钥，之后密钥变了就拒绝 | 合理推测：第一次连接没有校验，可能遇到中间人攻击。官方说 `yes` 才是最大保护 | 原文已读 |
| C 从控制台日志读指纹 | cloud-init 默认把主机密钥和指纹写到控制台日志。若厂商接口能读控制台输出，程序读出指纹再写进 known_hosts | 要厂商接口支持读控制台输出 | 未验证 |

cloud-init 的 `ssh_deletekeys` 默认为 true，会删掉镜像自带的主机密钥。设了 `ssh_keys` 后，不会再自动生成别的密钥。

合理推测：C 最稳，因为私钥不出服务器。前提是厂商能读控制台输出，所以先验证这一条。

## 三条风险的验证细节

### 部分后缀要实名或资质：成立

- **.us。** Cloudflare 的 .US 页写明，注册人必须与美国有「真实关联」，要在三类里选一类，并说明用途。信息不实或不回应，可能被暂停或注销。
- **接口层。** 创建注册接口有 `contact_extensions` 字段。接口描述举例：.us 的关联字段、.uk 的注册人类型、.ca 的法律类型。调用方按 `GET /accounts/{account_id}/registrar/extensions/{extension}` 返回的 schema（字段格式说明）填。
- **.cn。** 《中国互联网络信息中心域名注册实施细则》（cac.gov.cn 上的 2012 版）第 15 条要求申请人提交身份证明，由注册服务机构核验。第 17 条要求申请人保证信息真实。第 19 条第二款规定，信息不实的域名由 CNNIC 通知注册服务机构注销。这是 2012 版，现行版本没核对。
- **未验证。** Cloudflare 能否注册 .cn。后缀清单页返回 403，指南没写。

### 内地服务器要备案，香港不要：部分成立

- **法规原文。** 《非经营性互联网信息服务备案管理办法》2005 年原文（cac.gov.cn 页）第五条要求，在境内提供非经营性互联网信息服务应当备案，未经备案不得从事。「境内提供」的定义按「境内的组织或个人」利用网站提供服务来写，没写服务器位置。全文没出现香港。
- **阿里云帮助页。** 两个页面都写，备案取决于服务器所在地域，资源在香港、海外节点则无需备案。其中一页另写，需完成公安联网备案。另一页没提公安联网备案。
- **修订。** 工信部令第 68 号在 2024 年修改了该办法。原文没读，只看到搜索摘要。
- **结论。** 「服务器在香港不用备案」是阿里云对自家云资源的说法。法规原文没写，朝晞云的说法没读。公安联网备案是否适用，没读到法规依据。

### #7 的厂商有没有接口：未验证

#7 的服务器厂商是朝晞云，香港区，月付。搜了「朝晞云」和「朝曦云」，结果里没有它的官网。本地文档里也没有接口使用记录。这只能说明没找到，不能说明没有。可能的原因是名称写法不同，或它是小厂商，或是转售商。

| sudo 规矩 | 规矩出处没找到。放宽成限定命令的免密 sudo，要定哪几条命令 | #10 的「部署环境」类 |
| 主机密钥信任方式 | A、B、C 三选一，代价见步骤 6 | 无 |
| 厂商 | 朝晞云有没有接口要先问清。没有就要换厂商或接受手动。换厂商会改变备案和付款 | #17 初步想法写了「换厂商」要通知运营者 |
| Cloudflare 一次性设置 | 令牌类型和权限范围。默认注册人邮箱是否与已验证的账号邮箱一致 | 无 |

**和 #12 怎么接。** 注册接口返回 202 时要轮询状态地址。邮箱验证最长 15 天。#12 的调度器只看现状，状态都在服务商那边，轮询接得上。这是合理推测，没有官方文档讲调度。腾讯云的 InvalidAccount.InsufficientBalance 和阿里云的 InvalidPayMethod，可当作「停下来叫运营者」的信号。
