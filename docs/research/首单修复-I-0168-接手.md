## 五、执行循环

每张票按这个顺序做。

### 1. 确认票和前置

```bash
中台/dt show I-0169
```

看三样：票是 open、没有未关闭阻塞、验收条件和测试点清楚。有未关闭阻塞就换下一张 frontier。

### 2. 建 worktree

从 `origin/main` 拉分支。分支名用 **GitHub 号**，不是中台号。

```bash
orca worktree create --name issue-476 --no-parent --base-branch origin/main --json
```

如果 Orca 不在，用 git：

```bash
git worktree add ../grilling-remote-issue-476 -b issue-476 origin/main
```

worktree 里设 Orca 的 `linkedIssue` 指 GitHub #476。Orca CLI 没有这个参数时，用 Orca 界面设。不要设 GitHub assignee。

### 3. 实现

读票的 `## 垂直切片`、`## 验收条件`、`## 测试`。只做这张票的范围。

TDD：

1. 先写失败测试。
2. 跑测试，确认失败。
3. 写最小实现。
4. 再跑，全过。

不顺手重构，不格式化无关文件，不扩范围。

### 4. 跑测试

按改动范围跑：

```bash
cd factory && npm test
cd backend && npm test
cd site && npm test
cd site && npm run build
```

这个仓没有 `.github/workflows`，没有 GitHub CI。本地测试就是门禁。`gh pr checks` 可能是空的，不要等 CI。

### 5. 提交和推送

```bash
git add <这次改的文件>
git commit -m "FACTORY: I-0169 点火 push 与结果记录"
git push -u origin issue-476
```

提交前缀用 `FACTORY:`。只 add 这次改的文件。不要提交两份未跟踪的 `素材/llm-wiki/...`。

### 6. 开 PR

```bash
gh pr create --base main --head issue-476 \
  --title "FACTORY: I-0169 点火 push 与结果记录" \
  --body-file /tmp/pr-I-0169.md
```

PR 正文写四栏：摘要、改动、测试、风险。第一行带 `I-0169 / #476`。

### 7. 自查

```bash
git diff origin/main...HEAD
```

看三样：只改这张票的范围、测试真的覆盖了验收条件、没有调试输出和无关文件。

### 8. 写关票记录

合并前必须写待关票记录。先拿 PR head SHA：

```bash
gh pr view <PR号> --json headRefOid --jq .headRefOid
```

写 payload 文件。四条评论，分别是四列表、改动文件（含阻塞边复查）、`## 依据`、五类检查。没有新决定时 `decisions` 写空数组：

```json
{
  "comments": [
    "## 四列表\n| id | 决定 | 取代 | 解答未定 | 产出文件 |\n| --- | --- | --- | --- | --- |\n| 无结论 | 修复实现，不产生新决定 | 无 | 无 | <文件> |",
    "## 改动文件\n- <文件>\n\n## 阻塞边复查\n- <写清楚有没有改阻塞边>",
    "## 依据\n- <每条理由带来源>",
    "## 五类检查\n- 新需求冒头：无\n- 和旧决定冲突：无\n- 做了别张票的活：无\n- 文件和决定矛盾：无\n- 阻塞边不对：无"
  ],
  "decisions": []
}
```

如果有新决定，`decisions` 加 `{"statement": "...", "output_files": [...], "rationale": "..."}`，评论里用 `{{D1}}`、`{{D2}}` 引用，中台会分配编号。

```bash
中台/dt close prepare I-0169 --pr <PR号> --sha <head SHA> --payload /tmp/close-I-0169.json
```

命令会顺手把 PR 号写进 Orca。没写进就手动：

```bash
orca worktree set --worktree current --pr <PR号>
```

**SHA 必须等于合并时的 PR head。** 记录写完又推了提交，先 `中台/dt close revoke I-0169`，再重新 prepare。

### 9. 合并

测试全过、自查完成、关票记录写好，才合并：

```bash
gh pr merge <PR号> --merge --delete-branch
```

用 merge commit，和仓库现有 PR 一致，不 squash。合并冲突、测试失败、记录写不上，就停，不合。

### 10. 核对关票和同步

中台服务每 2 秒读 Orca 的 PR 状态。看到合并、SHA 对得上，会自动关票。

```bash

```

票应该是 closed。没关就看屏幕信号，不要用 `dt issue close --force`。

同步 GitHub：

```bash
中台/dt sync --check I-0168
中台/dt sync I-0168
```

同步计划里没有要改的就跳过。有就同步。

## 六、同步失败怎么补

第一次同步时遇到过：GitHub 票建成了，但返回结果丢了，中台没记上号。处理办法：

1. 先 `gh issue list` 按标题找那张票。
2. 找到了，把它挂到地图下：

```bash
gh issue edit 475 --add-sub-issue <票号>
```

3. 再 `中台/dt sync I-0168`。同步会认领同标题同正文的远端票，补阻塞边。
4. 找不到才重新建。不要直接重跑同步，先查 GitHub，避免建第二张。
