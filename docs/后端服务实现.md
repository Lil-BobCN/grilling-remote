# 后端服务实现

2026-11-15。对应票 I-0086「上传接收端点」。

一句话：真实服务在本仓库 `backend/`，没有第三方依赖，用 Node 26 直接跑。登录、订单、上传同进程，和占位服务走同一条发布路径。

## 目录

| 路径 | 干什么 |
| --- | --- |
| `backend/server.mjs` | 入口。读环境变量，起 HTTP 服务，每个请求写一行 JSON 日志 |
| `backend/lib/app.mjs` | 路由、登录、会话、订单查询、上传入口 |
| `backend/lib/uploads.mjs` | 上传判序、限速、快照落盘、失败包保留 |
| `backend/lib/auth.mjs` | argon2id 密码校验、签名 Cookie、账号状态检查 |
| `backend/lib/orders.mjs` | 订单记录读写、`o-0001` 编号、轮次和转档行 |
| `backend/lib/store.mjs` | 原子写、文件锁、Git 同步 |
| `backend/lib/validate-package.mjs` | 需求目录内容检查，生成 `missing` 文案 |
| `backend/py/checkzip.py` | 子进程：检查 zip 安全、找工作区根目录、只解出 `.scratch/` |
| `backend/bin/customer.mjs` | 客户白名单命令行，命令按 `docs/客户白名单维护.md` 第九节 |
| `backend/test/` | 42 个测试，`npm test` 跑 |

## 接口

路径和字段按 I-0035 的决定 D-0168、D-0169。前端 `site/src/api/account.js` 和 `site/src/pages/UploadPage.jsx` 不用改。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/app/api/health` | 占位服务和真实服务都有，回 `{ok, version}` |
| `POST` | `/app/api/login` | JSON `{email, password}`，成功回 `{user}` 并种 `afk_session` |
| `GET` | `/app/api/session` | 有会话回 `{user}`，没登录 401，账号停用 403 |
| `POST` | `/app/api/logout` | 204，清 Cookie |
| `POST` | `/app/api/uploads` | multipart `file`、`finished`，成功回 `{orders}` |
| `GET` | `/app/api/orders` | 只回自己的单 |
| `GET` | `/app/api/orders/{id}` | 不存在 404，不是自己的 403 |
| `GET` | `/app/api/admin/orders` | 只有 `role=admin` 能读 |

错误码：400 缺字段或 multipart 坏了；401 未登录；403 账号停用、不是同源、不是自己的单；404 订单不存在；413 超过 50 MB；415 不是 zip；422 路径穿越、解压炸弹、加密包、缺 `.scratch`；429 限速；5xx 服务端错误。

写请求查 `Origin` 或 `Sec-Fetch-Site`，同源才放行。Cookie 名 `afk_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`，线上加 `Secure`。客户 30 天，管理员 7 天。Cookie 里放账号 id、角色、密码哈希前 16 位和过期时间。每次请求重新查账号，停用立刻失效。

## 上传判序

1. 查登录态。没登录 401，账号停用 403。
2. 限速。同一账号 10 分钟 5 次，同一 IP 10 分钟 20 次。超了 429。
3. 收 multipart，只认 `file` 和 `finished`。`finished` 必须是 `true` 或 `false`。
4. 压缩包超过 50 MB 返回 413。不是 `.zip` 或 zip 打不开返回 415。
5. 子进程检查安全，见下表。命中任一条返回 422。
6. 找工作区根目录。规则按 D-0171：根目录有 `.scratch/` 通过；只有一个有效子目录且它有 `.scratch/` 也通过；找不到按四类给提示。
7. `.scratch/` 下没有需求目录返回 422。有需求目录就逐个检查内容。
8. 检查勾选和内容，生成 `missing`。缺 `.scratch/` 不建订单；内容不全仍返回 200，建订单并把 `missing` 写进订单。
9. 写订单记录，转档写 `已收到｜收包`，通过写 `已收到｜校验`，不通过写 `校验未通过｜等补传`。同一客户同一需求重传沿用原订单号，不建第二张。

失败包留在 `/data/uploads/<上传 id>/`，7 天后由启动清扫和定时清扫删掉。成功的包保留，等导入步骤拉走；导入和删除不在本票里。

## 安全限制

| 项 | 默认 | 环境变量 |
| --- | --- | --- |
| 压缩包上限 | 50 MB | `MAX_UPLOAD_BYTES`，只给测试改小 |
| 条目数 | 20000 | `ZIP_MAX_ENTRIES` |
| 解压总量 | 512 MB | `ZIP_MAX_UNCOMPRESSED` |
| 单个文件 | 128 MB | `ZIP_MAX_FILE` |

拒绝的情况：条目名含 `..`、绝对路径、盘符开头；符号链接；加密条目；超上面三条上限。解压只解 `.scratch/`，其他文件不落盘，原始 zip 原样保存。

上传件目录 `700`，文件 `600`，属主是服务用户 `afkapp`。

## 数据

| 文件 | 内容 |
| --- | --- |
| `/data/customers/customers.json` | 客户数组，字段见 `docs/客户白名单维护.md` |
| `/data/customers/admins.json` | 管理员数组，字段按 D-0168 |
| `/data/customers/orders/o-0001.json` | 一条订单一个 JSON，字段按 D-0167 |
| `/data/customers/orders/o-0001.sync-pending` | 推送私有仓失败的待办，后台每分钟补寄一次，成功后删掉 |
| `/data/uploads/<上传 id>/package.zip` | 回传件快照 |
| `/data/uploads/<上传 id>/meta.json` | 这次上传的 SHA256、状态、需求、订单号 |

订单文件只由 `backend/lib/orders.mjs` 写：先加文件锁，写临时文件再原子替换，然后提交并推送私有仓。`/data/customers` 不是 Git 仓库时跳过同步，只写磁盘。

推送失败时，订单目录多一条 `<订单号>.sync-pending`，记订单号、需求名、第一次失败时间、最近一次尝试和失败原因。服务每分钟拿这些待办重试一次推送，成功就删掉待办。待办超过 10 分钟还没清掉，积压期间每次重试都记一条 error，带订单号、开始时间和失败原因；`deploy/backend/check.sh` 查近 15 分钟的日志，命中就判巡检失败。待办文件不提交、不推送，私有仓里看不到。

## 客户白名单命令行

在服务器上用 `afkapp` 跑，否则文件属主会变：

```bash
sudo -u afkapp node /data/app/current/bin/customer.mjs add \
  --short-name acme --display-name "Acme 老板" --email boss@acme.example
```

命令会要求输两遍密码，不回显，写完打印 `c-0001`。其他命令：`list`、`show`、`disable --reason`、`enable`、`change-email`、`reset-password`。脚本里用 `--password-stdin` 从标准输入读密码。

密码用 argon2id 存哈希。Cookie 里的版本取哈希前 16 位，换密码、停用后旧会话立即失效。

## 部署和回滚

打包、传输、发布和 `docs/后端服务部署.md` 一样，只是源目录换成 `backend/`：

```bash
bash deploy/backend/package.sh backend 1.0.0
ssh dev@<服务器地址> 'cat > /tmp/afkapp-1.0.0.tgz' < output/afkapp-1.0.0.tgz
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/deploy.sh /tmp/afkapp-1.0.0.tgz 1.0.0'
```

回滚不变：

```bash
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/rollback.sh'
```

上线前确认三件事：`/data/customers` 已建好并能被 `afkapp` 读写；`/etc/afkapp/app.env` 填了 `SESSION_SECRET`；Caddy 的 `/app/api/*` 仍反代到 `127.0.0.1:8787`。

`SESSION_SECRET` 没填时服务会用临时密钥启动，日志里有一条警告。登录能用，但服务重启后所有人要重新登录，线上不要这样跑。
