2026-11-09 决定。依据 [地图：地图与票跟着运营者的认知一起更新](https://github.com/Lil-BobCN/grilling-remote/issues/117)、[四列表与编号规范](https://github.com/Lil-BobCN/grilling-remote/issues/118)。

一句话：一项决定只在关票那一刻写一次，写进那张票评论的四列表。`docs/decisions.md` 和地图 `Decisions so far` 都由脚本从已关闭票编出，提交进 git，不许手改。

## 为什么要换

旧做法的写入点是扫描表：五项，其中两项是「地图每一行判现行还是被取代」和「逐张开放票判一档」。这是手写清单，每关一张票全文重写一遍。手写清单会烂，实测有两处。

一是数不上。地图 #1 的索引 52 行对 53 张关闭票，缺 #36；ADR 0006 记的 11-06 对账是 23 行对 24 票，缺 #18。两次都只差一张，说明没有机制在数。

二是扫得浅。#45 写「要你判的矛盾：无」，后来判出与 #20 相反；#72 写「已关闭决定的矛盾：无」，后来判出与 #17 矛盾。开放问法直接问「矛盾吗」，实测准确率 53.8%；改成先找证据再判，精确率 88%。

旧做法还有一个结构问题：一个决定存多处。票的关票评论、地图 52 行索引、`docs/adr/` 七份、`docs/*.md` 里 18 处「已废/已被」标记，四个载体，没有哪个是权威。

维护得住的知识系统都把两件事分开：只增不改的历史，和可重建的当前视图。ADR、事件溯源、维基 revision、Kafka 日志压实都是这个形状。更新点都落在决定落地那一刻，没有「以后统一整理」。

## 换成什么

写入点退到一处：关闭票的评论，正文是一张表，列固定为 `id`、`决定`、`取代`、`解答未定`、`产出文件`。没有结论的票写 `无结论：<理由>`。编号形如 `D-0002`，全仓连续，写完不复用。新号取 `docs/decisions.md` 和 `docs/decisions-archive.md` 里最大的号加一；两个文件都不存在时，取所有已关闭票评论里的最大号加一。

读取视图是编译产物：`scripts/decisions build` 编出两个文件。`docs/decisions.md` 只收现行决定，被取代的条目连同原行挪进 `docs/decisions-archive.md`，编号保留。同时重生成地图的 `Decisions so far` 一段，那一段退回上游的形状，一张关闭票一行，只写票名、一句结论和链接，不标现行还是被取代，不判重复。手改台账，`check` 第 6 条按字节比对，立刻报错。

开放票读不到老票的问题，用一行引用顶住：正文第一行写 `依据：D-0002,D-0005`。号码被取代后，脚本按这一行就能列出所有受影响的开放票，不用知道哪张票派生自哪张。

验证分两层。能由脚本验的写法列进 `check` 的八条不变量：编号唯一、现行和被取代互斥、开放票不引用已取代编号、每张已关闭票有表或写了 `无结论：`、产出文件存在且提到取代者编号、提交版等于 `build` 结果、`解答未定` 指向的 `U-` 已从地图未定块移除、覆盖表每句有状态。脚本验不了的只剩两处，靠写的人和运营者抽查：四列表里「决定」那一句要写清实际定了什么；覆盖表要填真能落这一句的票。这两处出错，`check` 不报。

## 代价

每关一张票仍要写表，但只写表，不再重写地图索引。运营者多一个动作：先调 `check`，再调 `wrap-up`，后者只读前者的输出，不自己重跑。

台账进 git，每次关票带一次生成文件的改动。

「决定」那一段脚本判不了，写弱了要人看出来。这是这套方案留着的人控点，不打算用脚本消掉。

## 没验证

1. `scripts/decisions` 还没写，八条不变量对着现存 53 张票跑出什么，未知。
2. 53 张老票的结论散在正文里，补成四列表要人手一条条写。迁移多少张、怎么排先后，按地图 #117 的《老票迁移》执行。
3. 地图 `Decisions so far` 由脚本重生成之后，GitHub 正文会不会被并发会话覆盖，上游 #476 报过同类问题，本仓未实测。
4. `map-gate` 与 `spec-check` 都已定：两者都改成读地图全文、`docs/decisions.md` 和现行决定对应的来源票，不再只看「现行决定清单」评论。`map-gate` 保留检查，查矛盾、旧句、缺口，它出的清单评论当放行报告；`spec-check` 照样只读、只标问题。两个技能的正文还没改，改法归后续票。
5. 覆盖表要求「填真能落这一句的票」，这一项没有脚本能验，漏填时 `check` 只报「没状态」，不报「填错」。
