# 调度器直接点火，Grok Bot 只当窗口和收件箱

2026-11-04 决定。Mac 上的调度器每 30 秒读一遍 open 工单的标签。找到「该动还没动」的，自己启动对应的执行会话，把提示词喂进去。Grok Bot 不做路由，不点火。它只收提醒、点闸门、拆票、给客户回话。

为什么：Grok Bot 靠例程和 webhook。审批会过期，例程会被暂停，用量会限流，提醒到不了人。点火这条链不能押在它身上。状态只在 GitHub，调度器主动去读，少一层转发。

代价：点火后 2 分钟没回执，调度器在工单上写「点火超时」、打标签、发一封邮件，不自动补点，等人。告警走 GitHub 和邮件，不走 Grok Bot。门铃和 webhook 退场。2 分钟这个阈值是从旧门铃方案沿用的，没实测。
