# 回传走官网上传页

2026-11-05 决定。客户澄清结束后，把 `.scratch/{简称}/` 和 `meta.json` 打成一个 zip，拖到官网固定上传页。服务器校验 `meta.json` 和客户白名单，自动建或复用客户仓、写 parent issue、打闸门。运营者点闸门才开工。

为什么走网页上传：客户动作只有两步，点页面、拖 zip。客服微信和邮件只作兜底。服务器有公网地址和仓库令牌，能在客户不接触 GitHub 的前提下自动建单。`meta.json` 带简称和邮箱，解决微信文件名、聊天昵称、隐藏目录对不上人的问题。

为什么只回 `.scratch/{简称}/`：工作区里还有 `.dsh/`（技能、会话记录）和 `AGENTS.md`。全打包会把客户和 agent 的对话顺手带出去。对话记录回不回单独定过，这次定不回。原型在 `prototypes/` 里随包走，存档在本机，不进客户仓。

时机：澄清全部做完传一次。中途客户卡住或运营者要核对时，按需补一份当前快照。`meta.json` 的 `complete` 为 false 时只存快照，不建单。

自动建的三道保险：上传前校验（zip 可解、必填字段、`complete` 为 true、文件清单对得上、大小上限）；`requirement_id` 幂等，重传不建第二张单；建完打闸门标签，不自动开工。

身份：服务器维护 `customers.json`，接单时加一行（简称、称呼、邮箱、仓名）。`meta.json` 的简称和邮箱要和这一行对上，对不上就拒，页面提示找客服。

存储：服务器只做中转。私有存储、随机地址、只下载不渲染。导入完成就删；失败留 7 天。长期存档在 Mac 的 `inbox/`。

兜底：上传页打不开、客户不会拖，或 Mac 超过 24 小时没处理，微信发同一个 zip 给客服，存 `inbox/`，跑同一条 import。邮件第二兜底。

代价：服务器要临时存客户草稿，和 `docs/工厂流程.md` 原来写的「不存客户草稿」冲突。这条改成「只留到导入完成，失败最长 7 天」。上传页、接收端点、Mac 拉取桥的实现不在 wayfinder 开票，等 map 执行时由 to-spec 出票。

没验证：Windows 上 agent 能不能用 `Compress-Archive` 或 `zip` 打包；客户能不能把 zip 从电脑拖进上传页；手机上传；服务器自动建单和 `gh` 的幂等。

依据：#24 的结论和契约评论；#22（`pending.md`）、#23（安装和 `.scratch` 查看）、#20（原型不进客户仓）、#30（问题树需要 `pending.md`）。
