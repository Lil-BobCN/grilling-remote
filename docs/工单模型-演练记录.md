# 工单模型演练记录

日期：2026-11-07
机器：macOS
`gh`：2.95.0
测试仓：`Lil-BobCN/grilling-customer-test`（私有，不是真客户）

## 怎么演

照 `docs/工单模型.md` 从零建一遍：建仓和四个标签，建一张父工单和两张子票，把四档走一遍，再走驳回和改口。

调度器还没写。标签用 `gh issue edit` 手工改，由我扮演调度器。

## 一、建仓和标签

```bash
gh repo create grilling-customer-test --private --add-readme \
  --description "工单模型演练用测试客户仓，不是真客户"

gh label create "状态:已提交" --color ededed --description "已建单，等技术闸门"
gh label create "状态:排队中" --color fbca04 --description "轮到了，等点火"
gh label create "状态:开发中" --color 1d76db --description "正在跑"
gh label create "状态:待验收" --color 0e8a16 --description "活干完了，等下一步确认"
```

结果：仓建成，默认分支 `main`，私有。四个标签都在，中文名和 ASCII 冒号正常。`gh label list` 能看到颜色和说明。

需求全文按 `docs/requirements/<需求名>/` 拷进仓，用 Contents API 写了一个 `map.md`，提交 `4c571ac`。

## 二、建单

```bash
gh issue create --title "顾客在微信上看今天的水果、下单，选到店取还是送货" \
  --body-file parent.md --label "状态:已提交"
```

结果：#1。五段正文都在。

```bash
gh issue create --title "顾客打开链接能看到今天的水果、价格和卖完的" \
  --body-file child1.md --label "状态:排队中" --parent 1

gh issue create --title "顾客下单时能选到店取并挑一个取货时间" \
  --body-file child2.md --label "状态:排队中" --parent 1 --blocked-by 2
```

结果：#2、#3 都挂到 #1 下面，`sub_issues` 能查出来。#3 的原生依赖指向 #2，正文写 `Blocked by: #2`，两处一致。

## 三、四档走一遍

| 步 | 命令 | 结果 |
| --- | --- | --- |
| 闸门答完 | `gh issue edit 1 --remove-label "状态:已提交" --add-label "状态:排队中"` | 父工单只剩 `状态:排队中` |
| 拆票点头、点火 #2 | `gh issue edit 1` 和 `gh issue edit 2` 都换成 `状态:开发中` | 父工单、子票都是 `状态:开发中` |
| #2 证据齐 | `gh issue edit 2 --remove-label "状态:开发中" --add-label "状态:待验收"` | #2 是 `状态:待验收` |
| 合进需求分支 | `gh issue close 2 -c "验证技能跑过、前后截图、测试全绿、评审两轴过。"` | #2 关闭 |
| #3 解锁 | 查 `issues/3/dependencies/blocked_by` | #2 显示 `closed`，#3 可点火 |
| #3 走完 | 开发中 → 待验收 → 关闭 | #3 关闭 |
| 父工单进入待验收 | `gh issue edit 1 --remove-label "状态:开发中" --add-label "状态:待验收"` | 父工单 `状态:待验收`，仍 open |

查标签筛选用：`gh issue list --label "状态:排队中"`，返回 #2、#3。

## 四、驳回

```bash
gh issue comment 1 --body "驳回：价格改完顾客看不到，要刷新两次才行。这条不行，先改好。"
gh issue edit 1 --remove-label "状态:待验收" --add-label "状态:开发中"
gh issue create --title "价格改完顾客刷新一次就能看到" --body-file fix.md \
  --label "状态:排队中" --parent 1 --blocked-by 2
```

结果：评论在 #1 上（id 6702887744），父工单回到 `状态:开发中`，修复子票 #4 挂到 #1 下。父工单没重开，也没另开新 issue。

## 五、改口

```bash
gh issue comment 1 --body "改口：送货也要能选上午还是下午，别只给个地址。旧条文留档：……"
gh issue edit 1 --body-file parent.md
```

结果：评论在 #1 上（id 6702889852），旧验收条件原文在评论里，正文加了一条新验收条件。

## 七、发现

中文标签可用。`gh label create` 和 `gh issue edit --label` 都认中文，`gh issue list --label "状态:排队中"` 能筛。冒号要用 ASCII 的 `:`，全角冒号脚本对不上。

`--parent` 和 `--blocked-by` 可用。gh 2.95 两个参数都在，建子票顺手挂父工单和阻塞边，不用事后补命令。

关子票即解锁。父工单还开着不影响子票之间的依赖，看的是被挂那张子票自己的状态。

**坑一：编号写错。** 我第一次给 #3 挂的是 `--blocked-by 1`，本意是「第一张子票」，实际挂成了父工单。父工单一直 open，这条边永远不解除。子票编号从父工单之后开始，写边之前先 `gh issue view` 看真实编号。挂错的边用 `gh issue edit 3 --remove-blocked-by 1 --add-blocked-by 2` 改回来，正文的 `Blocked by:` 也要跟着改。

**坑二：相对路径。** 正文写 `docs/requirements/yuyue-quhuo/`，能不能点没验成。私有仓页面用 token 抓不到渲染结果，`/markdown` 接口又只原样返回相对链接。模板改用完整 URL，绕开这个不确定。

**坑三：关票不清标签。** #2、#3 关掉以后 `状态:待验收` 还在票上。这是历史，别清。调度器看的是 `state == open` 加标签，不看有没有残留。

## 八、没验到的

- 调度器本身没写。30 秒对账、读 `驳回：` 评论、`needs-info` 兜底、点火超时，都是手工演的。
- 私有仓 issue 页面的渲染没抓到，完整链接点不点得开，要在浏览器里看一眼。
- 服务器校验、建仓脚本、客户白名单都没到位，回传整条链路没接。本记录只验了工单这一层。
