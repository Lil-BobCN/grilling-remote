# 服务器操作手册

日期：2026-11-07
状态：现行。每条命令都在机器上跑过。
适用：回传用的那台 Linux 服务器。

地址、域名、私钥路径不进公开仓库，记在本地 `private/服务器.md`。

这台机器现在只做一件事：给一个域名回 `ok`。没有应用，没有业务数据，重启后自己站起来。下面写清谁能进、怎么复核、出事看哪里。

## 二、防火墙

`ufw` 一直是开着的。2026-11-07 实测：

```
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
```

放行只有三条，IPv4 和 IPv6 各一套：22（SSH）、80、443。没有别的端口。

改规则要 `sudo`。加放行用 `sudo ufw allow <端口>/tcp`，看当前规则用 `sudo ufw status verbose`，删规则用 `sudo ufw status numbered` 先看编号，再 `sudo ufw delete <编号>`。

80 和 443 现在只由 caddy 用。以后上传服务另开端口时，记得按 #73 用独立用户，并且只放行反代需要的那一个端口，不要整段放开。

## 三、复核命令

机器换过、重启过、有人说打不开时，照这张表从上往下跑。

现在没有自动巡检，靠人跑。重启后、改过配置后、被问到「服务还在不在」时各跑一遍，另外每月至少一次。跑出来有不对的，先看第四节确认该哪个单元负责，再看 `/var/log` 和 `journalctl`。

| 要确认什么 | 命令 | 正常输出 |
| --- | --- | --- |
| 能登录 | `ssh -i <私钥> dev@<地址> hostname` | `ser863263820538` |
| 机器没被换 | `ssh-keyscan -t ed25519 <地址> 2>/dev/null \| ssh-keygen -lf -` | `SHA256:MV6dD1kltFSR0vaU3hrbkDRlwVGTmhkvVwzLRpK2cbE` |
| 时钟同步 | `timedatectl` | `System clock synchronized: yes` |
| 站点活着 | `curl -sS --resolve <域名>:443:<地址> https://<域名>/` | `ok` |
| 证书没过期 | `echo \| openssl s_client -connect <地址>:443 -servername <域名> 2>/dev/null \| openssl x509 -noout -dates` | `notAfter` 在一年以内 |
| caddy 在跑 | `systemctl is-active caddy` | `active` |
| 有没有坏掉的单元 | `systemctl --failed` | `0 loaded units listed` |
| 端口在听 | `ss -tln` | 22、80、443 |
| 防火墙规则 | `sudo ufw status` | `Status: active`，放行只有 22、80、443 |
| 数据盘挂上 | `df -h /data` | 79 G |
| 最近的日志 | `journalctl -u caddy -n 50 --no-pager` | 最近 50 行 |

两个坑：

本机开着代理软件时，DNS 会被接管。2026-11-07 实测（代理开着），`<域名>` 在本机解析成 `198.18.0.51`，不是服务器地址；关掉代理后 `dig` 直接返回源站地址。判断有没有被接管，看返回值是不是 `198.18` 开头。

这时直接跑 `curl https://<域名>` 也可能返回 `ok`，因为请求是代理转出去的。于是机器已经挂了，本地看着还是好的。判断服务器死活要用 `--resolve` 指向真实地址，绕开本机 DNS。

`ssh-keyscan` 不经过 known_hosts，用来核对机器身份。看到别的指纹就先停下，别往里输任何东西。

## 四、服务清单

| 单元 | 干什么 | 开机自启 | 挂了会怎样 |
| --- | --- | --- | --- |
| `caddy` | 申请证书、回 `ok` | 是 | 443 不通，站点打不开 |
| `systemd-timesyncd` | 对时 | 是 | 时间慢慢漂，证书校验和日志时间会歪 |
| `ssh` | 登录 | 是 | 登不上，只能从云控制台进 |
| `unattended-upgrades` | 自动装安全更新 | 是 | 安全补丁不装 |
| `ufw` | 防火墙 | 是 | 规则不加载，对外端口不受这台机控制 |

其余是 Ubuntu 默认带的（cloud-init、snapd、rsyslog、cron、apparmor 等），没配过，也不用管。

caddy 版本 2.6.2，来自 Ubuntu 自己的软件源。配置文件 `/etc/caddy/Caddyfile`，现在一共三行：一个域名，一句 `respond "ok"`。启动方式是 `/usr/bin/caddy run --environ --config /etc/caddy/Caddyfile`。

## 六、时钟

2026-11-07 之前一直不同步。`timedatectl` 里 `System clock synchronized: no`，timesyncd 在跑但对不上。

原因：这台机器只有 IPv4 路由，没有 IPv6。timesyncd 默认解析 `ntp.ubuntu.com`，拿到的是 IPv6 地址 `2620:2d:4000:1::41`，包发不出去，它也不换下一个地址。实测往这个地址发包直接 `Network is unreachable`。

修法：在 `/etc/systemd/timesyncd.conf` 里钉两个能通的 IPv4 地址。实测 `ntp.tencent.com`（`119.28.230.190`）和 `time.cloudflare.com`（`162.159.200.1`）都能通，延迟 3 到 7 毫秒。`ntp.ubuntu.com` 的两个 IPv4 地址反而超时，别用。

```ini
[Time]
NTP=119.28.230.190 162.159.200.1
FallbackNTP=ntp.tencent.com time.cloudflare.com
```

改完 `systemctl restart systemd-timesyncd`，等几秒，`timedatectl` 里应该变成 `yes`。

2026-11-07 04:05 复核：同步到 `162.159.200.1`，偏差 0.68 毫秒，和运营者本机逐秒对得上。

换机器或换机房要重测。两个地址都不通时，timesyncd 会退到 fallback 的域名，域名又可能解析到 IPv6，于是重新卡住。换机房前先测通再写进去。

## 七、备份

**这台机器不做备份。** 四条理由：

`/data` 是空的，没有业务数据可丢。站点只有一个三行的 `Caddyfile`，重建比恢复快。证书由 caddy 自动申请和续期，本来就不用备份。整机能从同一个镜像重建，步骤见最后一节。

什么时候改主意：`/data` 开始放东西，或者出现手工改过、重建不出来的配置。到那时再加备份，别提前养一套没人盯的定时任务。

## 九、agent 怎么拿权限

用 `dev` 登录，靠 `/etc/sudoers.d/agent-ops` 放开四条改状态的命令，不要密码：

```
dev ALL=(root) NOPASSWD: /usr/bin/systemctl restart caddy, /usr/bin/systemctl reload caddy, /usr/bin/systemctl restart systemd-timesyncd, /usr/bin/timedatectl set-ntp true
```

读状态不需要 sudo。`dev` 在 `adm` 和 `systemd-journal` 两个组里，`journalctl` 能读全量日志。`systemctl status`、`ss`、`df` 本来就开放。

加命令前先问一句：这条命令能不能拿来改任意文件，或者起任意进程。能，就不加。

`journalctl` 这类会调分页器的命令别放进 sudo 白名单。sudo 下分页器以 root 跑，`less` 里能开 shell。这个坑用组权限解决，不用 sudo。

出事故收回：`sudo rm /etc/sudoers.d/agent-ops`，或者把整行注释掉。改完都跑一次 `visudo -c`。

服务器上不跑常驻 agent。旧配置开过 `bypassPermissions` 和 `skipDangerousModePermissionPrompt`，两个都是 Claude Code 自己的确认开关，开了就等于跳过确认。这一层和上面的 sudo 白名单是两回事：白名单管得住 root 命令，管不住这两个开关。以后要在服务器上跑 agent，先删这两个开关，再把动作限在白名单那四条命令里。见 [#78](https://github.com/Lil-BobCN/grilling-remote/issues/78)。

## 十、从空机器重建

1. 开一台 Ubuntu 24.04 的机器，系统盘 30 G 起，数据盘 80 G。
2. 建 `dev` 用户，加进 `sudo` 组，放公钥到 `~/.ssh/authorized_keys`。
3. `apt install caddy`，来自 Ubuntu 自带源。
4. 开防火墙，只放 22、80、443：`sudo ufw allow 22,80,443/tcp`，再 `sudo ufw enable`。云控制台的安全组也要放这三个端口，见 #84。
5. 写 `/etc/caddy/Caddyfile`：一个域名块，一句 `respond "ok"`。
6. 格式化数据盘，挂到 `/data`，用 UUID 写进 `/etc/fstab`，带 `nofail`。
7. 按第六节改 `timesyncd.conf`。
8. `reboot`，按第三节复核一遍。

半小时左右，大半时间在装系统和等证书签发。
