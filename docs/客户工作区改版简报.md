## 一句话

官网不再发「技能包 + 装配提示词」，改发一个已经摆好的工作区 zip。客户下载、解压、用 dsh 打开，说一句话就开始。做完把 `.scratch/` 打包回传。

## 客户流程

1. 官网点下载 `客户工作区-v1.zip`。
2. 新建空文件夹，把 zip 放进去，解压到当前文件夹。
3. 用 dsh 打开这个文件夹，说「我想做一个……」，或「开始需求澄清」。
4. 做到最后，按模板收尾，打包 `.scratch/{简称}/` 加 `meta.json` 上传。

没有提示词①。第一次打开由 agent 自检。浏览器不能直接下文件夹，zip 是载体；解压后根目录直接是工作区，外面不套 `grilling-skills-v1/` 这一层。

规则：

- `AGENTS.md` 是成品，不是 `AGENTS-TEMPLATE.md`。
- `docs/agents/` 两份预生成，`## Answer` 改成 `## 结论`，`## Comments` 改成 `## 评论`。
- `.dsh/skills/` 放客户版技能。`setup` 不放，源码里留着给构建用；`ask-matt` 建议不放。
- 不放 `.scratch/`，第一次说需求时由 agent 建。
- 放 `技能清单.md`；官网清单从同一份源生成，不手写两份。
- 根目录放 `README.txt`、`LICENSE`、`NOTICE.md`。
- 构建脚本要把 zip 的内容直接放在根目录。现在 `build.sh` 套了一层 `grilling-skills-v1/`，要改。

## 三个技能，三个点

| 什么时候 | 用哪个 | 干什么 | 客户听到什么 |
| --- | --- | --- | --- |
| 每次开头 | next | 读地图的「接下来」，挑第一张没被挡的 | 「还剩 4 张，今天做第 2 张，讲的是……」 |
| 写结论前 | map-gate | 读地图和全部票，列冲突 | 「你前面说价格只有老板能改，刚才说店员也能改，要改前面那句吗？」 |
| 每次收尾 | wrap-up | 列新想法、和旧结论冲突的地方、对不上的先后 | 「这次多了一个想法，我记到第 5 张后面了」 |

规则：

- 照 `.claude/skills/next`、`map-gate`、`wrap-up` 的步骤改，数据源换成 `map.md` 和 `issues/*.md`。不读 GitHub，不写 issue 评论。
- 去掉 `disable-model-invocation: true`。description 写触发时机，例如「每次开工前用」「写结论前用」「每次收尾用」。
- 不能直接拷贝运营者版。
- `map-gate` 用没参与这段对话的 agent 读；起不来就自己重读文件，不要卡住客户。
- 第一次还没有地图，`next` 不选票，直接问客户想做什么。
- `AGENTS.md` 写三句触发：
  - 每次开工：先用 `next` 看下一张。
  - 写 `## 结论` 前：先用 `map-gate` 查这次结论有没有推翻前面的结论，查完在本票 `## 评论` 写一句「查过：……」。
  - 收尾：先用 `wrap-up` 列这次的新想法和冲突。
- 痕的两种写法：「查过：和前面没有冲突」；「查过：和第 N 张冲突，客户选择改第 N 张」。

## 验收

1. 新 Mac 空文件夹：解压、打开 dsh、说一句话，agent 直接问需求，不需要装配提示词。
2. 第一次自检能报出缺 `docs/agents/` 或缺 `.dsh/skills/`，并停下。
3. 三张票走一遍：开头 `next` 报进度；第 2 张写结论前 `map-gate` 发现和第 1 张冲突，问客户；客户说改，旧票加评论、地图标「已废，见第 2 张」、开放票改正文；本票评论有「查过」。
4. 收尾 `wrap-up` 列出新想法和冲突。
5. 新 zip 解压到旧工作区，`.scratch/` 还在。
6. Windows 解压、隐藏 `.dsh`、中文路径原按 #36 清单测；2026-11-07 决定不测（没有对应主机），这四项未验证。
7. 回传包仍能上传、能被运营者解压读取。
