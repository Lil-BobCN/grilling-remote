# 领域文档

本文件说明工程类 Skill 了解代码库时，该怎样读取本仓库的领域知识。

## 开始前先读什么

- 根目录存在 `CONTEXT.md` 时，先读它。
- 根目录存在 `CONTEXT-MAP.md` 时，先通过它找到与当前工作相关的 `CONTEXT.md`。
- 读 `docs/adr/` 中与当前工作相关的架构决策记录（ADR）。

这些文件不存在时直接继续，不提示缺失，也不提前建议创建。等术语或重要决定
真正明确后，再由 `domain-modeling`、`grill-with-docs` 或
`improve-codebase-architecture` 按需创建。

## 文件布局

本仓库是单一上下文（没有多包结构）：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-示例决定.md
│   └── 0002-另一项决定.md
└── src/
```

## 使用项目已经确定的说法

Issue 标题、重构建议、假设和测试名称里出现领域概念时，使用 `CONTEXT.md` 已定义的名称，
不要换成近义词。

需要的概念还没定义时，先判断是不是自己造了项目里不存在的说法。确实缺失，再记为
需要通过 `domain-modeling` 解决的问题。

## 明确指出与 ADR 的冲突

建议与现有 ADR 冲突时，直接指出冲突和重新讨论的理由，不要悄悄覆盖已有决定。例如：

> 这与 ADR-0007 的决定冲突，但值得重新讨论，因为……
