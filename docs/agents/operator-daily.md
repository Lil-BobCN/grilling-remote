# 运营者的日常

一句话：你只做三件事，看主线、守承诺、收例外。其余交给 agent 和中台。

## 三条原则

1. 日常按一次会话排，不按钟点。
2. 只有产生承诺或不可逆结果的动作必须你来做。
3. 结论会变是正常的。系统抓的是你推翻旧结论的那一刻，不是每次代码改动。

## 日常节奏

| 节点 | 你看什么 | 你做什么 | 在哪 |
| --- | --- | --- | --- |
| 开工前 | 当前地图的 Destination 和覆盖表、开着的影响清单 | 决定今天推哪张图，有没有待处理的清单 | 中台屏幕 |
| 开场 | agent 汇报的当前票前提、状态、要你拍板的事 | 听汇报，拍板 | orca 会话 |
| 会话中 | 不盯屏幕 | agent 问就答，要决定就拍板 | orca 会话 |
| 关票前 | PR 正文的四列表和决定草稿、票上的冒头评论 | 认了才合并，冒头判去向，代码 diff 扫一眼 | GitHub、中台 |
| 合并 | PR 的合并按钮 | 合并即确认决定草稿和关票 | GitHub |
| 合并后 | 票是否变「已完成」 | 不用做事，关票信号亮了再处理 | 中台屏幕 |
| 收工前 | 即时档信号、同步计划 | 处理信号，按地图同步；同步后看有没有异常 | 中台屏幕、终端 |

## 信号 → 动作

视觉信号分三档。立即档在会话中或收工前处理；收尾档在地图收尾或进 `to-spec` 前批量处理；不追档只在决定被触碰时补。

| 档 | 信号 | 你做什么 | 在哪 |
| --- | --- | --- | --- |
| 立即 | 破前提 | 打开影响清单，逐项处理，处理完关闭 | 中台屏幕 |
| 立即 | 影响清单未清 | 同上 | 中台屏幕 |
| 立即 | 工作卡住 | 去 orca 看终端；答问或给权限；解决不了停会话，票上写卡点 | orca |
| 立即 | 同步异常 | `dt sync --check` 看计划，重试一次；还失败看服务日志 | 终端 |
| 立即 | 待关票记录过期 | 重新开 PR 后让 agent 重写记录；不做了就关票 | 中台、GitHub |
| 立即 | 缺待关票记录 | 让 agent 补记录；或 `dt issue close --force` | 中台 |
| 立即 | 关票 SHA 不符 | 确认后让 agent 按正确 SHA 重写记录 | 中台 |
| 立即 | 关票无法核对 | 检查 `gh` 登录；下一轮自动重试 | 终端 |
| 立即 | 关票写入失败 | 看服务日志；记录还在，下一轮重试 | 终端 |
| 收尾 | 覆盖缺口 | 判断要不要建票；要就让 agent 建，`covers` 指这句 | 中台屏幕 |
| 收尾 | 吃旧决定 | 改范围、关掉、重开或新建 | 中台屏幕 |
| 收尾 | 无主票 | 补 `derived_from` 和拆票理由；「未记录」不追 | 中台 |
| 收尾 | 无源决定 | 补 `source_ticket`；「未记录」不追 | 中台 |
| 不追 | 裸决定 | 决定被触碰或地图收尾时补一条前提 | 中台 |

## 只有你能做的动作

- 合并 PR。
- 建、推翻、作废决定。
- 影响清单逐项处理和关闭。
- 触发同步。
- 冒头判去向。
- 改 Destination、清雾。
- `dt issue close --force`。

其余动作归 agent 或自动流程：建当前票的子票、写评论、加前提、判前提、写关票记录；合并后由服务自动关票。

## 能跳过和能延后

判据一条：产生承诺或不可逆结果的步骤不能跳。

- 不能跳：合并 PR、确认决定、影响清单关闭、改 Destination。
- 可延后：同步（收工前）、补前提（决定被触碰或地图收尾）、文档补充（地图收尾）、信号清理（进 `to-spec` 前）。
- 可跳过：小改动的 grilling（按 one-shot 做）、没有信号时的屏幕巡检、合并后的手工关票。

## 结论变了怎么办

你发现旧结论不成立，或客观事实变了，当场说。agent 判前提已破，或你推翻、作废决定。影响清单自动打开，你逐项处理，处理完关闭。不在 PR 里临时改。

这是系统抓你认知变化的主路径。PR 评审只确认这次的决定陈述，不负责兜底你的想法变化。

## 多张图

一次只推一张执行图。当前顺序：

1. 中台 v1：决策看板，GitHub 做镜像（#139）收尾。
2. 工作区清理：旧流程文件、旧地图和 MAP 1 的去向（I-0013）清理，含客户需求地图（#1）内部部分和 53 张老票。
3. 客户侧新工作。

地图与票跟着运营者的认知一起更新（#117）和它的迁移票（#124）交给旧地图和它的迁移票退役（I-0015）退役，不单独推。

例外：任何图亮破前提或影响清单未清，立刻处理，不管当前主图。

清雾你做。平时新发现的雾先记进 `Not yet specified`；地图开放票清零或准备进 `to-spec` 时集中清。

## 环境分工

- 中台屏幕：看全局现状、信号和影响清单。
- orca：会话和终端，工作发生的地方，也是工作状态的来源。
- GitHub：只读镜像。你只在合并 PR 时打开。
- 终端 `dt`：屏幕做不了或要批量处理时用。
