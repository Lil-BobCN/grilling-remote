# 讲解：客户这三段怎么走，工厂怎么接

一句话：客户在网页上说清要什么，点一下确认，剩下的交给 Mac 上的工厂。你必点两次：补缺口、拆票。合并后你每天早上抽样，出事时被叫醒。

原型是 `prototype/index.html`，双击打开就能点。下面按幕讲，每一幕写三件事：客户看到什么、网页 agent 在做什么、工厂在做什么。

## 第一幕 开口

**客户看到**：一句提问「你这店，想让人在网上做什么？」，下面一个输入框。再下面三句例子、六个词：预约、问价、登记、库存、收款、其他。

**网页 agent**：把他这句话复述一遍，确认中心思想。然后开始问生意，一个问题都不碰技术。

**工厂**：不动。这时候还没有工单。

首屏放输入框，和你原来定的研究结论不一样。研究说卡片省力，那是针对「完全没想法」的人。你的客户多半心里有那件事，只是不知道怎么开口。给他一句话的机会，比让他从八个类型里认领一个更准。三句例子和六个词是兜底，他卡住时点一个，输入框里就有一句能改的话。

## 第二幕 只问生意

**客户看到**：左边一屏一问。每题三到五个能点的选项，答完上面收起、下面接着出。右边是双手机，前面是顾客看到的，后面是他的后台。每答一题，手机上的东西变一次。

问他五件事：给谁用、进来第一件事做什么、现在这件事怎么做、做完看到什么会说「对了」、有没有明确不要的。

**网页 agent**：用 grilling 的问法，一轮问清一件，每题带一个推荐。这一段一个技术词都不出现。

**工厂**：还是不动。

第 3 问答完，会弹一次「今天，和以后」。左边是他现在的做法，比如微信接龙；右边是做完之后的三步。这是让他知道自己买的是什么。功能清单他不一定看得懂，前后对比他一定懂。

右下角常驻一个「找人」。他卡住可以写一句留言，留言挂在草稿上，你手机同时响一下。

## 第三幕 选载体

**客户看到**：四张载体卡，微信小程序、公众号、网页、独立 App。每张写清好处、麻烦、大约多久。

选完，右边手机的外壳跟着换。接着问入口（扫码、发链接、搜得到）、要不要在线付钱、有没有现成东西要接。

「要不要在线付钱」这题他点「说不清」，网页给两张小图。一张到店再付，一张先在手机上付。看图比读字快。

**网页 agent**：把载体翻译成后果。「小程序不用下载，但要执照，审核一到三天。」不说「小程序生态」。

**工厂**：不动。

## 第四幕 技术选择

先问一句：你自己做过网站或小程序吗。三个选项：没做过、用过现成工具、有技术同事。三种人，后面的话不一样。

没做过的人，看到的是「下面的词你不用懂」。有技术同事的人，看到的是「你可以自己定，也可以交给我」。

然后三张卡：数据放哪、账号用谁的、每月愿意花多少。每张左边写好处，右边写麻烦。想不清楚就点最下面那个按钮：「你帮我定，交给运营者」。

**网页 agent**：只给推荐值，不替他拍板。

**工厂**：这三张卡的意思带进补缺口那一步，当推荐值，等你答。

## 第五幕 确认单

**客户看到**：五行大白话，加一条「不做」清单。点一行，右边手机上对应的块亮。每行都能改。

五行是：做什么、给谁用、怎么找到、怎么付钱、什么算成。

点「就按这个来」，服务器依次做三件事：建客户仓库、建工单、把需求写进仓库。调度器读到新单，经 Grok Bot 推你一条。建仓和建单的顺序不能反，票要挂在工单下面，两者得同仓。

## 第六幕 工厂接手

顶部切到「工厂视角」。上面一条工单，标题是客户那句话。中间六步流水线，最后加一步验收，一共七格：澄清、写规格、拆票、实现、评审、提 PR、验收。点一格，右边看输入、产出、谁负责。

每一步下面挂着技能标签，三种颜色：直接调、改造后用、条件触发。

再下面三块：一次性装好（新仓库开一次）、条件触发（非小需求用 wayfinder，术语摇摆用 domain-modeling，合并后抽样用 retro）、技术闸门。

闸门五条：技术栈、部署到哪、第三方账号、数据怎么存、每月花多少。客户第三段的意思显示在旁边，只当推荐。你不点，流程停在这里，24 小时提醒一次。

最下面是状态带：草稿、已确认、已进队列、等你定、开工、待验收、完成。点任一状态，看这一步的输入、产出、谁负责。

原型和正稿的差别，原型都没改：最后一格叫验收，正稿里这一格是合并与抽样。状态带里有「待验收」，正稿没有这个状态。闸门只画了五条，正稿的补缺口还有标了「你答」的题、合规、接缝、词汇表和查重。

## 第七幕 你出现的地方

**补缺口**：客户点确认、仓库和工单建好之后，你答一轮。五类技术选择、标了「你答」的题、合规、接缝、词汇表、查重，每项带推荐，你答「是」就过。你不回就停着，24 小时提醒一次。

**拆票后**：spec 和五张票写完，同一屏给你接缝、票单、每票的验收条件。点「按这个拆」才开工。这一下长期保留。

**做完后**：你不用点。每个 PR 一队验证 agent，合并前评审，过了工厂自己合主干，部署，客户收到地址。验证队和评审过不了的，当环境问题通知你。

**每天早上**：你抽样看前一天合进主干的单，读 /pr 正文和提交历史，先看单向门、影响范围大、验证没覆盖到的。发现问题先回滚，另开分支改。

**出事时**：同一个问题试了三圈还没好、花钱超过额度、碰到禁区。判据是这段改动能不能验证、出事能不能回滚。两条里有一条不成立，就停下来等你。还有两种：同类问题跨票出现两次，先加规则重跑，还不过就叫你；验证队和评审修了还是过不了。

## 两个变体

原型底下有个切换条，两种表达换着看。流程一样，只有右边预览不一样。

A 是双手机斜叠：前面顾客看到的，后面你的后台。B 是单手机，旁边一张常驻对照条，写清每一步现在怎么做、以后怎么做。
