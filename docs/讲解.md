# 讲解：客户这几段怎么走，工厂怎么接

一句话：客户把工作区 zip 解压，用本机 `dsh` 说清要什么，做完压缩上传。剩下的交给 Mac 上的工厂。你必点两次：补缺口、拆票。合并后你每天早上抽样，出事时被叫醒。

下面按幕讲，每一幕写三件事：客户看到什么、`dsh` 里的 agent 在做什么、工厂在做什么。客户那边的原话，样本见 `docs/客户侧流程样本.md`。

## 第一幕 打开

**客户看到**：官网下载 `客户工作区-v1.zip`。新建一个空文件夹，把 zip 放进去，解压到当前文件夹。文件列表里要能看到 `AGENTS.md`。用 `dsh` 打开这个文件夹，说「开始需求澄清」，或直接说「我想做一个……」。

**agent**：第一次打开，还没有 `.scratch/`，先自检。查 `docs/agents/issue-tracker.md`、`docs/agents/domain.md`、`.dsh/skills/` 在不在。缺一个，就说「文件没放对，按官网第 2 步重放」，然后停下，不问需求。三样都在，再讲第一段开场词，请客户说想做什么。

**工厂**：不动。这时候还没有工单。

多套一层文件夹时，根目录里没有 `AGENTS.md`，agent 读不到自检规则。这一种只能靠官网第 2 步的肉眼检查和客服。自检本身 2026-11-07 #26 实测过：缺 `docs/agents/` 或 `.dsh/skills/` 时，agent 报「文件没放对」并停下，不问需求。

## 第二幕 判断大小，定终点

**客户看到**：agent 说一句「你先说你想做什么」。客户说一段模糊的想法。agent 判断大小。小的说一声「这件事不大，今天就能问清楚」。大的说「已经确定需要拆分」，然后一次问一件，把终点问成一句话。客户自己答。

**agent**：小需求有三条标准：改动落在一个已有功能里，一个会话做得完，验收条件客户已经说清。三条全满足才算小。缺一条走拆分，拿不准也走拆分。小需求用 `grilling`（追问技能，一次问一件事）问清楚，写 `.scratch/{需求名}/需求草稿.md`。大的用 `grilling` 问出终点，写进 `map.md` 的 Destination。技术题旁加一句「这题偏技术，不懂就按我的推荐」。客户说不懂，按推荐答案往下问，记进 `pending.md`。对客户不说技能名。

**工厂**：还是不动。

第二幕和第三幕在第一次对话里一次走完。

## 第三幕 拆成票

**客户看到**：终点定了，agent 讲第二段开场词。一张议题代表一个任务，一次对话只定这一件事。最怕三件事：在一张议题里聊另一张的事；说着说着拐到别处；在后面的议题里悄悄改前面定过的事。拆完把清单给客户看：一共几张，每张做什么。顺序由客户定。每张开头写一句，这次是聊、看个样子、动手做，还是去查。

**agent**：写 `.scratch/{需求名}/map.md`，六段。每个决定一个文件 `issues/NN-任务名.md`，票头写 `Type:`（票型）和 `Blocked by:`（被谁挡着）。客户定完顺序，写进地图「接下来」的行序。再用 `next`（选票技能）选第一张，给出一行「继续：需求名 编号 票名」。

**工厂**：不动。

## 第四幕 一次对话一张票

**客户看到**：新开一次对话，把收尾给的那一行原样复制过来。agent 先说走到哪、这次做什么，再做这一张。做完三句话总结。看个样子的票，agent 做一个单文件 HTML 放进 `prototypes/`，客户双击就能开，看图说话，改两轮。

**agent**：客户发「继续：需求名 编号 票名」，就直接做那张。只发「继续」二字，由 `next` 选。开工先把票头 `Status:` 改成 `claimed`，按 `Type:` 调技能：聊用 `grilling`，看个样子用 `prototype`，我去查用 `research`，动手做用 `task`。客户没听懂，先换短话重讲，再举例子或给选项；答不了、要问别人，写一段能直接转发的话，票保持 `claimed`，答案带回来再写结论。写结论前用 `map-gate`（查冲突技能）：起一个没参与这段对话的子代理，读地图和全部票，查这次结论有没有推翻前面的结论。有冲突就问客户。客户说改，旧票加评论，地图标「已废，见第 N 张」，开放票改正文。查完在本票评论写一句「查过：……」。结论写一句能独立读懂的话，下一行写「产出文件：相对路径」。收尾用 `wrap-up`（收尾技能）列这次的新想法和冲突，新想法记到对应的票后面。最后 `next` 给出固定句：推荐下一张，带一行「继续：需求名 编号 票名」。

**工厂**：不动。

## 第五幕 回传

**客户看到**：全部做完，agent 先说文件核过了，再提醒客户压缩整个文件夹，到官网上传页登录后拖入，简称和邮箱由账号带出，勾「已问完」。然后等我们联系。文件夹里所有文件都会上传。对话记录在 `~/.dsh/sessions/`，不在工作区里，v1 不回传。

**agent**：不写 `meta.json`，不问简称。说上传之前，先核收尾检查：票都做完、验收场景有客户确认、客户原话和不做清单都在。核不过不让上传。

**工厂**：服务器读 `.scratch/`，看三样：勾了「已问完」，每张票都是 `resolved`，地图「接下来」为空。小需求改看 `Status: 已问完`。都满足才自动做三件事：建客户仓、建工单、把需求写进仓库。父工单五段从回传件读：客户原话看 `问答记录.md` 开头（小需求看 `需求草稿.md` 第 1 段），结论看 `map.md` 的 Decisions so far，验收条件看 `验收场景.md`，不做清单看 `Out of scope`，需求全文是整个 `.scratch/{需求名}/`。不满足只存快照，不建单。建仓和建单的顺序不能反，票要挂在工单下面，两者得同仓。调度器读到新单，经 Grok Bot 推你一条。

上传页和接收端点还没建，需求见 `docs/客户工作区方案.md` 第六节。Mac 和 Windows 右键压缩会不会带上隐藏的 `.scratch/`，没验证。

## 第六幕 工厂接手

这一幕讲原型页里的工厂视角，画面没改。

原型页顶部切到「工厂视角」。上面一条工单，标题是客户那句话。中间六步流水线，最后加一步验收，一共七格：澄清、写规格、拆票、实现、评审、提 PR、验收。点一格，右边看输入、产出、谁负责。

每一步下面挂着技能标签，三种颜色：直接调、改造后用、条件触发。

再下面三块：一次性装好（新仓库开一次）、条件触发（客户单非小需求用 wayfinder，术语摇摆用 domain-modeling，合并后抽样用 retro）、技术闸门。

闸门五条：技术栈、部署到哪、第三方账号、数据怎么存、每月花多少。客户答过的内容和 `pending.md` 里的推荐答案显示在旁边，只当推荐。你不点，流程停在这里，24 小时提醒一次。

最下面是状态带：草稿、已确认、已进队列、等你定、开工、待验收、完成。点任一状态，看这一步的输入、产出、谁负责。状态名沿用网页接单时的叫法，没按本机路线改。

原型和正稿的差别，原型都没改：最后一格叫验收，正稿里这一格是合并与抽样。状态带上的名字是原型里起的，正稿四档是 已提交、排队中、开发中、待验收，见 `docs/工单模型.md`。闸门只画了五条，正稿的补缺口还有标了「你答」的题、合规、接缝、词汇表和查重。

## 第七幕 你出现的地方

**补缺口**：回传校验通过、仓库和工单建好之后，你答一轮。五类技术选择、标了「你答」的题、合规、接缝、词汇表、查重，每项带推荐，你答「是」就过。客户说不懂的技术题，开工前也由你确认。你不回就停着，24 小时提醒一次。

**拆票后**：spec 和五张票写完，同一屏给你接缝、票单、每票的验收条件。点「按这个拆」才开工。这一下长期保留。

**做完后**：你不用点。每个 PR 一队验证 agent，合并前评审，过了工厂自己合主干，部署，客户收到地址。验证队和评审过不了的，当环境问题通知你。

**每天早上**：你抽样看前一天合进主干的单，读 /pr 正文和提交历史，先看单向门、影响范围大、验证没覆盖到的。发现问题先回滚，另开分支改。

**出事时**：同一个问题试了三圈还没好、花钱超过额度、碰到禁区。判据是这段改动能不能验证、出事能不能回滚。两条里有一条不成立，就停下来等你。还有两种：同类问题跨票出现两次，先加规则重跑，还不过就叫你；验证队和评审修了还是过不了。
