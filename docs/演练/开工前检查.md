# 开工前检查

> 状态：现行

一句话：每次全链演练开工前，按这张表逐项检查，结果贴进当次演练记录的开头。

## 怎么用

1. 把「清单」的表复制进当次演练记录。
2. 每项在「状态」列写「通过」或「不通过」，「证据或动作」列写命令、退出码或文件路径。
3. 第 6 项的验收场景条数用命令从包里数，实际条数写进记录。模板、执行书和记录都不写死条数。

## 清单

| # | 检查 | 状态 | 证据或动作 |
| --- | --- | --- | --- |
| 1 | 环境清场 |  | 演示仓没有 `Sandcastle` 标签；`~/.afkfactory/jobs.json` 没有遗留 stop；中台和 Orca 在线；与本次无关的残留列进记录的「已知残留」 |
| 2 | 调度器和 notifier 跑新代码 |  | 进程启动时间晚于最后一次相关提交；启动日志写出步骤、agent、管道三个上限 |
| 3 | token |  | PAT 能读；App 的 id、installation id、私钥都在；写权限用 scratch 仓验证，验完删临时分支 |
| 4 | helper |  | `sudo -n afk-product product-status` 返回正常；共享 Postgres 在跑；`check.sh --templates-only` 退出 0 |
| 5 | 通知 |  | 主 notifier 的 `orca_bot` 开着；控制台可作兜底 |
| 6 | 演练包 |  | 记下包路径；`unzip -l <包>` 数文件数；`unzip -p <包> 软件.md` 确认需求名；验收场景条数用下面的计数命令；票文件逐个确认 `Status: resolved`；`unzip -p <包> '.scratch/<需求>/map.md'` 确认「接下来」和 `Not yet specified` 两节为空 |
| 7 | 客户仓 |  | 目标仓不存在，本机也没有同名残留 |
| 8 | 账号 |  | 账号能登录，返回 `role=customer`；密码文件权限 600 |
| 9 | 基线和快照 |  | 演练前把 docker ps、worktrees、labels、jobs、env 键、中台状态、覆盖表存进基线目录 |
| 10 | 运营者声明 |  | 窗口开始和结束时间、这段时间不在 Mac 前、替身按执行书行动、除叫醒条件外不联系 |

开跑前必须满足：第 10 项的窗口声明写进记录。

### 第 6 项的计数命令

```sh
unzip -p <包> '.scratch/<需求>/验收场景.md' | grep -cE '^[0-9]+\. '
```

输出就是验收场景条数，原样写进记录。

## 记录里写什么

第 6 项写清包路径、文件数、需求名、验收场景条数（命令输出的数字）、票状态、地图两节是否为空。实际数字只写在记录里，执行书只说「按包内实际编号」。
