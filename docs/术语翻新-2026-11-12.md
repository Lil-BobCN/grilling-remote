## 全局例外

下面这些一律不改，不管命中哪个旧说法。

1. 路径和标识符：文件路径、目录名、分支名、字段名、命令、代码标识符、URL、标签名。例：`kind: ticket`、`board.db`、`workstate.json`、`events.jsonl`、`repoId`、`linkedIssue`、`split_reason`、`covers`。
2. 引用和原文：`素材/` 口播原文、`docs/research/` 引文、第三方 LICENSE、外部产品名（GitHub、微信、Orca、dsh 等）。
3. 历史记录：已关闭票评论里的四列表，表头、id、决定内容、编号不动。记录改名的句子保留旧名。
4. 生成文件：`docs/decisions.md`、`docs/decisions-archive.md` 不手改；`scripts/decisions` 的输出不动。
5. 别票负责的文件：`docs/agents/issue-tracker.md` 归 #153；`.claude/skills/` 下的旧流程技能归 #158。
6. `docs/archive/` 正文不改，只在文件开头加一句「旧说法，以根 `GLOSSARY.md` 为准」。
7. 固定词组：`决策组`、`决策图`、`决策看板`、`决策中台`、`影响清单`。
8. 通用词义不改：`状态`、`类型`、`关系`、`依赖`、`记录`、`内容`、`条件`、`理由`、`背景`、`来源`、`操作`、`判断`、`结论`、`界面` 等。只有明确指词表术语时才改。
9. 编号、链接、父子关系、阻塞边不动。票改名时，正文里引用它的地方同步改，链接 URL 不变。
10. GitHub 原生功能的界面叫法不改：sub-issue 叫「子任务」，issue 叫「议题」或「issue」，按 GitHub 自己的说法。
