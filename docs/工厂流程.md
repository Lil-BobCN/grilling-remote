# 这间工厂怎么运转

这份说明按「一天里发生什么」来写，不讲概念。看完你应该能回答：客户在哪一步、你在哪一步、机器在哪一步。

## 一句话

客户在网页上说清楚要什么，你的 Mac 自动把它做出来。你只在三个地方出现：开工前定技术选择、做完后点验收、出事时被叫醒。

## 五个地方，各管一件事

| 在哪 | 干什么 |
| --- | --- |
| 客户的浏览器 | 说需求、看图、点确认、看进度 |
| 服务器 | 存工单、开网页、把你该知道的事推到微信 |
| 你的 Mac | 真正干活的地方，跑 agent |
| GitHub | 工单和代码住的地方 |
| Orca | 你的窗口，看状态、点选择、批验收 |

## 一个真实订单走一遍

客户 B 开小超市，想做一个让街坊预约送货的系统。

**10:00** 他打开网页。首屏是八张卡片：我要预约、我要问价、我要登记、我要管库存……他点「我要预约」。

**10:01** 网页问：谁用这个系统？他点了「我的顾客」。问：一次能约几个时间段？他点了「上午、下午、晚上各一个」。问的问题一次只出一条，每条都带三到四个能点的选项。开头两题他不用打字，因为系统已经按「预约」这个类型替他填了三成。

**10:04** 问到「要不要在线付钱」，他停住了。他点了「我说不清，给我看图」。网页先给一段文字：你要的是街坊能自己选时间下单，你能看到当天要送哪些货。他点了「还是不确定」。网页出三个界面风格，一个有日历、一个有列表、一个只有两个大按钮。他挑了第二个。

**10:06** 他接着答题。中间有一次他卡住了，点了右下角的「找人」，写了一句「我不知道送货费怎么算」。这条留言进了工单，你的手机同时响了一下。

**10:12** 最后一页是确认单：「你要的是：街坊用手机选时间段下单；你能看到当天送货清单；不做在线支付；不做会员积分。」他点确认。

**10:12** 同一分钟，服务器做了四件事：建工单、建一个客户仓库、把需求书写进仓库、推你一条微信。

**10:13** 你手机响：`B 店 · 预约送货 · 已进队列`。

**10:13** 你的 Mac 上，调度器每三十秒读一次工单。它看到这张单该动了。先判断：这单要十个页面，走全套。然后它把这条单里要你定的技术选择列出来，推到 Orca 的「等你定」列。

**10:20** 你打开 Orca，看到三条：

- 服务器共用一台还是单独一台（推荐共用）
- 登录用手机号还是邮箱（推荐手机号）
- 要不要做在线支付（推荐先不做）

你点了三个推荐。

**10:21** 开工。写规格，拆成五张票，五个 Docker 容器同时跑。每张票写完，先跑一遍验证，把页面点一遍、截图、留 trace。再由另一个 agent 读这次的改动挑毛病。

**11:40** 五张票都过了。合到需求自己的分支，再合进主干。微信再响一次：`B 店 · 待验收`。

**11:41** 你在 Orca 里点开这条，看到截图、改动摘要、测试结果，点了通过。

**11:42** 客户那边状态变成「可以看了」。他打开你给的地址，试了两次下单。

**第二天** 他说送货清单要能导出 Excel。你在网页上给他开了张新单，回到 10:13 那一步。

## 你在三个地方出现

**开工前。** 定五类技术问题：技术栈、部署到哪、用哪些第三方服务、数据怎么存、要花哪些钱。每条都给三个带推荐的选项，你点一下就行。

**做完后。** 点通过或驳回。驳回就回到开发中，另开一条分支改，不重开单。

**出事时。** 三种情况必叫你：同一个问题试了三圈还没好、花的钱超过额度、碰到禁区。禁区的判据不是「这件事危险」，而是「这段改动能不能验证，出事了能不能回滚」。两个里有一个不能，就停下来等你。

## 机器什么时候自己往前走

它不看事件，只看现状。每三十秒读一遍所有工单，找出「该动但还没动」的，动它。

这样做的好处很实在。你电脑重启了，它接得上，因为状态记在工单里。不会同一个活干两遍，因为判断依据是现在什么状态。出问题也好查，你只要问一句「它为什么觉得这张单不该动」。

## 什么必须由人定，什么它自己定

**它自己定**：代码怎么写、用什么库、测试写多少、文件怎么分、变量叫什么。

**必须你定**：技术栈、部署环境、第三方账号、数据合规、花钱。

**必须客户定**：要做什么、给谁用、必须有什么、不要什么、怎么算做对了。

## 现在定到哪一步

已经定的：客户怎么答、工单怎么建、仓库怎么长、怎么判断走全套还是直接干、agent 怎么跑、PR 怎么合、半夜能不能合、什么必须叫你、钱怎么控、工作台用什么。

还没定的：服务器买哪台（等你租）、工作台第一屏长什么样。

## 三个还没验证的风险

一，Orca 认不认我们自己建的 worktree。如果它只认自己建的，「Orca 当看板」这件事就落空一半。

二，「你在 Orca 里回一句、客户网页能看到」这句话，前提是客户网页读的是同一条 issue 线程。这个前提还没验证。

三，一台 Mac 同时跑五个容器，会不会慢到不能忍。没测过。
