## 接口

路径和字段按 I-0035 的决定 D-0168、D-0169。前端 `site/src/api/account.js` 和 `site/src/pages/UploadPage.jsx` 不用改。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/app/api/health` | 占位服务和真实服务都有，回 `{ok, version}` |
| `POST` | `/app/api/login` | JSON `{email, password}`，成功回 `{user}` 并种 `afk_session` |
| `GET` | `/app/api/session` | 有会话回 `{user}`，没登录 401，账号停用 403 |
| `POST` | `/app/api/logout` | 204，清 Cookie |
| `POST` | `/app/api/uploads` | multipart `file`、`finished`，成功回 `{orders}` |
| `GET` | `/app/api/orders` | 只回自己的单 |
| `GET` | `/app/api/orders/{id}` | 不存在 404，不是自己的 403 |
| `GET` | `/app/api/admin/orders` | 只有 `role=admin` 能读，每单多 `customer`、`issue_url` 和 `messages` |
| `POST` | `/app/api/admin/orders/{id}/messages` | 只有 `role=admin`；JSON `{type, anchor}`，记「标记已发」 |

错误码：400 缺字段或 multipart 坏了；401 未登录；403 账号停用、不是同源、不是自己的单；404 订单不存在；413 超过 50 MB；415 不是 zip；422 路径穿越、解压炸弹、加密包、缺 `.scratch`、认不出软件；429 限速；5xx 服务端错误。

写请求查 `Origin` 或 `Sec-Fetch-Site`，同源才放行。Cookie 名 `afk_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`，线上加 `Secure`。客户 30 天，管理员 7 天。Cookie 里放账号 id、角色、密码哈希前 16 位和过期时间。每次请求重新查账号，停用立刻失效。

## 上传判序

1. 查登录态。没登录 401，账号停用 403。
2. 限速。同一账号 10 分钟 5 次，同一 IP 10 分钟 20 次。超了 429。
3. 收 multipart，只认 `file` 和 `finished`。`finished` 必须是 `true` 或 `false`。
4. 压缩包超过 50 MB 返回 413。不是 `.zip` 或 zip 打不开返回 415。
5. 子进程检查安全，见下表。命中任一条返回 422。
6. 找工作区根目录。规则按 D-0171：根目录有 `.scratch/` 通过；只有一个有效子目录且它有 `.scratch/` 也通过；找不到按四类给提示。
7. `.scratch/` 下没有需求目录返回 422。
8. 认软件。读工作区根目录 `软件.md` 的第一行当软件简称；没有这个文件、空文件、读不出名字时按没有处理。没有 `软件.md` 时，按 `.scratch/` 需求目录名里出现的 `customers.json.repos` 已知键回退；一个已知键都没有时按新软件处理，软件简称取需求目录名。新软件第一次上传带多个需求目录返回 422，不建单，日志记一条 error。软件简称和同一客户已有软件重名（大小写不区分），或对应的仓名 `<客户简称>-<软件简称>` 已属于另一个已知软件时，也返回 422。重名只和 `repos` 里已有的键比；建仓时 GitHub 重名按 D-0221 报运营者。
9. 检查勾选和内容，生成 `missing`。缺 `.scratch/` 不建订单；内容不全仍返回 200，建订单并把 `missing` 写进订单。
10. 写订单记录，订单记 `product`（软件简称）和 `requirement`（需求目录名）。转档写 `已收到｜收包`，通过写 `已收到｜校验`，不通过写 `校验未通过｜等补传`。同一客户、同一软件、同一需求重传沿用原订单号，不建第二张；不同软件或不同需求建新单。

失败包留在 `/data/uploads/<上传 id>/`，7 天后由启动清扫和定时清扫删掉。成功的包保留，等导入步骤拉走；导入和删除不在本票里。

## 工单评论与进度

订单文件里的 `transitions` 只到建单前。建单后的转档由调度器写在父工单评论里，每行以 `进度 v1｜` 开头。服务读工单状态和评论，按订单缓存 60 秒；读失败先用最近一次缓存，没有缓存就只返回订单记录里的转档。

- 工单地址写在订单的 `issue` 字段，写完整链接（`https://github.com/<owner>/<repo>/issues/<n>`），也可以写成 `{owner, repo, number}`。导入步骤还没实现，现有的单这个字段是 `null`，服务跳过读 GitHub。
- 读接口是 `GET /repos/{owner}/{repo}/issues/{n}` 和 `.../comments?per_page=100`。评论最多读 3 页，只取以 `进度 v1｜` 开头的行，时间用评论的 `created_at`。
- 父工单关闭，并且最后停在「待客户验收」时，服务补一行 `客户档：已完成`，时间用 `closed_at`。关票前没到过「待客户验收」的不补。客户页和管理视图都直接看拼接后的 `transitions`。
- 客户接口不返回 `messages`。管理接口才返回，客户页看不到发没发。
- `messages` 数组一条记 `{type, anchor, at}`。`type` 是 `校验未通过`、`待客户验收`、`满 24 小时`；`anchor` 分别是本次上传时间、轮次、最近一次通过校验的上传时间。同一类型、同一锚点只记一条。

相关环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 空 | 读客户仓工单用。空着就不读 GitHub，只显示建单前的转档 |
| `GITHUB_API` | `https://api.github.com` | 测试时指向假服务 |
| `GITHUB_TIMEOUT_MS` | 5000 | 单次 GitHub 请求超时 |
| `PROGRESS_CACHE_MS` | 60000 | 按订单缓存工单状态的时长 |

## 管理视图

`/app/admin` 是前端页面，调 `/app/api/admin/orders`。列客户、需求名、当前档、内部细阶段、停留天数、卡住、交付地址、小进度条、消息 / 工单。顶部三个数是进行中、该发消息、卡住，带对应筛选。页面只读，只有一个写动作「标记已发」。

「该发消息」在前端按三条规则算：校验未通过、待客户验收、从最近一次通过校验的上传算满 24 小时。锚点没变、标过已发就不再提示。点「标记已发」调 `POST /app/api/admin/orders/{id}/messages`，服务走订单文件唯一写入模块追加 `messages`，顺手提交并推送私有仓。

管理员账号没有命令行，直接在 `/data/customers/admins.json` 里写一条，密码哈希用 `auth.mjs` 的 `hashPassword` 生成。已有 `admins.json` 时先读出数组，把新行补进去，别整份覆盖：

```bash
cd /data/app/current
sudo -u afkapp node --input-type=module -e "
import { hashPassword } from './lib/auth.mjs'
console.log(JSON.stringify([{
  id: 'a-0001',
  email: 'you@example.com',
  display_name: '运营者',
  password_hash: await hashPassword('换成你的密码'),
  status: 'active',
  created_at: new Date().toISOString(),
  updated_at: new Date().toISOString(),
  disabled_at: null,
  disabled_reason: null,
}], null, 2))
"
```

写完重启服务，用这个邮箱和密码登录 `/app/admin`。

## 安全限制

| 项 | 默认 | 环境变量 |
| --- | --- | --- |
| 压缩包上限 | 50 MB | `MAX_UPLOAD_BYTES`，只给测试改小 |
| 条目数 | 20000 | `ZIP_MAX_ENTRIES` |
| 解压总量 | 512 MB | `ZIP_MAX_UNCOMPRESSED` |
| 单个文件 | 128 MB | `ZIP_MAX_FILE` |

拒绝的情况：条目名含 `..`、绝对路径、盘符开头；符号链接；加密条目；超上面三条上限。解压只解 `.scratch/`，其他文件不落盘，原始 zip 原样保存。

## 数据

| 文件 | 内容 |
| --- | --- |
| `/data/customers/customers.json` | 客户数组，字段见 `docs/客户白名单维护.md` |
| `/data/customers/admins.json` | 管理员数组，字段按 D-0168 |

| `/data/customers/orders/o-0001.sync-pending` | 推送私有仓失败的待办，后台每分钟补寄一次，成功后删掉 |
| `/data/uploads/<上传 id>/package.zip` | 回传件快照 |
| `/data/uploads/<上传 id>/meta.json` | 这次上传的 SHA256、状态、需求、订单号 |

订单文件只由 `backend/lib/orders.mjs` 写：先加文件锁，写临时文件再原子替换，然后提交并推送私有仓。`/data/customers` 不是 Git 仓库时跳过同步，只写磁盘。

推送失败时，订单目录多一条 `<订单号>.sync-pending`，记订单号、需求名、第一次失败时间、最近一次尝试和失败原因。服务每分钟拿这些待办重试一次推送，成功就删掉待办。待办超过 10 分钟还没清掉，积压期间每次重试都记一条 error，带订单号、开始时间和失败原因；`deploy/backend/check.sh` 查近 15 分钟的日志，命中就判巡检失败。待办文件不提交、不推送，私有仓里看不到。

## 客户白名单命令行

在服务器上用 `afkapp` 跑，否则文件属主会变：

```bash
sudo -u afkapp node /data/app/current/bin/customer.mjs add \
  --short-name acme --display-name "Acme 老板" --email boss@acme.example
```

命令会要求输两遍密码，不回显，写完打印 `c-0001`。其他命令：`list`、`show`、`disable --reason`、`enable`、`change-email`、`reset-password`。脚本里用 `--password-stdin` 从标准输入读密码。

密码用 argon2id 存哈希。Cookie 里的版本取哈希前 16 位，换密码、停用后旧会话立即失效。

## 部署和回滚

打包、传输、发布和 `docs/archive/合并前-2026-11-16/后端服务部署.md` 一样，只是源目录换成 `backend/`：

```bash
bash deploy/backend/package.sh backend 1.0.0
ssh dev@<服务器地址> 'cat > /tmp/afkapp-1.0.0.tgz' < output/afkapp-1.0.0.tgz
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/deploy.sh /tmp/afkapp-1.0.0.tgz 1.0.0'
```

回滚不变：

```bash
ssh -t dev@<服务器地址> 'sudo bash /data/app/bin/rollback.sh'
```

上线前确认三件事：`/data/customers` 已建好并能被 `afkapp` 读写；`/etc/afkapp/app.env` 填了 `SESSION_SECRET`；Caddy 的 `/app/api/*` 仍反代到 `127.0.0.1:8787`。

`SESSION_SECRET` 没填时服务会用临时密钥启动，日志里有一条警告。登录能用，但服务重启后所有人要重新登录，线上不要这样跑。
