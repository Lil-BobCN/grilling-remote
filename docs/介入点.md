# 你在这套流程里出现的地方

一句话：一单从头到尾，你必点两次，特大单的前五单加一次。另有每天早上抽样一次，不属于哪一单。其余时间它自己跑。

> 2026-11-03 按 `docs/工厂流程.md` 重写。上一版写的是五次动手，其中一次是待验收点通过。正稿改成验证队和评审都过了就由工厂自己合，你每天早上抽样，所以这一次取消。

必点的两次是补缺口（C1）和拆票（C4），不点工厂就停在原地。客户留言回一句，不卡工厂，但客户在等。出事不算计划内。

两条只要知道、不用动手：

- 客户点确认，单子进队列。这条是让你知道有活来了。
- 客户勾了「急」，插到队首，同时推你一条。

工厂自己合主干时要不要推你一条，正稿没写，见「还没定的」。

## 各自看什么

### 一、补缺口：一次列完，逐项答「是」

客户点完确认，仓库和工单建好。A2 第一轮之后，系统已经判过分流，你在这里复核。形式和客户那边一样，是一轮 grilling。每项带推荐答案，措辞让你答「是」就等于接受。

这一轮里要你定的有七类：

1. 分流复核。小单跳过 spec 和拆票，直接实现。大单走全套。特大单走 wayfinder。
2. 五类技术选择：技术栈、部署到哪、第三方服务与账号、数据怎么存、每月花多少。客户的答案当推荐值。
3. A2 里标了「你答」「你最后定」的题。
4. 合规：收不收个人信息，接不接支付。默认都不。
5. 接缝：测试打在哪一层，理想数量是一个。无人值守时没有客户可问，由你代答。
6. 词汇表：客户的词写进客户仓 `GLOSSARY.md`，你确认命名。
7. 查重：先搜 open 和 closed 工单。

agent 能查到的事实，它先查完，不推给你。点在工作台里，不在微信里回。微信只负责叫你。

不回就停在「等你定」，每 24 小时提醒一次，它不猜。猜错了返工更贵。

这一步估计约三分钟，没实测。

### 二、特大单：开图前点一次头

分流看三个信号：客户肯不肯「第一版只做一条主流程」；第一轮之后，互相独立的大块有几个；本会话已用的上下文有多大。三个信号是推断，没验。

判成特大单，一个会话装不下，走 wayfinder，只出决策，不出代码。前五单，开图之前你点一次头。前五单之后还要不要点，正稿没写。

### 三、拆票：扫一眼就点

写 spec 和拆票都由机器做，做完给你一屏：接缝、票单、每票的验收条件。

点「按这个拆」，或者改一条再点。这是视频里「人批准拆分」那一步。前五单保留这一下，数你改了几次，再定长期留不留。

这一步估计约两分钟，没实测。

### 四、客户卡住：回一句就够

客户在网页右下角点「找人」，写一句「送货费怎么算，我不敢写」。这条留言挂在草稿上，你的手机当场响。客户点确认建单时，留言一起写进工单，不丢。

你在 Orca 里回一句，客户网页能看到。这个能力是 #15 里「四个必需动作」之一。

这一步不阻塞工厂。他不回你，单子也照样往下走，只是答案会缺一块。

### 五、每天早上抽样：合并之后看

工厂合主干之前，每个 PR 有一队验证 agent，没写过这份代码，像真实用户那样点来点去找回归。合并前还有一次评审，分标准和 spec 两轴。两样都过了，工厂自己合主干，部署，客户收到地址。你不用点。

你每天早上看前一天合进主干的单：

1. 读 /pr 正文和提交历史，不逐行读 diff。
2. 先看单向门、影响范围大、验证没覆盖到的。「人工判断」条目写在 PR 正文里，也先看。
3. 看模式，不看单个。一个 agent 走捷径是个案。多个 agent 走同一条捷径，就改环境。
4. 发现问题：先回滚，另开分支改，不重开单。记一条：这次的错，本该在哪一层被挡住。

### 六、出事：只有五种情况会叫你

- 同一张票试了三圈还没进展。
- 花的钱超过额度。
- 碰到禁区。判据是两句话：这段改动能不能验证，出事了能不能回滚。有一条答不能，就停。
- 同类问题跨票出现两次，它先自动加一条规则重跑，还不过就叫你。新规则要在出错那次的改动上亮红灯，做不到就不自动加，直接叫你。
- 验证队和评审修了还是过不了。当环境问题，停这条线，通知你，附现象和试过的办法。你修环境，不替这个 PR 改结论。

你到了现场，能做的三件事：让它再试一次、换个做法、或者停掉等白天。

## 一天里，你出现几刻

拿 `docs/工厂流程.md` 里那单 B 店举例。钟点是示意，没有实测。

**10:04** 服务器建单、建仓，微信响：`B 店 · 预约送货 · 已进队列`。这条不用动。

**10:20** 你打开 Orca，补缺口。每项带推荐。这单撞上三件：服务器共用还是单独、登录用手机号还是邮箱、要不要在线支付。你答三个「是」。估计三分钟。

**10:22** spec 和五张票写完。

**10:24** 你扫一眼票单，点「按这个拆」。估计两分钟。

**10:25** 调度器开工，先跑一单。之后一小时你在干别的。

**11:40** 四样证据齐，子票合进需求分支。你不用动。

**11:41** 验证队和评审都过了，工厂自己合主干，部署。你不用动。

**11:42** 客户收到地址。

**第二天早上** 你抽样看前一天合进主干的单。客户要加导出 Excel，开新单，回到 10:20。

如果中间没出事，这单你一共花了约五分钟，另加每天早上的抽样。

## 什么永远不自动

三条边界。

第一，五类技术问题不自动猜。理由很实在：猜错了返工，返工比等你贵。

第二，验证队和评审过不了的 PR，不自己合，也不自己放宽检查。放宽任何一道检查，要验证者的证明，再由你复签。

第三，涉及钱、数据、对外动作的业务参数，不当假设处理，要阻塞等客户答。其余可逆的参数，agent 写成「假设」并标记，客户事后在进度页点确认。（推断）

## 还没定的

- 状态标签怎么映射，还没定（#5 的 Q4）。所以待办这一列现在是用看板列拼的，不是标签驱动。列怎么命名、怎么随状态变，也还没定。
- 工作台第一屏长什么样，还没定（#14 开着）。你知道有事，但点开先看到什么，没有答案。
- 手机端 Orca 没有看板页（#15 记的限制）。你在外面只能收到微信，点不了。
- 工厂自己合主干时，要不要推你一条。地图 #11 原来要求合并前推一条，不能不让你知道。正稿 E1 改成自己合，没写通知。
- 每天早上抽样，要不要有提醒。
- 特大单前五单之后，开图前那一下点头留不留。

## 和视频比，人在哪

视频默认 spec 和票都经人看过。拆票技能里写着「迭代到用户批准拆分为止」。然后人看 PR，抽空跑 retro。

我们把人挪到前后两头。前面是补缺口和拆票，特大单再加开图前一下。后面是每天早上抽样。中间不出现。

挪的理由有两个。客户不懂技术，spec 和票没法让他批，只能你扫一眼。合并照素材：每个 PR 一队验证 agent，合并前评审，过了自己合，人在合并之后看模式，不看单个。

PR 里那层「这一改有多险」的信息，补成两栏：单向门还是双向门、影响范围。见 `docs/工厂流程.md` 八节 E1。单向门不再让工厂停下，它决定你抽样先看哪些。
