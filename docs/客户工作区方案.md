## 一、客户怎么走

1. 官网下载 `客户工作区-v1.zip`。
2. 新建空文件夹，把 zip 放进去，解压到当前文件夹。解压后文件列表里要能看到 `AGENTS.md`。看不到，就是多套了一层，把里面的东西拖出来。
3. 先在 dsh 的 设置 → 模型 里填好 DeepSeek API key，再用 dsh 打开这个文件夹，说「开始需求澄清」，或直接说「我想做一个……」。key 在 `https://platform.deepseek.com/` 申请，按用量计费。
4. 每次对话做一张票。收尾时 agent（智能体）给一行「继续：tanxin-yuyue 01 空档怎么放」。客户新开对话，原样复制发出去。
5. 全部做完，agent 先按追踪器文档的「全部做完后的清雾」清一遍，再按「收尾与回传」核七项。核过了，再提醒客户压缩整个文件夹，到官网上传页登录后拖入，简称和邮箱由账号带出，勾「已问完」。小需求也核，看 `需求草稿.md` 的 `Status: 已问完`、「复核：」一行和 `验收场景.md`。

没有提示词①，没有装配步骤。第一次打开由 agent 自检。

客户多套一层文件夹时，不留兜底提示词。靠官网第 2 步的肉眼检查，再靠客服。

## 二、包里放什么

zip 内容直接放在根目录，外面不套文件夹。

```text
AGENTS.md
README.txt
技能清单.md
LICENSE
NOTICE.md
docs/agents/issue-tracker.md
docs/agents/domain.md
.dsh/skills/
├── grilling/
├── domain-modeling/
├── grill-with-docs/
├── wayfinder/
├── prototype/
├── research/
└── wait-what/
```

规则：

- `AGENTS.md` 是成品，不是模板。标题下加一行 `工作区版本：v1（构建日期）`。
- `docs/agents/` 两份直接提交成品，构建时不跑 `setup`。已确认源文件里已经是中文的 `## 评论`、`## 结论`，不用改名。
- 不放 `setup`、`ask-matt`、`.scratch/`。`.scratch/` 由 agent 在客户第一次说需求时建。
- `技能清单.md` 由 `manifest.json`（技能清单数据源）生成，官网清单用同一份。
- `README.txt` 里装配和重开的话要删，换成解压和打开的三步。

四个位置各有主人（2026-11-07 按 #39）。词表放根目录一份，只放词义，不放规则。

| 文件 | 谁写 | 谁读 |
| --- | --- | --- |
| `AGENTS.md` | 我们，随 zip 预装 | `dsh` 每次新会话注入给 agent |
| `GLOSSARY.md` | 客户侧 agent，定词义时写 | agent 每次开工；运营者回传后 |
| `docs/agents/*` | 我们，随 zip 预装 | agent 只读，查追踪器和领域读法 |
| `.scratch/` | 客户侧 agent，写地图、票、草稿、`pending.md`、问答记录、验收场景、研究、原型、问题树 | agent 读写；运营者回传后读 |

`.dsh/skills/` 同 `docs/agents/`：我们写，agent 读。这三样客户和 agent 都不改，要改由我们出新 zip。客户侧只写 `.scratch/` 和词表。`GLOSSARY.md` 不预装，第一个词定下来时才建。

## 三、agent 靠什么执行

旧做法：客户粘提示词①，agent 在客户机器上把文件写出来。新做法：文件已经摆好，agent 只读。

| 流程 | 靠什么 | 变化 |
| --- | --- | --- |
| 第一次用之前 | `customer-kit/安装步骤.md` 的「配模型 key」和包内 `README.txt` | 新增；客户自己申请和填写 DeepSeek API key |
| 第一次打开 | `AGENTS.md` 的自检 | 新增 |
| 开场词、评估、定终点、建地图 | `AGENTS.md` 加 `grill-with-docs`、`wayfinder` | 文字照 #44 改 |
| 每次开工 | `AGENTS.md` 的「继续：」规则和追踪器文档的「选票」 | 取代 `next` |
| 做票 | `AGENTS.md` 和追踪器文档写四类票做法；不另起子代理查冲突 | 取代 `map-gate` |
| 写结论前 | 客户的话明显推翻前面定过的内容时，按 `AGENTS.md` 的「改前面定过的结论」处理 | 取代 `map-gate` |
| 收尾 | `AGENTS.md` 的会话结尾，Agent 自己说四句并给继续行 | 取代 `wrap-up` |
| 全部做完 | 先清 `Not yet specified`，再按追踪器文档的「收尾与回传」核七项 | 取代 #44 的回传四步；先核文件，再让客户上传 |

模型靠 description（技能的触发说明）决定调不调技能，可能漏掉。所以规则写成 `AGENTS.md` 里的硬规则。这是合理推测，靠现行客户包测试记录验。

`AGENTS.md` 新增六处：

1. 版本行。
2. 第一次自检。没有 `.scratch/` 时，不管客户先说什么，先查 `docs/agents/issue-tracker.md`、`docs/agents/domain.md`、`.dsh/skills/` 在不在。缺任何一个，就说「文件没放对，按官网第 2 步重放」，然后停下，不问需求。通过后再讲第一段开场词。
3. 选票和改旧结论：
   - 每次开工：按「继续：」一行核对票；只发「继续」时按追踪器文档的「选票」规则选，有 `Status: claimed` 的票先接着做。
   - 写结论前：不另起子代理查冲突。客户的话明显推翻已经定过的内容时，按「改前面定过的结论」一节处理。
   - 收尾：Agent 自己说四句，给继续行，不跑子代理。
4. 「继续：」规则。第一句以「继续：」开头，且需求名和编号都对得上某张票，就直接做那张，不再自己选。只发「继续」二字，按追踪器文档的「选票」规则选。需求名或编号对不上，或那张票被挡着，按现有跳步规则处理。
5. 一个工作区一个软件，见第八节。
6. 会话结尾：前三句不变，第四句是 `AGENTS.md` 固定句里的继续行。

2026-11-13 I-0074 补单票规则：开工先把票头 `Status:` 改成 `claimed`，按 `Type:` 调对应技能；`## 结论` 写一句能独立读懂的话，下一行写「产出文件：相对路径」，`Status:` 改 `resolved`，删 `Blocked by:`，地图 Decisions so far 只抄这一句。客户没听懂或答不上来，按 `AGENTS.md` 的「客户没听懂或答不上来」一节：先重讲，再举例或给选项；要看样子才能定的不现场做原型，仍按被动规则；客户答不了、要问别人，写一段能直接转发的话，票保持 `claimed`；技术题记 `pending.md`，等运营者确认。其中 `map-gate` 的写结论前查冲突步骤已被 I-0081 的 D-0133 取消；小需求收尾的「复核：查过」仍在。规则落在 `AGENTS.md` 和追踪器文档。

### 2026-11-07 三技能设计（历史，已作废）

共同规则：

- 照 `.claude/skills/next`、`map-gate`、`wrap-up` 的步骤改，数据源换成 `.scratch/{需求名}/map.md` 和 `issues/*.md`。不读 GitHub，不用 `gh`，不写 issue 评论。
- 阻塞读票头的 `Blocked by:` 和 `Status:`，不读 GitHub 的阻塞边。
- 去掉 `disable-model-invocation: true`。description 写触发时机：「每次开工前用」「写结论前用」「每次收尾用」。
- 不直接拷贝运营者版。运营者版不动。
- 对照主干 78bd6f4 的运营者版：`wrap-up` 从三类扩成五类，`map-gate` 多读关闭评论里列的文件。客户版取简化版，见下面各节。

#### next（选票，历史）

- 阶段一：票拆好、客户定完顺序后。取地图「接下来」里第一张没被挡、没人领的。
- 阶段二：一张票做完，`map-gate` 和 `wrap-up` 都跑完后。取下一张没被挡的。
- 第一次还没有地图：不选票，直接问客户想做什么。
- 全部做完：不推荐票，先照追踪器文档的「收尾与回传」核一遍，核过才说回传的下一步。小需求没有地图，不走 `next`，收尾时也核一遍，再说上传。
- 固定句由 `next` 输出。`AGENTS.md`、`wrap-up`、流程样本里不再各写一份。

固定句草稿。阶段一把第一行换成「议题拆好了，顺序按你定的。第一张是 01 空档怎么放。」

> 这张定下来了。下一张建议做 02 学生看到和填写什么，它没有被别的议题挡着。
>
> 请新开一次对话，把下面这一行复制过去发给我：
>
> 继续：tanxin-yuyue 02 学生看到和填写什么

固定句里不出现技能名。

#### map-gate（写结论前查冲突，历史）

- 起一个没参与这段对话的 subagent（子代理，独立上下文的查证助手），读地图、全部票，加上各票 `## 结论` 下「产出文件」列的文件，列出这次结论和前面哪句冲突。开头标了「已被第 N 张取代」的文件，不当成现行。
- 起不来，自己重读文件。不卡客户，也不对客户提子代理。
- 有冲突就问客户。客户说改：旧票加评论，地图标「已废，见第 2 张」，开放票改正文。
- 文件矛盾（2026-11-07 运营者定）：每张票 `## 结论` 下有一行「产出文件：相对路径」，算写它的那张票。旧文件被新结论推翻时，在旧文件第一行加「已被第 N 张取代」。agent 不移动，不删除客户的文件。范围只在 `.scratch/{需求名}/` 内：`research/`、`prototypes/`、`pending.md`、`需求草稿.md`。
  - 词表例外：根目录 `GLOSSARY.md` 不算旧文件。改词原地改，不加「已被第 N 张取代」，在改词的那张票里记一句。词表和新结论相反时，照样问客户。
- 查完在本票 `## 评论` 写一句，三种写法：
  - 查过：和前面没有冲突
  - 查过：和第 N 张冲突，客户选择改第 N 张
  - 查过（自查）：……，用在子代理没起来时

#### wrap-up（收尾列新想法，历史）

- 起带整段对话的子代理，列四件事：这次出现的新想法、和旧结论冲突的地方、做了别张票的活的越界产出、对不上的先后。
- 起不来，自己重读对话和文件。
- 新想法记到对应的票后面，再对客户说一句，例如「这次多了一个想法，我记到第 5 张后面了」。
- 越界产出取简化版（2026-11-07 运营者定）。这次对话里做了别张票的内容，比如做第 1 张时顺手出了第 3 张的原型，agent 自己处理，不给客户出表。在那张票的 `## 评论` 记一句「这张的一部分已在第 N 张做过：……」，并在地图「接下来」那行改一笔。对客户只说一句。只有成果已经把另一张票的答案定死时，才问客户「认这个方向吗」。
- 阻塞边只查一处：票头 `Blocked by:` 和地图「接下来」里「等 03」是否一致。不一致时以票头为准改地图，并对客户说一句。这一条是我按运营者版改的，运营者没单独点过。
- 文件矛盾由 `map-gate` 查，这里不重复。

三个客户版技能已写在 `customer-kit/package/.dsh/skills/`，对照主干 78bd6f4 的运营者版做了取舍。没有实测。

### 问题树（2026-11-07 按 #30 新增）

每个需求一份 `.scratch/{需求名}/问题树.md`，记题和题的依赖。格式和字段见 `docs/adr/0007-问题树单独存一份.md`。

- 2026-11-07 #26 实测：客户侧 agent 会照规则登记，编号、依赖、状态都对，出处能对上 `问答记录.md` 和 `pending.md`。重判归运营者侧 `question-tree`，用真实回传包另测。`question-tree` 用一张五题的模拟问题树试跑了两次，覆盖三堆视图、改一条后沿边重算、只核实、坏数据停下，主线都走通。第一次报出 16 处说明没写清，第二次报出 13 处，都已改说明。第二次改后的说明按运营者说法不再重跑。

| 做完怎么判 | 客户侧先按追踪器文档的「收尾与回传」核七项，包括验收场景、客户原话、不做清单、未定事项。服务器再看到三样：勾了「已问完」，每张票都是 `resolved`，地图「接下来」为空。小需求看 `Status: 已问完`。不满足只存快照，不建单 |
| 包里多出的文件 | 例如原 zip。服务器只读 `.scratch/`，其余原样存档，不校验 |
| 保存 | 导入完成就删，失败留 7 天。长期存档在运营者 Mac 的 `inbox/`；客户拿到地址和 zip 就算交付，交付后手动删，不设自动清理 |

| 隐私提示 | 上传页和教程各一句：文件夹里的所有文件都会上传，请只放本项目的资料 |

### 回传件怎么变成父工单五段

父工单的格式见 `docs/工单模型.md`。回传件里的来源固定：

| 父工单段 | 从哪读 |
| --- | --- |
| 客户原话 | 走地图：`问答记录.md` 开头的 `## 客户原话`；小需求：`需求草稿.md` 第 1 段第一条 |
| 客户确认的结论 | 走地图：`map.md` 的 `## Decisions so far`，取冒号后面那句，链接不抄；小需求：`需求草稿.md` 第 3 段「已经定下的」 |

| 不做清单 | 走地图：`map.md` 的 `## Out of scope`；小需求：`需求草稿.md` 第 5 段。没有写「无」 |

## 七、官网要什么

- 下载页：下载按钮，版本、日期、SHA256（文件校验值）。SHA256 可只给客服看。
- 清单页：由 `manifest.json` 生成。
- 三步图：下载，解压到空文件夹，用 dsh 打开并说一句话。第 2 步加那句肉眼检查。
- 上传页：登录后上传，简称和邮箱由账号带出；保留「已问完」勾选和隐私提示。简报原写「上传页不改」，这条要改。
- 教程页归 #31，「第一次对话会遇到什么」一节归 #58，发布归 #35。
- 静态页放本仓库 `site/`，和 `manifest.json` 同源，部署到 #7 那台服务器。上传接收端点另开仓库。
- 本次实现只交 zip、`manifest.json` 和生成出来的清单，不写页面代码。

## 八、一个工作区一个软件

- 一个工作区只做同一个软件。可以有多个需求，也可以在已有软件上开新功能。
- 新想法出现时，agent 先问一句：这是接着做同一个软件，还是另一个软件。
- 同一个：在同一个工作区新建需求目录。
- 另一个：请客户再解压一份到新文件夹。
- 客户说两个需求要合成一个软件：现在没有规则，先照客户的话记进 `map.md` 的 `Not yet specified`，告诉客户「这条我记下了，开工前会有人确认」。
