# 客户工作区方案

日期：2026-11-07
状态：草案，等运营者审。这是方案，不是决定记录。
依据：`docs/客户工作区改版简报.md`，加上 2026-11-06 到 11-07 的逐题问答。简报本身不改。

官网改发一个摆好的工作区 zip。客户解压后用 dsh（DeepSeek Harness，客户用的桌面智能体软件）打开，说「开始需求澄清」就开始。做完后压缩整个文件夹，传到官网上传页。

## 一、客户怎么走

1. 官网下载 `客户工作区-v1.zip`。
2. 新建空文件夹，把 zip 放进去，解压到当前文件夹。解压后文件列表里要能看到 `AGENTS.md`。看不到，就是多套了一层，把里面的东西拖出来。
3. 用 dsh 打开这个文件夹，说「开始需求澄清」，或直接说「我想做一个……」。
4. 每次对话做一张票。收尾时 agent（智能体）给一行「继续：tanxin-yuyue 01 空档怎么放」。客户新开对话，原样复制发出去。
5. 全部做完，agent 提醒客户压缩整个文件夹，到官网上传页拖入，填客户简称和邮箱，勾「已问完」。

没有提示词①，没有装配步骤。第一次打开由 agent 自检。

客户多套一层文件夹时，不留兜底提示词。靠官网第 2 步的肉眼检查，再靠客服。

## 二、包里放什么

zip 内容直接放在根目录，外面不套文件夹。

```text
AGENTS.md
README.txt
技能清单.md
LICENSE
NOTICE.md
docs/agents/issue-tracker.md
docs/agents/domain.md
.dsh/skills/
├── grilling/
├── domain-modeling/
├── wayfinder/
├── prototype/
├── research/
├── wait-what/
├── next/
├── map-gate/
└── wrap-up/
```

规则：

- `AGENTS.md` 是成品，不是模板。标题下加一行 `工作区版本：v1（构建日期）`。
- `docs/agents/` 两份直接提交成品，构建时不跑 `setup`。已确认源文件里已经是中文的 `## 评论`、`## 结论`，不用改名。
- 不放 `setup`、`ask-matt`、`.scratch/`。`.scratch/` 由 agent 在客户第一次说需求时建。
- `技能清单.md` 由 `manifest.json`（技能清单数据源）生成，官网清单用同一份。
- `README.txt` 里装配和重开的话要删，换成解压和打开的三步。

## 三、agent 靠什么执行

旧做法：客户粘提示词①，agent 在客户机器上把文件写出来。新做法：文件已经摆好，agent 只读。

| 流程 | 靠什么 | 变化 |
| --- | --- | --- |
| 第一次打开 | `AGENTS.md` 的自检 | 新增 |
| 开场词、评估、定终点、建地图 | `AGENTS.md` 加 `grilling`、`wayfinder` | 文字照 #44 改 |
| 每次开工 | 触发句，用 `next` | 新增 |
| 做票 | `AGENTS.md` 加各类型技能 | 不变 |
| 写结论前 | 触发句，用 `map-gate` | 取代旧的「写结论前查漏」 |
| 收尾 | 触发句，先 `wrap-up`，再 `next` | 新增 |
| 全部做完 | `AGENTS.md` 会话结尾 | 取代 #44 的回传四步 |

模型靠 description（技能的触发说明）决定调不调技能，可能漏掉。所以触发写成 `AGENTS.md` 里的三句硬规则。这是合理推测，靠验收第 3 条测。

`AGENTS.md` 新增六处：

1. 版本行。
2. 第一次自检。没有 `.scratch/` 时，不管客户先说什么，先查 `docs/agents/issue-tracker.md`、`docs/agents/domain.md`、`.dsh/skills/` 在不在。缺任何一个，就说「文件没放对，按官网第 2 步重放」，然后停下，不问需求。通过后再讲第一段开场词。
3. 三句触发：
   - 每次开工：先用 `next` 看下一张。
   - 写 `## 结论` 前：先用 `map-gate` 查这次结论有没有推翻前面的结论，查完在本票 `## 评论` 写一句「查过：……」。
   - 收尾：先用 `wrap-up` 列这次的新想法、越界产出和冲突。
4. 「继续：」规则。第一句以「继续：」开头，且需求名和编号都对得上某张票，就直接做那张，不再自己选。只发「继续」二字，由 `next` 选。需求名或编号对不上，或那张票被挡着，按现有跳步规则处理。
5. 一个工作区一个软件，见第八节。
6. 会话结尾：前三句不变，第四句换成 `next` 输出的固定句。

## 四、三个新技能

共同规则：

- 照 `.claude/skills/next`、`map-gate`、`wrap-up` 的步骤改，数据源换成 `.scratch/{需求名}/map.md` 和 `issues/*.md`。不读 GitHub，不用 `gh`，不写 issue 评论。
- 阻塞读票头的 `Blocked by:` 和 `Status:`，不读 GitHub 的阻塞边。
- 去掉 `disable-model-invocation: true`。description 写触发时机：「每次开工前用」「写结论前用」「每次收尾用」。
- 不直接拷贝运营者版。运营者版不动。
- 对照主干 78bd6f4 的运营者版：`wrap-up` 从三类扩成五类，`map-gate` 多读关闭评论里列的文件。客户版取简化版，见下面各节。

### next（选票）

- 阶段一：票拆好、客户定完顺序后。取地图「接下来」里第一张没被挡、没人领的。
- 阶段二：一张票做完，`map-gate` 和 `wrap-up` 都跑完后。取下一张没被挡的。
- 第一次还没有地图：不选票，直接问客户想做什么。
- 全部做完：不推荐票，改说回传的下一步。小需求没有地图，不走 `next`，收尾仍说「这份问完了，等我们审」。
- 固定句由 `next` 输出。`AGENTS.md`、`wrap-up`、流程样本里不再各写一份。

固定句草稿。阶段一把第一行换成「议题拆好了，顺序按你定的。第一张是 01 空档怎么放。」

> 这张定下来了。下一张建议做 02 学生看到和填写什么，它没有被别的议题挡着。
>
> 请新开一次对话，把下面这一行复制过去发给我：
>
> 继续：tanxin-yuyue 02 学生看到和填写什么

固定句里不出现技能名。

### map-gate（写结论前查冲突）

- 起一个没参与这段对话的 subagent（子代理，独立上下文的查证助手），读地图、全部票，加上各票 `## 结论` 下「产出文件」列的文件，列出这次结论和前面哪句冲突。开头标了「已被第 N 张取代」的文件，不当成现行。
- 起不来，自己重读文件。不卡客户，也不对客户提子代理。
- 有冲突就问客户。客户说改：旧票加评论，地图标「已废，见第 2 张」，开放票改正文。
- 文件矛盾（2026-11-07 运营者定）：每张票 `## 结论` 下有一行「产出文件：相对路径」。旧文件被新结论推翻时，在旧文件第一行加「已被第 N 张取代」。agent 不移动，不删除客户的文件。范围只在 `.scratch/{需求名}/` 内：`research/`、`prototypes/`、`pending.md`、`需求草稿.md`。
- 查完在本票 `## 评论` 写一句，三种写法：
  - 查过：和前面没有冲突
  - 查过：和第 N 张冲突，客户选择改第 N 张
  - 查过（自查）：……，用在子代理没起来时

### wrap-up（收尾列新想法）

- 起带整段对话的子代理，列四件事：这次出现的新想法、和旧结论冲突的地方、做了别张票的活的越界产出、对不上的先后。
- 起不来，自己重读对话和文件。
- 新想法记到对应的票后面，再对客户说一句，例如「这次多了一个想法，我记到第 5 张后面了」。
- 越界产出取简化版（2026-11-07 运营者定）。这次对话里做了别张票的内容，比如做第 1 张时顺手出了第 3 张的原型，agent 自己处理，不给客户出表。在那张票的 `## 评论` 记一句「这张的一部分已在第 N 张做过：……」，并在地图「接下来」那行改一笔。对客户只说一句。只有成果已经把另一张票的答案定死时，才问客户「认这个方向吗」。
- 阻塞边只查一处：票头 `Blocked by:` 和地图「接下来」里「等 03」是否一致。不一致时以票头为准改地图，并对客户说一句。这一条是我按运营者版改的，运营者没单独点过。
- 文件矛盾由 `map-gate` 查，这里不重复。

### 对照主干新版后的补充（2026-11-07）

三个客户版技能已写在 `customer-kit/package/.dsh/skills/`，对照主干 78bd6f4 的运营者版做了取舍。没有实测。

- 主干 `next` 新增的「并行组」不进客户版。客户一次只做一张票，没有第二个会话。
- 客户版 `next` 多一步：有 `Status: claimed` 的票，说明上次停在半路，先接着做它，不选新票。运营者版靠负责人判断进行中，客户版没有负责人。
- 做完的票从地图「接下来」里删，由 `wrap-up` 第 6 步做。原因：服务器判「做完」要看「接下来」为空，方案原先没写谁来删。
- `map-gate` 在写结论前跑，那时「产出文件」一行还没写。所以第 1 步先列出本票的产出文件，写完结论再补那一行。
- 阻塞边只核对票头 `Blocked by:` 和地图「接下来」是否一致，以票头为准。
- `spec-check` 和 `init-trail` 不进客户包。客户不跑 `to-spec`。
- 主干新版的「越界产出」「文件矛盾」两项，已按 Q32、Q33 取简化版，不给客户出表。

## 七、官网要什么

- 下载页：下载按钮，版本、日期、SHA256（文件校验值）。SHA256 可只给客服看。
- 清单页：由 `manifest.json` 生成。
- 三步图：下载，解压到空文件夹，用 dsh 打开并说一句话。第 2 步加那句肉眼检查。
- 上传页：加客户简称、邮箱、「已问完」勾选和隐私提示。简报原写「上传页不改」，这条要改。
- 教程页归 #31，「第一次对话会遇到什么」一节归 #58，发布归 #35。
- 静态页放本仓库 `site/`，和 `manifest.json` 同源，部署到 #7 那台服务器。上传接收端点另开仓库。
- 本次实现只交 zip、`manifest.json` 和生成出来的清单，不写页面代码。

## 八、一个工作区一个软件

- 一个工作区只做同一个软件。可以有多个需求，也可以在已有软件上开新功能。
- 新想法出现时，agent 先问一句：这是接着做同一个软件，还是另一个软件。
- 同一个：在同一个工作区新建需求目录。
- 另一个：请客户再解压一份到新文件夹。
- 客户说两个需求要合成一个软件：现在没有规则，列为待定。

## 十、验收

1. 新 Mac 空文件夹：解压，用 dsh 打开，说「开始需求澄清」。agent 先自检，再讲第一段开场词，不需要装配提示词。
2. 自检：删掉 `docs/agents/` 或 `.dsh/skills/` 再开，agent 报缺什么并停下。多套一层时根目录没有 `AGENTS.md`，agent 读不到自检规则，只能靠官网第 2 步的肉眼检查。
3. 三张票走一遍：开头 `next` 报进度。第 2 张写结论前，`map-gate` 发现和第 1 张冲突，问客户。客户说改，旧票加评论，地图标「已废，见第 2 张」，开放票改正文。本票评论有「查过」。
4. 收尾：`wrap-up` 列出新想法和冲突，`next` 给出固定句。
5. 新会话只发「继续：tanxin-yuyue 02 学生看到和填写什么」能接上。只发「继续」，由 `next` 选。
6. 最后一张做完：不推荐票，改说回传。
7. 回传：Mac 右键压缩和 Windows 压缩，是否带上隐藏的 `.scratch/` 和 `.dsh`。运营者能解压读到 `.scratch/`。
8. #36 清单补四项：隐藏 `.dsh`、中文路径、多套一层、没解压。
9. 九个技能的 frontmatter 都没有 `disable-model-invocation: true`。
10. 核对本机 `.claude/skills/`、运营者测试用的 dsh、客户包 `.dsh/skills/` 三处。三个客户版技能的步骤和运营者版一致，只有数据源不同，以及越界产出、文件矛盾取简化版。
11. 越界产出：做第 1 张时，让客户顺手要第 3 张的原型。收尾后第 3 张的 `## 评论` 有「这张的一部分已在第 1 张做过」，地图「接下来」改了一笔，对客户只说了一句，没有出表。

## 十二、证据边界

已确认事实：

- 改前：`customer-kit/build.sh:6` 硬写 `grilling-skills-v1`，zip 套一层，仓库里没有 `manifest.json`。2026-11-07 已改，`manifest.json` 在 `customer-kit/` 根目录，本机构建并解压核对过。
- 运营者版 `next`、`map-gate`、`wrap-up` 都带 `disable-model-invocation: true`，并依赖 `gh`。客户版三个技能已写在 `customer-kit/package/.dsh/skills/`，去掉了这个开关，不读 GitHub，没有实测。
- 客户版 `docs/agents/issue-tracker.md` 已经用中文的 `## 评论`、`## 结论`。
- 对话记录在 `~/.dsh/sessions/`，不在工作区。依据是桌面副本的 `.dsh/` 里只有 `skills/`。只在运营者这台 Mac、dsh 0.2.1-rc.5 上看过，没读内容。
- 官网代码和官网技能清单的来源，仓库里没找到。#7 的服务器、域名、HTTPS 已通。
- 运营者用桌面副本走了一遍，流程正常，子代理能起。这是运营者口述，在本机。

合理推测：

- 模型可能漏调技能，所以写三句硬触发。
- 仓库里「简称」有两个意思：需求名（agent 起，如截图里的 `tanxin-yuyue`）和客户名（运营者给，写进 `customers.json`）。本方案里，上传页填的是客户简称，目录名是需求名。

未验证：

- 客户右键压缩是否带上隐藏目录，Mac 和 Windows 都没测。
- Windows 解压、中文路径、`.dsh` 被隐藏时 dsh 是否正常。
