读地图编号和它的全部子票，查清哪些决定现在还有效。编号在命令后面。本技能除第 5 步点头后建票、第 7 步发布放行报告外，只读。地图和票的其他修改，等运营者逐条确认后另做。

`/to-spec` 只综合当前会话里已有的内容。会话里放进什么，spec 就写什么。本技能出两样：一份给运营者的放行报告，发成地图上的一条评论；一句给新会话的读法。新会话读地图全文和 `docs/decisions.md`，需要细节时打开台账里这条决定对应的来源票，地图 `Decisions so far` 只当索引；放行报告只用来确认可以进 `to-spec`，不是唯一输入。本会话里读过新旧两边原文，所以不要在本会话接着跑 `/to-spec`。

## 步骤

1. **对账。** 列出地图的全部子票，开放和关闭都要：`gh api --paginate repos/{owner}/{repo}/issues/<地图编号>/sub_issues`。再用标签补一遍，地图自己除外：`gh issue list --state all --limit 200 --json number,title,state,labels --jq '.[]|select(any(.labels[]; .name|startswith("wayfinder:")))|[.number,.state,.title]|@tsv'`。只在标签里出现、不在子票里的，标“没挂在地图下”，列给运营者，由运营者定挂不挂。数关闭票，再数地图 `Decisions so far` 的索引行。跑 `./scripts/decisions coverage <地图编号>`，记下首行「n 句里 m 句没落票」和它列出的句子。完成条件：每张关闭票都有一行索引；覆盖表的 n 和 m 已记下。

2. **起新子代理读全图。** DSH 用 `subagent`，Claude 用 Agent 工具选 general-purpose。新子代理只带提示里写的内容，没见过本会话的任何结论。提示里放：地图正文、每张关闭票的正文和最后一条评论、每张开放票的正文，加上地图和票的正文里提到的仓库文档全文（例如 `docs/工厂流程.md`，找法：在地图和票的正文里搜 `docs/`），以及每张关闭票的关闭评论里列的文件。开头标了「已被 <票名> 取代」的文件，归入「已废」。仓库文档里读起来像现行的旧句，也列进「旧句仍在」。让它给每张票写一行状态（现行、已废、部分取代），再报四类问题，每条带票名和原文一句：
   - 互相矛盾：两条都读起来现行，但不能同时成立。
   - 旧句仍在：被后来的补丁取代的句子，原句还留着，读起来像现行。常见写法是“旧句不改，以这里为准”。
   - 开放票仍指向旧前提。
   - 已关闭，正文却写着“待产出”。
   完成条件：每张子票都有一行状态，每条问题带原文和票名。

3. **运营者逐条判。** 一次一条，一条只含一个判断。含两个以上判断的，拆成几条分别判。每条按三块写，顺序固定：
   - 背景：这条涉及哪几张票或文件，各自是干什么的，为什么这条值得判。用人话写，假设运营者没看过这些票。
   - 冲突：用表格列两边原文，每行带票名和出处行号。再写一句：不处理会怎样。
   - 推荐：先给结论，再写理由。理由里分清已确认事实、合理推测、没核到的地方。最后列选项：仍成立、作废、补问客户。

   引文先对存档核对原文再写，没核到的明说。涉及已关闭决定的，由运营者判，你只列。完成条件：问题清单里每一条都有运营者的回答。

4. **出现行决定清单。** 写在对话里，分四段，每段一个小标题。现行决定：每行票名带链接，加一句结论。已废（历史，to-spec 不用）：每行票名，被哪张票取代，一句原因。已废句子：旧句还留在地图 Notes 或仓库文档里、读起来像现行的，每条写出处和一句原文，to-spec 看到就忽略。待运营者定：每行票名，加问题一句。一条决定只出现在一段里。完成条件：对账时数过的每张关闭票，都落进前两段之一。

5. **查缺口。** 照 `docs/agents/issue-tracker.md` 「查缺口」一节做。先问运营者一句：「做 `to-spec` 前，你觉得还缺哪些铺垫？」答几句、答「没有」都行，原话记下。起新子代理（工具同第 2 步），它没见过本会话，提示里放：地图 Destination、Notes 里的执行边界、第 4 步的现行决定清单、开放票正文、`Not yet specified`、`Out of scope`、运营者的铺垫原话。运营者逐条判，一次一条。判出「建新票」或「并入已有票」的，点头执行后停下，对话里告诉运营者「地图还有票要做，做完再重跑 `/map-gate`」，不进第 6 步。完成条件：见「查缺口」一节末尾。

6. **看体量。** 现行决定覆盖不止一个功能区、一份 spec 装不下时，提议按功能区拆成几份 spec，按依赖排好顺序，请运营者选先做哪一份。

7. **放行。** “待运营者定”一段为空，且第 1 步记下的覆盖表 `m` 为 0，才发布。`m` 不为 0 时，不发布，把 `./scripts/decisions coverage <地图编号>` 的输出原样给运营者，说「n 句里 m 句没落票，落完票再重跑 `/map-gate`」。发布是把放行报告写成评论：`gh issue comment <地图编号> --body-file -`。这条评论只当放行报告，不再是新会话的唯一输入。单条评论控制在 400 字内，放不下就按段拆成几条，每条第一行写「现行决定清单 <日期> 第 k 版 第 n/m 条」加一句结论，首次发布 k 为 1，同日重发 k 加 1。发六段：终点（一行，抄地图 Destination）、现行决定、已废、已废句子、未定、范围外。「未定」和「范围外」抄地图 `Not yet specified` 和 `Out of scope`，每项一句，「未定」每项开头写「未定，不要当成已定」。第 5 步判成「放着」的缺口也写进「未定」，开头照旧，另加一句「缺口，运营者放着」。评论里的「未定」是地图自己的未定项，不等于第 4 步的「待运营者定」；后者发布前必须已清空，不进评论。发完读回确认六段都在。然后在对话里报一行覆盖表结论（「Destination 覆盖表 n 句，m 句没落票」），再把下面这句话原样给运营者，请他复制到新会话的第一句：「只读地图 <地图编号> 全文和 `docs/decisions.md`。需要细节时打开台账里这条决定对应的来源票；地图 `Decisions so far` 只当索引。仓库文件开头标了「已被 <票名> 取代」的，不当成现行。然后跑 /to-spec」。新会话里 to-spec 如果还是引用了旧句，把那句的出处补进已废句子，重发一组。to-spec 写完后，运营者在同一个新会话里跑 `/spec-check <地图编号>`。
