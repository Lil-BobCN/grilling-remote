读地图编号下的子票，告诉运营者下一步做哪张。编号在命令后面。没给编号时，用会话里正在处理的那张地图。

本技能只读：不改票，不写文件，不打标签。结论每次现算，只在对话里给。存下来的结论会过期，过期的结论比没有更糟。

## 步骤

1. **取数。** 列出地图的开放子票：`gh api --paginate repos/{owner}/{repo}/issues/<地图编号>/sub_issues --jq '.[]|select(.state=="open")|.number'`。对每张取负责人、`wayfinder:` 类型标签、标题，以及它的阻塞项编号和状态：`gh api repos/{owner}/{repo}/issues/<n>/dependencies/blocked_by --jq '.[]|[.number,.state]|@tsv'`。完成条件：每张开放子票都有阻塞项列表，空列表也要记下。

2. **分三堆。** 可开工：没有未关闭的阻塞项，也没有负责人。进行中：有负责人。被挡住：还有未关闭的阻塞项。有负责人又被挡住的，归被挡住。完成条件：每张开放子票落进且只落进一堆。

3. **给可开工的排序。** 数每张票的「等它的票数」：沿阻塞边往下，直接或间接等它的开放票，各算一张。数大的在前，同数按地图里的子票顺序。完成条件：每张可开工票都有一个数，排序理由能用一句话说出。

4. **圈并行组。** 可开工的票都没有未关闭的阻塞边，彼此不会互相挡，进行中的票也挡不到它们。所以除第一张外，其余可开工票都能和第一张同时做。每张后面标类型，取 `wayfinder:` 后面的词。`grilling`（访谈，要运营者本人答题）一次只能做一张。第一张和并行组合计有两张以上 `grilling` 时，行末加「grilling 要轮流做」。完成条件：并行组里每张票都标了类型。

5. **给结论。** 固定格式，第一行就是结论：

```
下一步做：<票名>。<一句理由>
可以并行：<票名>（<类型>）、<票名>（<类型>）
进行中：<票名>，负责人 <名字>
被挡住：<票名>，等 <票名>
```

理由写具体：「做完它，<票名> 才能开工」。没有票在等它时写「没有票在等它，按地图顺序排第一」。某一行没有内容，整行省略。票名包着链接，不单写编号，见 `docs/agents/issue-tracker.md`。完成条件：运营者只读第一行，就知道下一步做什么。

6. **没有可开工的票。** 第一行写「现在没有可开工的票」，下面列每张被挡住的票在等谁。再读地图 `Not yet specified`，把已经能问准的一两项列给运营者，由运营者决定建不建。不自己建票。这些事该 one-shot、先 grilling 还是开票，见 `docs/agents/issue-tracker.md` 的「开工前先选方法」。

## 限制

只认 GitHub 原生阻塞边。票正文里写了「依赖 #N」但没建边的，这里看不到。

阻塞边只管先后，看不出两张票会不会改同一个文件或同一个决定。并行前由运营者自己判。
