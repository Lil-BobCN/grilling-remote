列出本会话里漏记的五类东西：没建票的新需求，与旧决定冲突的新决定，做了别张票的活的越界产出，与仓库里已有文件矛盾的新产出，和正文对不上的阻塞边。第一步是前置：本会话已经跑过 `scripts/decisions check`，本技能只读它的输出，不自己重跑。除此之外先只读。建票、改票、改地图、改文件、改阻塞边，等运营者逐条点头再做。

## 步骤

1. **前置：先跑过 `scripts/decisions check`。** 本技能不重跑 `check`，只读运营者给的那份 `scripts/decisions check <地图编号>` 输出；没有这份输出，先停下，请运营者跑一次，不自己补跑。按脚本的报错三类处理：A 类格式错，本会话自己改；B 类二选一，当场问运营者；C 类要重做，按脚本给的建议标题查重，已有开放票接管的指到那张票，没有接管的列进第 5 步的新需求表。完成条件：`check` 的每一条输出都有去处：改完、已问、已列。

2. **扫会话，查漏。** 从头读本会话。每次出现新需求或新决定，记一条，附会话里的原话一句。只记还没落到票或地图里的。然后起一个 fork 子代理，它带着整段会话。DSH 用 `subagent_fork`，Claude 用 Agent 工具填 subagent_type: fork。只问它一句：“这份清单漏了会话里的哪些新需求或新决定？”它补出的并进清单。完成条件：会话里的每一轮都读过，子代理答“无遗漏”或补出的已并入。

3. **查冲突：地图和文件。** 分两路。

   - 地图：读地图编号（命令后面那个；没给就用会话里 `/wayfinder` 打开的那一张）和本条新决定涉及的票。给每条新决定找它碰到的现有决定。只看涉及的票，不逐张扫开放票；开放票的前提由领取时的「开工核对」查。完成条件：每条新决定写明碰到的票或地图行，或写“无冲突”。
   - 文件：照 `docs/agents/issue-tracker.md` “地图上的变动怎么留痕”一节的“查文件矛盾”，查本会话的每条新决定和每份新写、改过的文档，有没有和仓库里已有文件说法相反。完成条件：搜索命中的每个文件都有一行判定（矛盾、部分矛盾、无关、未读）。没有命中的，写“无文件矛盾”。

4. **查票：越界产出和阻塞边。** 分两路。

   - 越界产出：照 `docs/agents/issue-tracker.md` “地图上的变动怎么留痕”一节的“查越界产出”，查本会话做的事有没有超出本票的 `Scope`。完成条件：本会话改过的每个文件、写过的每条评论、改过的每张票，都落进“本票内”“属于某张开放票”“哪张都不属于”三档之一，属于别票的写明做到哪一步。
   - 阻塞边：照同一节的“查阻塞边”，查本会话动过的票，含查越界产出时要改正文的归属票。完成条件：每张动过的票都有一行：现有边、应有的边、依据一句。

5. **给运营者看。** 第一行先写文件矛盾的结论：“有 n 个文件说法相反”或“无文件矛盾”。再给五张表。新需求表：一句话、原话、建议归类（新票、并入某张票、未定、范围外、当场做完）。冲突表：新决定、碰到的票或地图行、冲突点、建议处理。越界产出表：产出、归属票、占它 `Scope` 第几条、做到哪一步、建议处理。文件矛盾表：文件路径和行号、旧句原文、对应的新决定（票名）、判定、建议改法（写出要加的那句话）。阻塞边表：票、现有边、应有的边、依据一句。

   建议处理从下面七种里选：
   - 开放票：原地改正文，删掉被推翻的前提，末尾记一行“按 [票名] 更新”。
   - 关闭票：正文不动，加评论“被 [票名] 部分取代”，写明哪一部分。
   - 地图索引行：保留原行，行首标“已废，见 [票名]”。
   - 已关闭的决定被推翻：新开一张取代票，旧票不重开。
   - 阻塞边：补加或移除。加边命令见 `docs/agents/issue-tracker.md` 常用操作里的“阻塞”一条。
   - 越界产出：按 `docs/agents/issue-tracker.md` “查越界产出”里的表选。
   - 文件矛盾：按 `docs/agents/issue-tracker.md` “查文件矛盾”里的表选。

6. **运营者回应后再动手。** 要改的文件直接推到当前 PR，不开新分支，也不另开 PR；等 wrap-up 和 next 都跑完再合并。运营者逐条回：建、并入、放着、不要。越界产出表的行回：并入、留在本票、回退、放着。文件矛盾表的行回：改、归档、合并、放着。阻塞边表的行回：补、移除、放着。建票之前先搜 open 和 closed 票查重，建票照 `docs/agents/issue-tracker.md`。完成条件：每条回应都执行了，或标了“放着”。
