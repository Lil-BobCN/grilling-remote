# 说清楚，再开工：客户需求 → 自动软件工厂（可点原型）

给运营者看的单文件原型。看完应该能回答两件事：客户会经历什么，每一屏背后跑了什么。

这是 throwaway 原型，不是产品代码。所有状态在内存里，刷新重来。

## 怎么开

双击 `prototype/index.html`。或者在终端里：

```bash
open prototype/index.html
```

- 零依赖、零构建、零 CDN。`file://` 直接开。
- 浏览器用新版 Chrome、Safari 或 Edge。
- 刷新回到第 1 步。
- 底部左边浮动条切 A/B。键盘 `←` `→` 也能切，光标在输入框里时不抢键。
- 地址后加 `?variant=B` 可以直接开 B。默认 A。
- 右下角「找人」是留言面板，只在内存里，不发出去。

## 看哪

| 视角 | 看什么 |
| --- | --- |
| 客户视角 | 左边对话，右边成品预览，下面是已定 / 待定 |
| 工厂视角 | 上面一条七步流水线，中间三块说明，右边详情，底部状态带 |

顶部有视角开关、阶段跳转和重播。工厂视角里点工单条右边的状态标签，会滚到底部状态带。

## 三段问

### 第 1 段：只问需求

开场是一个大输入框、三句示例、一行行业词。点示例或行业词只填一句话，不跳页。输入框下面写「不知道怎么说？从这些开始」。

客户写完，网页 agent 先复述一句，再一题一题问：

1. 给谁用：顾客 / 员工 / 自己 / 还说不清
2. 进来第一件事：预约 / 看价 / 联系 / 填表
3. 现在怎么做：微信接龙 / 打电话 / Excel / 记本子 / 没做过
4. 做完看到什么会说「对了」：自由输入，给三个例子
5. 明确不要的：登录 / 支付 / 会员 / 后台 / 多语言 / 都没有

第 3 题答完，弹一次「今天 vs 以后」对照。左边是微信群接龙，右边是三步流程。关掉后继续。

第 5 题答完，给三行人话复述。点「接着说载体和走向」进第 2 段。

这一整段不问载体、后端、服务器、预算、账号。

### 第 2 段：载体和走向

1. 载体四选一：微信小程序 / 公众号 / 网页 / 独立 App。每张卡有一个小手机图、一句好处、一句麻烦、大概多久。选中后主手机外壳跟着换。
2. 顾客怎么找到你：扫码 / 发链接 / 搜得到。手机顶上出现入口条。
3. 要不要在线付钱：要 / 不要 / 说不清。选「说不清」给两张场景图，不解释术语。
4. 有没有现成东西要接：微信群 / 公众号 / Excel / 没有。有就出现在手机里。

每答一题，手机上的对应元素出现或消失。

### 第 3 段：技术细节

先问一句：你之前自己做过网站或小程序吗？没做过 / 用过现成工具 / 有技术同事。

然后三张卡，每行左边好处、右边麻烦：

| 卡 | 选项 |
| --- | --- |
| 数据放哪 | 国内（推荐）/ 海外 |
| 账号用谁的 | 你的微信 / 我们代管 |
| 每月愿意花多少 | 0–100 / 100–500 / 500 以上 / 你定 |

每张卡下面有大按钮「你帮我定，交给运营者」。点了，卡片标成「等你定」，待定列多一条。卡上写「我会带 3 个选项和推荐」。自己选也行，选完写「开工前运营者会再确认一次」。

### 确认页

左边 5 行人话，下面一行「不做」清单。右边还是手机。

- 点一行，手机上对应的块亮。
- 点手机上的块，左边对应的行亮。
- 每行都能点「改」，直接在行里改。
- 点「就按这个来」，四件事依次出现：建工单 / 建仓库 / 写需求 / 推微信。
- 四件完成后，给「切到工厂视角」按钮。

### 工厂视角

一条七步流水线：

澄清 → 写规格 → 拆票 → 实现 → 评审 → 提 PR → 验收

每步下面挂着 skill 和产出，颜色分三类：改造后用、直接调、条件触发。点一步，右边显示输入、产出、谁负责、用到哪些 skill。澄清这一步还会列出这张单的 5 行确认单。

另外三块：

- 一次性装好：`/setup-matt-pocock-skills` + `gh label create`
- 条件触发：`/wayfinder`、`/domain-modeling`、`/retro`
- 技术闸门：五类问题，每条三个选项，带推荐

底部状态带：草稿 → 已确认 → 已进队列 → 等你定 → 开工 → 待验收 → 完成。当前高亮。点一个状态，右边看它的输入、产出、谁负责、对应 skill。

技术闸门没点完时，状态停在「等你定」。闸门旁边写「没回就停着 · 每 24 小时提醒一次」。状态带里的「演示：推进状态」只用于看后面几步。

## A/B 两个变体

| 变体 | 右侧 | 适合看什么 |
| --- | --- | --- |
| A（默认） | 双手机，300×620，斜叠。前一台是顾客看到的，后一台是你的后台。 | 前后台一起变，每答一题都能看到两边 |
| B | 单手机，下面一条「今天 / 以后」对照。 | 现在怎么做、以后少哪几步 |

变体只换右侧的表达。左边的问题、确认单、工厂视角完全一样。

底部浮动条切换。切了会写进地址的 `?variant=`，刷新后变体还在，流程回到第 1 步。

## 状态怎么连起来

- 第 1 段的受众、第一件事、现在的做法、完成态、不做清单，决定手机内容和确认单。
- 第 2 段的载体换外壳：微信导航条 / 公众号头 / 浏览器地址栏 / App 导航。入口、付钱、要接的系统，分别让手机上的入口条、支付行、整合提示出现。
- 第 3 段的三个选择进「待定」。工厂的技术闸门会显示「客户意思」。客户点了「你帮我定」，闸门等运营者。
- 确认页第 1 行改的是工单标题。第 3、4、5 行改的是手机里的入口、支付、验收。
- 第 2 行「给谁用」只改确认单。手机里的受众文案是产品话术，没有跟着改。
- 手机里的示例数据不参与计算。6 单、14 斤都是写死的。

## 研究里的 8 条决策，落在哪

1. 首屏：按 Y-001 用输入框。示例句和行业词是折中。研究第 1 条原本主张先给卡片。
2. 每题 3–5 个选项，答完还能点「改」。
3. 一屏一个决策。右侧用手机替代文字卡，按 Y-005。
4. 开局替客户填 30%：没做。开场是空白，只给示例句。
5. 第 1 段 5 个问题，在 5–8 的预算内。
6. 说不清时给两张场景图，不给 6 个方向。
7. 能回看、能单条改。没做草稿持久化，刷新就清空。
8. 结尾 5 行人话确认单，逐条可改，点「就按这个来」才往下走。

## 哪些是模拟的

- 没有登录、后端、数据库、网络请求。所有状态在内存里。
- 手机里的店、价格、订单、备货量、审核时间都是示例。
- 「建工单 / 建仓库 / 写需求 / 推微信」是定时出现的四行字，没有真的建。
- 技术闸门的五个选择只存在内存里。
- 「24 小时提醒一次」是文案，没有定时器，也没有微信通知。
- 「找人」不发消息，只弹一条提示。
- 已定 / 待定是摘要，不是完整工单。
- 条件触发、一次性、skills 表是说明。网页里没有跑真 agent。
- 状态带的「演示：推进状态」只换界面状态，不跑流程。

## 砍了什么

- 没做持久化和草稿恢复。刷新就回第 1 步。
- 没做研究第 4 条「开局先填 30%」。
- 没做客户技术选择的单独待定面板。三个选择进已定 / 待定列，卡上标「等你定」。
- 没做真阻塞。技术闸门没回时，状态显示「等你定」，但没有队列和定时器。
- 没做复杂动效。只有卡片状态、消息进场和手机内容的小过渡。
- 确认页第 2 行不写回手机。产品话术和需求句子分开，避免把需求文档塞进成品界面。
