# 客户进度模块样品（#109）

一句话：四屏单文件样品，给运营者判断能不能拿去 `to-spec`；转档状态定在工单评论里，一行一条。

## 怎么开

双击 `prototype/issue-109/index.html`。零依赖，`file://` 直接开。

底部深色条是样品控制，正式页不显示。

- 页面：登录 / 订单列表 / 运营者视图。
- 详情状态：正常开发中 / 校验未通过 / 待客户验收 / 驳回后第 2 轮 / 已完成。

## 这版有什么

| 屏 | 看什么 |
| --- | --- |
| 登录 | 邮箱加密码。账号我们建，密码微信发，忘了找客服重设。 |
| 订单列表 | 5 个订单、五档状态、小进度条、最近更新时间。传新需求登录后不用再填简称和邮箱。 |
| 订单详情 | 五档进度条；走过打勾带时间，当前高亮；点节点展开这一档的细步骤。详情放了四个状态。 |
| 运营者视图 | 8 单一行一单。客户、需求名、当前档、内部细阶段、停留天数、卡住、交付地址、小进度条。只读，标「该发消息了」，点「工单」去 GitHub。 |

详情页的细步骤用客户话写。管理视图只读；答闸门、拆票、点火仍在 GitHub 和 Orca。

每档的小步是固定表，不随订单、轮次增删。点和看都对得上同一串：

| 档 | 固定小步 |
| --- | --- |
| 已收到 | 收包 → 校验 |
| 安排中 | 建单 → 技术闸门 → 写规格 → 拆票 → 点头 |
| 开发中 | 开工 → 子票开发 → 验证 → 评审 → 合分支 → 合主干 → 部署 |
| 待客户验收 | 打包 → 等试用 |
| 已完成 | 关单 |

两条分支不另起一串小步：

- **校验未通过**：还是「已收到」这一档，停在「校验」这步；缺什么、怎么补写在提示里。补好重传，回到「已收到」。
- **已驳回**：进度条退回「开发中」，挂「第 2 轮」；上一轮时间进「经历」。这一轮还是上面那条「开发中」固定小步，从「开工」重新走。

管理视图的「内部细阶段」可以比客户小步细，例如校验未通过显示「等补传」。客户页只显示固定表，不跟着变长。

## 转档状态：结论

**写在工单评论里，一行一条。建单前写在上传服务的订单记录里，同一格式。页面读评论和记录，按轮次拼起来。**

格式：

```text
进度 v1｜客户档：开发中｜细阶段：子票开发 2/4｜轮次：1｜卡住：否
```

有卡住原因时，末尾加 `备注：`。备注只给运营者看，客户页不显示：

```text
进度 v1｜客户档：安排中｜细阶段：技术闸门｜轮次：1｜卡住：是｜备注：等运营者答技术闸门
```

字段：

| 字段 | 必填 | 值 |
| --- | --- | --- |
| 客户档 | 是 | 已收到 / 校验未通过 / 安排中 / 开发中 / 待客户验收 / 已完成 / 已驳回 |
| 细阶段 | 是 | 固定词表，见下 |
| 轮次 | 是 | 1 起。客户驳回一次加 1 |
| 卡住 | 是 | 是 / 否 |
| 备注 | 否 | 一句话。只在卡住或内部说明时写 |

细阶段词表：

| 客户档 | 细阶段 |
| --- | --- |
| 已收到 | 收包 / 校验 |
| 校验未通过 | 等补传 |
| 安排中 | 建单 / 技术闸门 / 写规格 / 拆票 / 点头 |
| 开发中 | 开工 / 子票开发 n/m / 验证 / 评审 / 合分支 / 合主干 / 部署 |
| 待客户验收 | 打包 / 等试用 |
| 已完成 | 关单 |
| 已驳回 | 记驳回 |

五档的小步就是上面这五串，固定不变。`校验未通过` 和 `已驳回` 是分支事件，不是第六、第七串小步：前者的页面停在「已收到 · 校验」，后者进「经历」，进度条回「开发中」。`开修复`、`过户` 不当小步：前者是驳回后的内部动作，后者写在「已完成」的提示里。

写法：

1. 每次转档写一条评论。评论正文只有这一行，不夹别的话。
2. 时间不写在行里。页面取 GitHub 评论的 `created_at`，这样时间不会因为调度器时钟偏了而错。
3. 建单前没有工单，写不了评论。「已收到」「校验未通过」这两档由上传服务写进订单记录，还是这一行，时间取记录时间。
4. 页面读一条单的全部评论，只取以 `进度 v1｜` 开头的；再和建单前的记录按时间拼起来，按 `轮次` 分组。
5. 当前档取最后一条；某一档的到达时间取这一档第一条；当前小步取最后一条的细阶段。分支事件按固定表归位：校验未通过归「校验」，已驳回进「经历」。

为什么不写仓库里的状态文件：

- 状态属于工单，不属于代码。写文件要提交，会和正在合并的 PR 抢同一棵树。
- 驳回、改口本来就用评论留档，转档放一起，运营者在工单里一眼看全。
- 评论天然带时间、作者和顺序，不用另造一份时间字段。

为什么不只读标签：

- 四个 `状态:*` 标签只给调度器看，没有小步、时间、轮次和卡住原因。
- 标签继续由调度器写。页面不读标签，读评论。

## 样品怎么读这套格式

`index.html` 里每个订单的 `lines` 就是一组原样的评论行。`parseLine` 按 `｜` 和 `：` 拆字段，`renderPanel` 按 `轮次` 和 `客户档` 拼出进度条和细步骤。

这份样品没有真评论，时间也是写死的。格式本身是真的照上面写的。

## 和 `docs/客户进度.md` 对过

| 文档 | 样品 |
| --- | --- |
| 五档 | 进度条五个节点：已收到、安排中、开发中、待客户验收、已完成。 |
| 每档小步 | 五档各自固定，不随订单、轮次增删。 |
| 校验未通过 | 挂在「已收到」上，节点标红；小步还是固定的「收包、校验」，缺什么写在提示里。 |
| 已驳回 | 进度条退回「开发中」，挂「第 2 轮」；上一轮时间进「经历」，不另加小步。 |
| 已完成 | 固定小步只有「关单」；过户写在提示里，不当小步。 |
| 内部四档 | 管理视图的「内部细阶段」显示还没建单 / 排队中 / 开发中 / 待验收 / 关闭。 |
| 卡住 | 管理视图标旗子，带原因；客户页不写原因，只让最近更新时间变旧。 |
| 三条消息 | 管理视图按三条规则算「该发消息了」：校验未通过、部署好待验收、从上传算满 24 小时还没到待验收。客户页不显示发没发。 |
| 验收不设时限 | 页面不写倒计时，不催。 |

## 哪些是模拟的

- 没有登录、后端、数据库、网络请求。刷新回登录页。
- 登录按钮只换页，不校验账号密码。
- 上传、重新上传、打开交付地址、工单链接都只弹提示。
- 「该发消息了」按样品日期算，不发消息。
- 卡住是写死的一单，没有调度器。
- 底部样品条不属于产品页。

## 自测

Chrome 156，headless，CDP 驱动。

- 四屏都能开。订单列表 5 张卡，管理列表 8 行。
- 详情四态加「已完成」都能看到；五档节点、当前高亮、到达时间、点节点展开都对。
- 每档小步按固定表渲染：开发中 7 条、已完成 1 条；校验未通过停在「校验」，不另起一串。
- 驳回后第 2 轮：进度条退回开发中，挂第 2 轮，经历里有第 1 轮和驳回时间。
- 管理视图：该发消息 3 单、卡住 1 单、已完成 1 单；四个筛选都对。
- 登录、密码显示切换、忘记密码、样品说明弹窗、节点切换都过了一遍。
- 控制台 0 报错。
- 390、768、1024、1440 四档宽，登录 / 列表 / 详情 / 管理都没有横向滚动。
- 截图时用 `prefers-reduced-motion` 关掉入场动画，因为 headless 截图会停在动画第一帧。正常浏览器会播 0.45 秒。

## 等运营者判断

这张票的最后一个成功条件是运营者的一句话：能不能拿去 `to-spec`，哪里要改。

看这几处：

1. 登录页：邮箱加密码、密码微信发、忘了找客服，这套说法对不对。
2. 订单列表：五档和两个分支的说法对不对；第 2 轮够不够显眼。
3. 订单详情：四个状态够不够用；每档小步是不是固定这几条；细步骤的客户话对不对；当前小步和时间清不清楚。
4. 运营者视图：列够不够；「该发消息了」和「卡住」能不能一眼看出来；只读边界对不对。
5. 转档格式：一行一条、写评论、建单前写服务记录，这三条能不能定。
